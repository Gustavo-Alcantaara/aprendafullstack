Modelos de Processos Prescritivos

Os modelos de processos prescritivos são modelos que definem como o desenvolvimento de software deve acontecer, estabelecendo etapas, atividades, ordem de execução, documentos e responsabilidades.

Eles servem como um guia estruturado para o desenvolvimento de sistemas.

A palavra prescritivo vem da ideia de “prescrever” regras e procedimentos.

Objetivos dos modelos prescritivos

Esses modelos existem para:

  • Organizar o desenvolvimento
  • Padronizar processos
  • Reduzir riscos
  • Melhorar qualidade
  • Facilitar gerenciamento
  • Controlar prazo e custo
  • Tornar o processo previsível

Características principais

Os modelos prescritivos normalmente possuem:

1. Fases bem definidas

O projeto é dividido em etapas.

Exemplo:

  • Requisitos
  • Projeto
  • Implementação
  • Testes
  • Implantação
  • Manutenção

2. Documentação forte

Grande parte dos modelos tradicionais exige:

  • documentação técnica
  • especificações
  • diagramas
  • relatórios

3. Controle rígido

Existe:

  • planejamento antecipado
  • cronograma
  • controle de mudanças

4. Sequência de atividades

As tarefas seguem uma ordem lógica.

Em alguns modelos:

  • uma fase só começa após a outra terminar.

Principais modelos prescritivos

Os mais importantes são:

  1. Modelo Cascata
  1. Modelo Incremental
  1. Modelo Evolucionário
  1. Modelo Espiral
  1. Modelo Concorrente
  1. Modelo V
  1. RAD

1. Modelo Cascata (Waterfall)

É o modelo mais clássico e tradicional.

O desenvolvimento ocorre em sequência linear.

Fluxo

Requisitos
   ↓
Projeto
   ↓
Implementação
   ↓
Testes
   ↓
Implantação
   ↓
Manutenção

Características

  • Processo sequencial
  • Alta documentação
  • Planejamento rígido
  • Mudanças são difíceis

Vantagens

  • Fácil de entender
  • Fácil de gerenciar
  • Bom para projetos pequenos
  • Funciona bem quando requisitos são estáveis

Desvantagens

  • Pouca flexibilidade
  • Cliente só vê o sistema no final
  • Mudanças custam caro
  • Alto risco de retrabalho

Quando usar

Quando:

  • requisitos são claros
  • projeto é simples
  • mudanças são raras

2. Modelo Incremental

O sistema é desenvolvido em partes chamadas incrementos.

Cada incremento adiciona funcionalidades novas.

Funcionamento

Exemplo:

Versão 1

  • Login

Versão 2

  • Cadastro

Versão 3

  • Relatórios

Características

  • Entregas parciais
  • Evolução gradual
  • Feedback constante

Vantagens

  • Cliente recebe partes do sistema cedo
  • Menor risco
  • Mais flexível
  • Facilita testes

Desvantagens

  • Requer bom planejamento arquitetural
  • Integração pode ser complexa

Quando usar

Quando:

  • o projeto é grande
  • há necessidade de entregas rápidas
  • requisitos podem evoluir

3. Modelo Evolucionário

O sistema vai sendo refinado conforme o usuário fornece feedback.

O software evolui continuamente.

Tipos principais

Prototipação

Cria-se um protótipo rápido para entender requisitos.

Espiral

Modelo baseado em análise de riscos.

Prototipação

Objetivo

Criar uma versão simplificada do sistema.

Tipos

Protótipo descartável

Serve apenas para entendimento.

Protótipo evolutivo

Vai sendo melhorado até virar o produto final.

Vantagens

  • Melhor entendimento dos requisitos
  • Maior participação do cliente
  • Redução de erros

Desvantagens

  • Cliente pode achar que o sistema já está pronto
  • Pode gerar arquitetura ruim se mal planejado

4. Modelo Espiral

Criado por Barry Boehm.

Mistura:

  • cascata
  • prototipação
  • análise de riscos

É um dos modelos mais importantes.

Estrutura da Espiral

Cada volta da espiral possui:

1. Planejamento

Definição de objetivos.

2. Análise de riscos

Identificação de problemas.

3. Engenharia

Desenvolvimento do sistema.

4. Avaliação do cliente

Feedback do usuário.

Características

  • Processo iterativo
  • Forte gerenciamento de riscos
  • Evolução contínua

Vantagens

  • Excelente para projetos complexos
  • Reduz riscos
  • Muito flexível

Desvantagens

  • Complexo
  • Caro
  • Exige experiência

Quando usar

Projetos:

  • grandes
  • críticos
  • complexos
  • com muitos riscos

5. Modelo Concorrente

As atividades acontecem simultaneamente.

Exemplo:

  • análise
  • implementação
  • testes

Tudo pode ocorrer ao mesmo tempo.

Características

Cada atividade possui estados:

  • aguardando
  • em execução
  • revisada
  • concluída

Vantagens

  • Mais dinâmico
  • Melhor adaptação
  • Bom para equipes grandes

Desvantagens

  • Difícil gerenciamento
  • Alta complexidade

6. Modelo V

É uma evolução do cascata.

Relaciona:

  • fases de desenvolvimento
  • fases de testes

Estrutura do Modelo V

Lado esquerdo

Desenvolvimento:

  • requisitos
  • projeto
  • arquitetura
  • codificação

Lado direito

Testes:

  • teste de aceitação
  • teste de sistema
  • teste de integração
  • teste unitário

Ideia principal

Cada fase de desenvolvimento possui um teste correspondente.

Vantagens

  • Forte foco em qualidade
  • Testes planejados cedo
  • Boa rastreabilidade

Desvantagens

  • Pouco flexível
  • Mudanças são difíceis

7. RAD (Rapid Application Development)

Modelo focado em:

  • velocidade
  • prototipação rápida
  • reutilização

Características

  • Desenvolvimento rápido
  • Ferramentas CASE
  • Componentização
  • Participação intensa do usuário

Vantagens

  • Entrega rápida
  • Alta produtividade
  • Feedback constante

Desvantagens

  • Não serve para projetos muito grandes
  • Requer equipe experiente

Relação com metodologias ágeis

Os modelos prescritivos são mais associados às metodologias tradicionais.

Já os métodos ágeis:

  • possuem menos rigidez
  • menos documentação
  • maior adaptação

Exemplos ágeis:

  • Scrum
  • XP
  • Kanban

Resumão Final

Modelos prescritivos:

  • definem regras e etapas
  • organizam o desenvolvimento
  • ajudam no controle do projeto

Principais modelos:

  • Cascata → sequencial
  • Incremental → entregas parciais
  • Evolucionário → refinamento contínuo
  • Espiral → foco em riscos
  • Concorrente → atividades simultâneas
  • Modelo V → foco em testes
  • RAD → desenvolvimento rápido

Conceito-chave

Os modelos prescritivos tentam responder:

“Qual o melhor processo para desenvolver software com qualidade, controle e previsibilidade?”
