Pilar do Encapsulamento

Pilar do Encapsulamento

O encapsulamento é um dos quatro pilares fundamentais da Orientação a Objetos (OO), ao lado da abstração, herança e polimorfismo. Seu principal objetivo é proteger os dados de um objeto e controlar a forma como eles são acessados ou modificados.

Em vez de permitir que qualquer parte do sistema altere livremente os atributos de um objeto, o encapsulamento cria uma camada de proteção, expondo apenas os recursos necessários e escondendo os detalhes internos da implementação.

Podemos resumir o encapsulamento com a seguinte ideia:

Os dados pertencem ao objeto e devem ser manipulados de forma controlada.

O que é Encapsulamento?

Imagine uma conta bancária.

Ela possui um saldo interno que não deveria ser alterado diretamente por qualquer parte do sistema.

Seria extremamente perigoso permitir algo assim:

conta.saldo = 1000000;

ou

conta.saldo = -5000;

Isso poderia gerar inconsistências e violar regras de negócio.

O correto é que o saldo só seja alterado através de operações autorizadas, como:

conta.depositar(500);
conta.sacar(100);

Dessa forma, a própria conta controla como seu saldo será modificado.

Esse é o conceito central do encapsulamento.

Objetivos do Encapsulamento

O encapsulamento existe para:

  • Proteger dados importantes.
  • Evitar alterações indevidas.
  • Garantir regras de negócio.
  • Reduzir dependências entre partes do sistema.
  • Facilitar a manutenção do código.
  • Tornar os objetos responsáveis por seus próprios dados.

Encapsulamento no Mundo Real

Exemplo: Automóvel

Ao dirigir um carro, você utiliza:

  • Volante
  • Pedais
  • Câmbio

Mas você não tem acesso direto a:

  • Pistões
  • Sistema de injeção
  • Computador de bordo
  • Sistema de ignição

Esses componentes ficam protegidos.

Você interage apenas através de uma interface controlada.

O encapsulamento funciona exatamente dessa maneira.

Exemplo: Caixa Eletrônico

Quando você realiza um saque:

Inserir cartão
↓
Digitar senha
↓
Escolher valor
↓
Receber dinheiro

Você não pode acessar diretamente:

  • O banco de dados
  • O saldo armazenado
  • Os sistemas internos do banco

Tudo é controlado por operações específicas.

Encapsulamento em JavaScript

No JavaScript moderno, podemos utilizar atributos privados através do símbolo #.

Exemplo Básico

class Conta {
    #saldo = 0;

    depositar(valor) {
        this.#saldo += valor;
    }

    mostrarSaldo() {
        console.log(`Saldo: R$${this.#saldo}`);
    }
}

Uso:

const conta = new Conta();

conta.depositar(500);

conta.mostrarSaldo();

Resultado:

Saldo: R$500

Observe que o saldo só pode ser alterado pelo método depositar().

Atributos Públicos e Privados

Atributos Públicos

Podem ser acessados de qualquer lugar.

class Pessoa {
    nome = "Gustavo";
}
const pessoa = new Pessoa();

console.log(pessoa.nome);

Resultado:

Gustavo

Atributos Privados

Só podem ser acessados dentro da própria classe.

class Pessoa {
    #cpf;

    constructor(cpf) {
        this.#cpf = cpf;
    }
}

Tentativa de acesso:

const pessoa = new Pessoa("123456789");

console.log(pessoa.#cpf);

Resultado:

SyntaxError

O JavaScript impede o acesso.

Protegendo Regras de Negócio

Uma das maiores vantagens do encapsulamento é a possibilidade de validar dados.

Sem encapsulamento:

produto.preco = -100;

Isso não faz sentido.

Com encapsulamento:

class Produto {
    #preco;

    constructor(preco) {
        this.#preco = preco;
    }

    alterarPreco(valor) {
        if (valor < 0) {
            console.log("Preço inválido.");
            return;
        }

        this.#preco = valor;
    }
}

Agora o objeto impede valores incorretos.

Getters e Setters

Além dos atributos privados, podemos controlar o acesso através de getters e setters.

Getter

Permite obter um valor.

get nome() {
    return this._nome;
}

Setter

Permite modificar um valor com validação.

set nome(valor) {
    if(valor.length < 3) {
        return;
    }

    this._nome = valor;
}

Exemplo completo:

class Usuario {
    constructor(nome) {
        this._nome = nome;
    }

    get nome() {
        return this._nome;
    }

    set nome(valor) {
        if (valor.length < 3) {
            console.log("Nome inválido.");
            return;
        }

        this._nome = valor;
    }
}

Uso:

const usuario = new Usuario("Ana");

console.log(usuario.nome);

usuario.nome = "Jo";

console.log(usuario.nome);

O setter impede alterações inválidas.

Encapsulamento e Integridade dos Dados

Considere este exemplo:

class Conta {
    #saldo = 1000;

    sacar(valor) {
        if(valor > this.#saldo) {
            console.log("Saldo insuficiente.");
            return;
        }

        this.#saldo -= valor;
    }
}

Sem encapsulamento alguém poderia fazer:

conta.saldo = 999999;

Com encapsulamento isso não é possível.

A integridade das informações é preservada.

Benefícios do Encapsulamento

1. Segurança

Protege dados importantes contra alterações indevidas.

2. Controle

Permite definir exatamente como os dados podem ser acessados.

3. Validação

Possibilita verificar informações antes de armazená-las.

4. Facilidade de Manutenção

Mudanças internas não afetam outras partes do sistema.

5. Redução de Erros

Evita que objetos fiquem em estados inválidos.

Encapsulamento e Abstração

Esses dois conceitos costumam ser confundidos.

Abstração

Pergunta:

O que o objeto faz?

Exemplo:

conta.sacar(100);

Você sabe que a conta realiza um saque.

Encapsulamento

Pergunta:

Como os dados são protegidos?

Exemplo:

#saldo

O saldo está protegido e só pode ser alterado através de métodos específicos.

AbstraçãoEncapsulamento
Esconde a complexidade.Esconde os dados internos.
Foca nas funcionalidades.Foca na proteção dos dados.
Mostra o que o objeto faz.Controla como o objeto é utilizado.

Boas Práticas

Evite expor atributos importantes diretamente

Ruim:

usuario.senha = "123456";

Melhor:

usuario.alterarSenha("123456");

Valide dados antes de armazená-los

Sempre que possível, verifique se os valores recebidos são válidos.

Use métodos para representar comportamentos

Em vez de permitir alterações diretas:

conta.saldo += 500;

Prefira:

conta.depositar(500);

Mantenha a responsabilidade dentro da classe

A própria classe deve ser responsável por proteger seus dados.

Resumo

O encapsulamento é o pilar da Orientação a Objetos responsável por proteger os dados internos de um objeto e controlar seu acesso através de métodos e interfaces apropriadas. Ele impede alterações indevidas, garante regras de negócio, melhora a segurança do sistema e facilita a manutenção do código. Em JavaScript, o encapsulamento pode ser implementado com atributos privados (#), métodos, getters e setters, tornando os objetos mais seguros, organizados e confiáveis.
