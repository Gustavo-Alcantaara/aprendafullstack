Objetos Únicos

Objetos Literais — Objetos Únicos

Em JavaScript, um objeto literal geralmente representa um objeto único, ou seja, uma entidade específica que existe apenas uma vez dentro do contexto da aplicação.

Diferentemente das classes, que funcionam como modelos para criar múltiplas instâncias, os objetos literais são criados para armazenar informações e comportamentos de um único elemento.

O que são Objetos Únicos?

Um objeto único é uma estrutura criada para representar uma única entidade, sem a necessidade de reutilização ou criação de cópias.

Exemplo:

const usuarioLogado = {
    nome: "Gustavo",
    email: "gustavo@email.com",
    autenticado: true
};

Nesse caso, usuarioLogado representa apenas o usuário atualmente autenticado no sistema.

Não existe a necessidade de criar várias instâncias desse objeto.

Objetos Literais x Classes

A principal diferença entre objetos únicos e classes está na finalidade de cada abordagem.

Objeto Literal

Representa uma instância específica.

const configuracoes = {
    tema: "escuro",
    idioma: "pt-BR"
};

Classe

Define um modelo para criar diversas instâncias semelhantes.

class Usuario {
    constructor(nome, email) {
        this.nome = nome;
        this.email = email;
    }
}
const usuario1 = new Usuario(
    "Gustavo",
    "gustavo@email.com"
);

const usuario2 = new Usuario(
    "Ana",
    "ana@email.com"
);

Se você precisa criar vários objetos com a mesma estrutura, as classes são mais adequadas.

Se precisa representar apenas uma entidade específica, o objeto literal costuma ser a melhor opção.

Características dos Objetos Únicos

Os objetos únicos possuem algumas características importantes:

  • São criados diretamente com {}.
  • Representam uma única entidade.
  • Não exigem instanciação com new.
  • São simples e rápidos de criar.
  • Podem conter propriedades e métodos.
  • Geralmente não são reutilizados como modelo.

Exemplos de Objetos Únicos

Configurações da Aplicação

const configuracoes = {
    tema: "escuro",
    notificacoes: true,
    idioma: "pt-BR"
};

Existe apenas um conjunto de configurações ativo.

Usuário Logado

const usuarioLogado = {
    id: 1,
    nome: "Gustavo",
    autenticado: true
};

Informações da Empresa

const empresa = {
    nome: "Tech Solutions",
    cnpj: "00.000.000/0001-00",
    telefone: "(85) 99999-9999"
};

Estado Global Simples

const appState = {
    carregando: false,
    paginaAtual: "home"
};

Objetos Únicos com Métodos

Objetos literais podem armazenar comportamentos.

const contador = {
    valor: 0,

    incrementar() {
        this.valor++;
    },

    decrementar() {
        this.valor--;
    }
};

Uso:

contador.incrementar();

console.log(contador.valor);

Resultado:

1

Nesse caso, existe apenas um contador.

Vantagens dos Objetos Únicos

Simplicidade

A criação é rápida e intuitiva.

const tema = {
    cor: "azul"
};

Menos Código

Não é necessário criar classes, construtores ou instâncias.

Facilidade de Leitura

Os dados ficam organizados em um único lugar.

Flexibilidade

Propriedades podem ser adicionadas ou modificadas facilmente.

tema.fonte = "Arial";

Quando Utilizar Objetos Únicos?

Utilize objetos literais quando:

  • Houver apenas uma instância da entidade.
  • Os dados forem simples.
  • Não existir necessidade de herança.
  • O objeto não precisar ser reutilizado como modelo.
  • A estrutura for pequena ou média.

Quando Evitar?

Evite utilizar objetos únicos quando:

  • Precisar criar várias instâncias semelhantes.
  • Existirem comportamentos complexos.
  • Houver necessidade de herança ou polimorfismo.
  • O sistema exigir maior organização orientada a objetos.

Exemplo inadequado:

const aluno1 = {
    nome: "Ana",
    curso: "JavaScript"
};

const aluno2 = {
    nome: "Carlos",
    curso: "JavaScript"
};

const aluno3 = {
    nome: "Maria",
    curso: "JavaScript"
};

Nesse cenário, uma classe seria mais adequada.

class Aluno {
    constructor(nome, curso) {
        this.nome = nome;
        this.curso = curso;
    }
}

Padrão Singleton e Objetos Únicos

Em outras linguagens, é comum utilizar o padrão de projeto Singleton, que garante a existência de apenas uma instância de uma classe.

Em JavaScript, um objeto literal já funciona naturalmente como um objeto único.

const logger = {
    log(mensagem) {
        console.log(mensagem);
    }
};

Qualquer parte da aplicação pode utilizar o mesmo objeto.

Exemplo Prático

Imagine um sistema financeiro.

const saldoAtual = {
    valor: 1500,

    depositar(valor) {
        this.valor += valor;
    },

    sacar(valor) {
        this.valor -= valor;
    }
};

Uso:

saldoAtual.depositar(500);

console.log(saldoAtual.valor);

Resultado:

2000

Existe apenas um saldo sendo manipulado.

Boas Práticas

  • Utilize const para declarar objetos únicos.
  • Agrupe dados relacionados.
  • Crie métodos para representar comportamentos.
  • Evite objetos excessivamente grandes.
  • Separe responsabilidades quando necessário.

Erros Comuns

Utilizar objetos únicos para representar múltiplas entidades

Se existem vários usuários, produtos ou alunos, considere utilizar classes ou funções fábrica.

Criar objetos gigantes

Objetos com muitas responsabilidades tornam o código difícil de manter.

Duplicar estruturas semelhantes

Se vários objetos possuem a mesma estrutura, provavelmente é hora de criar um modelo reutilizável.

Resumo

Os objetos únicos são objetos literais criados para representar uma única entidade dentro da aplicação. Eles são simples, flexíveis e ideais para armazenar configurações, estados globais, informações de sessão e dados específicos que não precisam ser reutilizados como modelo. Quando há necessidade de criar múltiplas instâncias semelhantes, o uso de classes, funções construtoras ou funções fábrica torna-se uma alternativa mais adequada.
