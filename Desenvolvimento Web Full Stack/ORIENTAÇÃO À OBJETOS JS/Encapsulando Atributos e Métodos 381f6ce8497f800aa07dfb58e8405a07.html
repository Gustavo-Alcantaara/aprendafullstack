Encapsulando Atributos e Métodos

Funções Construtoras — Encapsulando Atributos e Métodos

O encapsulamento é um dos pilares da Orientação a Objetos e tem como objetivo proteger os dados internos de um objeto, permitindo que eles sejam acessados ou modificados apenas de maneira controlada.

Nas funções construtoras, o encapsulamento é implementado de forma diferente das classes modernas. Como as funções construtoras não possuem suporte nativo a atributos privados com #, utilizamos o conceito de escopo léxico e closures para criar propriedades e métodos privados.

Relembrando o Conceito de Encapsulamento

O encapsulamento busca responder à seguinte pergunta:

Como proteger os dados internos de um objeto?

Em vez de permitir o acesso direto aos atributos:

conta.saldo = -1000;

Criamos métodos que controlam as alterações:

conta.depositar(500);
conta.sacar(100);

Assim, o próprio objeto é responsável por manter seus dados consistentes.

Problema: Atributos Públicos

Por padrão, tudo o que é definido com this em uma função construtora torna-se público.

Exemplo:

function Conta(saldoInicial) {
    this.saldo = saldoInicial;
}

Uso:

const conta = new Conta(1000);

console.log(conta.saldo);

Resultado:

1000

O problema é que qualquer parte do código pode alterar o valor.

conta.saldo = -5000;

Isso compromete a integridade do objeto.

Criando Atributos Privados com Variáveis Locais

Para encapsular dados, basta declarar variáveis dentro da função construtora sem utilizar this.

function Conta(saldoInicial) {
    let saldo = saldoInicial;
}

A variável saldo existe apenas dentro da função.

Tentativa de acesso:

const conta = new Conta(1000);

console.log(conta.saldo);

Resultado:

undefined

O atributo está protegido.

Utilizando Closures

Embora a variável privada não possa ser acessada diretamente, os métodos internos ainda conseguem utilizá-la.

Isso é possível graças às closures.

function Conta(saldoInicial) {
    let saldo = saldoInicial;

    this.consultarSaldo = function() {
        return saldo;
    };
}

Uso:

const conta = new Conta(1000);

console.log(conta.consultarSaldo());

Resultado:

1000

O método continua acessando a variável privada porque foi criado dentro do mesmo escopo.

Exemplo Completo de Encapsulamento

function Conta(saldoInicial) {
    let saldo = saldoInicial;

    this.depositar = function(valor) {
        if (valor > 0) {
            saldo += valor;
        }
    };

    this.sacar = function(valor) {
        if (valor > 0 && valor <= saldo) {
            saldo -= valor;
        }
    };

    this.consultarSaldo = function() {
        return saldo;
    };
}

Uso:

const conta = new Conta(1000);

conta.depositar(500);
conta.sacar(200);

console.log(conta.consultarSaldo());

Resultado:

1300

Tentativa de acesso direto:

console.log(conta.saldo);

Resultado:

undefined

Entendendo o Funcionamento Interno

Quando a função construtora é executada:

const conta = new Conta(1000);

O JavaScript cria um escopo privado para aquela instância.

Podemos imaginar algo semelhante a:

Conta
 ├── saldo → 1000
 ├── depositar()
 ├── sacar()
 └── consultarSaldo()

O atributo saldo permanece inacessível externamente.

Cada instância possui sua própria cópia dessa variável.

Métodos Privados

Também é possível criar funções privadas.

function Usuario(nome) {
    function validarNome(valor) {
        return valor.length >= 3;
    }

    this.definirNome = function(novoNome) {
        if (validarNome(novoNome)) {
            nome = novoNome;
        }
    };

    this.obterNome = function() {
        return nome;
    };
}

Uso:

const usuario = new Usuario("Gustavo");

usuario.definirNome("Ana");

console.log(usuario.obterNome());

Resultado:

Ana

A função validarNome() não pode ser acessada externamente.

Limitação: Consumo de Memória

O encapsulamento com closures possui uma desvantagem importante.

Cada objeto criado recebe sua própria cópia dos métodos.

const conta1 = new Conta(1000);
const conta2 = new Conta(2000);

Internamente:

conta1 → depositar()
conta2 → depositar()

São funções diferentes ocupando espaços distintos na memória.

Isso acontece porque os métodos precisam manter acesso às variáveis privadas.

Por que Não Utilizar o prototype?

Métodos definidos no prototype são compartilhados entre as instâncias.

Conta.prototype.depositar = function(valor) {
    // ...
};

Porém, eles não conseguem acessar variáveis locais da função construtora.

function Conta(saldoInicial) {
    let saldo = saldoInicial;
}

Conta.prototype.consultarSaldo = function() {
    return saldo;
};

Resultado:

ReferenceError: saldo is not defined

O prototype não possui acesso ao escopo privado.

Comparação com Classes Modernas

Função construtora:

function Conta(saldoInicial) {
    let saldo = saldoInicial;

    this.consultarSaldo = function() {
        return saldo;
    };
}

Classe moderna:

class Conta {
    #saldo;

    constructor(saldoInicial) {
        this.#saldo = saldoInicial;
    }

    consultarSaldo() {
        return this.#saldo;
    }
}

As classes oferecem uma sintaxe mais clara e eficiente para encapsulamento.

Quando Utilizar Esse Padrão?

O encapsulamento com funções construtoras é útil para:

  • Compreender closures.
  • Estudar o funcionamento interno do JavaScript.
  • Trabalhar com código legado.
  • Criar objetos com dados realmente privados.

Em projetos modernos, as classes com campos privados costumam ser a melhor opção.

Vantagens

  • Protege dados internos.
  • Garante regras de negócio.
  • Impede acesso indevido.
  • Utiliza recursos nativos da linguagem.
  • Demonstra o poder das closures.

Desvantagens

  • Consome mais memória.
  • Métodos não são compartilhados.
  • Código menos legível.
  • Manutenção mais complexa.
  • Menor desempenho em grande escala.

Boas Práticas

  • Exponha apenas os métodos necessários.
  • Valide dados antes de alterá-los.
  • Utilize nomes claros para métodos de acesso.
  • Evite expor dados sensíveis diretamente.
  • Prefira classes modernas em novos projetos.

Resumo

O encapsulamento em funções construtoras é implementado através de variáveis locais e closures, permitindo criar atributos e métodos privados sem utilizar this. As variáveis declaradas dentro da função permanecem inacessíveis externamente, enquanto os métodos públicos mantêm acesso a elas por meio do escopo léxico. Embora esse padrão seja eficiente para proteger dados, ele possui limitações relacionadas ao consumo de memória, já que cada instância recebe sua própria cópia dos métodos. Atualmente, as classes com campos privados (#) oferecem uma alternativa mais moderna e legível para implementar encapsulamento em JavaScript.
