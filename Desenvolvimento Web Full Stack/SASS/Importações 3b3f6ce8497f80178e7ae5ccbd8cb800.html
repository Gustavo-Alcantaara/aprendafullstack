Importações no SASS

O que são Importações?

As importações no SASS permitem dividir o código em vários arquivos menores e reutilizá-los em um único projeto. Em vez de escrever todo o SCSS em um único arquivo, é possível separar o código por responsabilidade (variáveis, mixins, componentes, layouts etc.) e depois importá-lo quando necessário.

Essa organização torna o projeto mais limpo, escalável e fácil de manter.

Objetivos das Importações

As importações são utilizadas para:

  • Organizar o projeto em módulos.
  • Evitar arquivos muito grandes.
  • Reutilizar código.
  • Facilitar a manutenção.
  • Melhorar a legibilidade.
  • Compartilhar variáveis, funções e mixins entre arquivos.
  • Favorecer o trabalho em equipe.

Como funcionam?

Em vez de colocar todo o código em um único arquivo:

style.scss

Podemos dividir em vários arquivos:

scss/

_variables.scss

_mixins.scss

_functions.scss

_header.scss

_footer.scss

_buttons.scss

_home.scss

style.scss

O arquivo principal (style.scss) reúne todos os demais.

Partials (Arquivos Parciais)

No SASS, arquivos destinados apenas à importação são chamados de partials.

Eles recebem um underline (_) no início do nome.

Exemplos:

_variables.scss

_mixins.scss

_buttons.scss

_header.scss

O underline indica que esses arquivos não devem ser compilados individualmente, mas apenas quando forem importados por outro arquivo.

A diretiva @import

Durante muitos anos, a importação era feita com a diretiva @import.

Exemplo:

@import "variables";
@import "mixins";
@import "buttons";

Importante: a extensão .scss e o underline (_) não precisam ser informados.

Arquivo:

_variables.scss

Importação:

@import "variables";

Exemplo completo com @import

_variables.scss

$cor-principal: #3498db;
$padding: 20px;

_buttons.scss

button{
    background: $cor-principal;
    padding: $padding;
}

style.scss

@import "variables";
@import "buttons";

CSS gerado

button{
    background:#3498db;
    padding:20px;
}

Problemas do @import

Embora muito utilizado no passado, o @import apresenta algumas limitações:

  • Importa o mesmo arquivo várias vezes, podendo gerar código duplicado.
  • Todas as variáveis e mixins ficam no escopo global, aumentando o risco de conflitos de nomes.
  • Dificulta a organização em projetos grandes.
  • Foi descontinuado (deprecated) nas versões modernas do SASS.

Por esses motivos, o uso de @import não é mais recomendado para novos projetos.

A diretiva @use (Recomendada)

Atualmente, a forma recomendada de importar arquivos no SASS é utilizando @use.

Ela importa um módulo apenas uma vez e mantém seus membros organizados em um namespace (espaço de nomes).

Sintaxe:

@use "arquivo";

Exemplo com @use

_variables.scss

$cor-principal: blue;

style.scss

@use "variables";

body{
    color: variables.$cor-principal;
}

CSS gerado

body{
    color: blue;
}

Observe que a variável é acessada usando:

variables.$cor-principal

O prefixo variables corresponde ao nome do arquivo importado.

Alterando o namespace

É possível definir um apelido (alias) para o módulo.

@use "variables" as vars;

body{
    color: vars.$cor-principal;
}

Isso reduz a quantidade de caracteres digitados e melhora a legibilidade.

Removendo o namespace

Caso seja realmente necessário, é possível remover o namespace utilizando as *.

@use "variables" as *;

body{
    color: $cor-principal;
}

Embora funcione, essa prática não é recomendada, pois pode causar conflitos entre variáveis de módulos diferentes.

Importando Mixins

_mixins.scss

@mixin botao{

    padding:10px;
    border-radius:5px;

}

style.scss

@use "mixins";

button{

    @include mixins.botao;

}

Resultado:

button{

    padding:10px;
    border-radius:5px;

}

Importando Funções

_functions.scss

@function dobro($valor){

    @return $valor * 2;

}

style.scss

@use "functions";

.box{

    width:functions.dobro(100px);

}

Resultado:

.box{

    width:200px;

}

Utilizando vários módulos

@use "variables";
@use "mixins";
@use "functions";

Cada módulo possui seu próprio namespace.

.card{

    color:variables.$cor-principal;

    padding:functions.dobro(10px);

    @include mixins.botao;

}

A diretiva @forward

Além do @use, o SASS oferece a diretiva @forward, utilizada para reexportar módulos.

Ela é muito útil para criar um único ponto de entrada para diversos arquivos.

Exemplo:

_index.scss

@forward "variables";
@forward "mixins";
@forward "functions";

Depois, basta importar apenas esse arquivo:

@use "index";

Assim, todos os módulos encaminhados estarão disponíveis por meio do namespace index.

Organização profissional

Uma estrutura bastante utilizada em projetos SASS é:

scss/
│
├── abstracts/
│   ├── _variables.scss
│   ├── _functions.scss
│   ├── _mixins.scss
│   └── _index.scss
│
├── base/
│   ├── _reset.scss
│   ├── _typography.scss
│
├── components/
│   ├── _buttons.scss
│   ├── _cards.scss
│
├── layout/
│   ├── _header.scss
│   ├── _footer.scss
│
├── pages/
│   ├── _home.scss
│   ├── _about.scss
│
└── style.scss

Essa organização facilita a escalabilidade e a manutenção do projeto.

Exemplo de arquivo principal

@use "abstracts";
@use "base/reset";
@use "base/typography";
@use "layout/header";
@use "layout/footer";
@use "components/buttons";
@use "components/cards";
@use "pages/home";

Todo o projeto será compilado em um único arquivo CSS.

Boas práticas

  • Utilize @use em vez de @import.
  • Centralize variáveis, funções e mixins em módulos específicos.
  • Utilize @forward para criar pontos de entrada organizados.
  • Evite usar as *, salvo quando houver um motivo específico.
  • Mantenha uma estrutura de pastas consistente.
  • Dê nomes claros aos arquivos e módulos.

Vantagens

  • Melhor organização do projeto.
  • Reutilização de código.
  • Evita duplicação de importações.
  • Reduz conflitos entre variáveis.
  • Facilita manutenção.
  • Escalabilidade para projetos grandes.
  • Melhor compatibilidade com as versões atuais do SASS.

Desvantagens

  • Exige um entendimento inicial sobre namespaces.
  • Pode aumentar a quantidade de arquivos no projeto.
  • Projetos muito pequenos podem não se beneficiar tanto da modularização.

Casos de uso

As importações são utilizadas para organizar:

  • Variáveis.
  • Mixins.
  • Funções.
  • Componentes.
  • Layouts.
  • Páginas.
  • Temas.
  • Tipografia.
  • Arquivos de configuração.
  • Design Systems.

Resumo

As importações no SASS permitem dividir um projeto em diversos arquivos menores e reutilizá-los de forma organizada. Tradicionalmente, isso era feito com a diretiva @import, mas ela foi descontinuada devido a problemas como duplicação de código e escopo global. Atualmente, a abordagem recomendada é utilizar @use, que importa módulos apenas uma vez e organiza seus membros por meio de namespaces, além de @forward, que facilita a criação de pontos de entrada para vários módulos. Essa modularização torna o código mais limpo, reutilizável, escalável e fácil de manter, sendo a prática adotada em projetos modernos desenvolvidos com SASS.
