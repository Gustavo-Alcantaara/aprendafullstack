Herança no SASS

O que é Herança?

A Herança (Inheritance) é um recurso do SASS que permite compartilhar estilos entre diferentes seletores, evitando a repetição de propriedades CSS.

Ela é implementada por meio da diretiva @extend, que faz com que um seletor herde os estilos de outro.

Em vez de copiar todas as propriedades para cada classe, o SASS combina os seletores no CSS compilado, reduzindo a duplicação de código.

Objetivos da Herança

A herança é utilizada para:

  • Reutilizar estilos.
  • Evitar repetição de código.
  • Padronizar componentes.
  • Facilitar manutenção.
  • Reduzir o tamanho do CSS gerado.
  • Criar componentes relacionados.

Como funciona?

A herança segue um processo simples:

  1. Cria-se um seletor base.
  1. Outro seletor utiliza @extend.
  1. O SASS une os seletores que compartilham os mesmos estilos.
  1. O CSS gerado contém uma única regra para todos os seletores.

Fluxo:

Classe Base
      ↓
@extend
      ↓
SASS une os seletores
      ↓
CSS otimizado

Sintaxe

A sintaxe básica é:

@extend seletor;

Exemplo:

.botao{

    padding:10px;
    border:none;

}

.btn-primary{

    @extend .botao;

}

Primeiro exemplo

SCSS

.botao{

    padding:10px;
    background:blue;
    color:white;

}

.btn-sucesso{

    @extend .botao;

}

CSS gerado

.botao, .btn-sucesso{

    padding:10px;
    background:blue;
    color:white;

}

Observe que o SASS não copia as propriedades para .btn-sucesso; ele apenas agrupa os seletores.

Adicionando estilos próprios

Após utilizar @extend, a nova classe pode possuir propriedades adicionais.

SCSS

.botao{

    padding:10px;
    color:white;

}

.btn-danger{

    @extend .botao;

    background:red;

}

CSS gerado

.botao, .btn-danger{

    padding:10px;
    color:white;

}

.btn-danger{

    background:red;

}

Assim, .btn-danger herda os estilos do botão base e adiciona sua própria cor de fundo.

Herança com múltiplas classes

Várias classes podem herdar da mesma classe base.

.botao{

    padding:10px;
    border-radius:5px;

}

.btn-primary{

    @extend .botao;

}

.btn-success{

    @extend .botao;

}

.btn-danger{

    @extend .botao;

}

Resultado:

.botao,
.btn-primary,
.btn-success,
.btn-danger{

    padding:10px;
    border-radius:5px;

}

Todos compartilham exatamente o mesmo conjunto de propriedades.

Placeholders (%)

Na maioria dos projetos modernos, a herança é utilizada com Placeholders.

Um Placeholder Selector é um seletor especial que começa com %.

Exemplo:

%botao{

    padding:10px;
    border-radius:5px;

}

Diferentemente de uma classe comum, um placeholder não aparece no CSS final, a menos que seja utilizado com @extend.

Utilizando Placeholders

SCSS

%botao{

    padding:10px;
    color:white;

}

.btn-primary{

    @extend %botao;

    background:blue;

}

.btn-danger{

    @extend %botao;

    background:red;

}

CSS gerado

.btn-primary,
.btn-danger{

    padding:10px;
    color:white;

}

.btn-primary{

    background:blue;

}

.btn-danger{

    background:red;

}

Perceba que %botao não aparece no CSS compilado.

Vantagens dos Placeholders

Os placeholders são recomendados porque:

  • Não geram classes desnecessárias.
  • Mantêm o CSS mais limpo.
  • São destinados exclusivamente ao compartilhamento de estilos.
  • Evitam que uma classe base seja utilizada diretamente no HTML.

Herança entre componentes

%card{

    padding:20px;
    border-radius:10px;
    box-shadow:0 0 10px rgba(0,0,0,.2);

}

.card-produto{

    @extend %card;

}

.card-usuario{

    @extend %card;

}

Resultado:

.card-produto,
.card-usuario{

    padding:20px;
    border-radius:10px;
    box-shadow:0 0 10px rgba(0,0,0,.2);

}

Herança em seletores aninhados

A herança também funciona dentro de estruturas aninhadas.

%texto{

    font-weight:bold;

}

.card{

    h2{

        @extend %texto;

    }

}

Resultado:

.card h2{

    font-weight:bold;

}

Herança com múltiplos @extend

Uma classe pode herdar de mais de um placeholder.

%borda{

    border:1px solid black;

}

%sombra{

    box-shadow:0 0 10px rgba(0,0,0,.3);

}

.card{

    @extend %borda;
    @extend %sombra;

}

Resultado:

.card{

    border:1px solid black;
    box-shadow:0 0 10px rgba(0,0,0,.3);

}

Herança e Mixins

Embora ambos reutilizem código, eles funcionam de maneira diferente.

Herança (@extend)

%botao{

    padding:10px;

}

.btn{

    @extend %botao;

}

Resultado:

.btn{

    padding:10px;

}

O SASS compartilha a mesma regra CSS.

Mixin

@mixin botao{

    padding:10px;

}

.btn{

    @include botao;

}

Resultado:

.btn{

    padding:10px;

}

O conteúdo do Mixin é copiado para cada @include.

Diferença entre @extend e @include

@extend@include (Mixin)
Compartilha regras CSSCopia propriedades
Utiliza @extendUtiliza @include
Ideal para estilos idênticosIdeal para estilos personalizados
Gera CSS menorPode gerar CSS maior
Não recebe parâmetrosPode receber parâmetros

Quando utilizar Herança?

A herança é recomendada quando:

  • Vários componentes possuem exatamente a mesma base de estilos.
  • Não há necessidade de parâmetros.
  • O objetivo é compartilhar regras CSS.

Exemplos:

  • Botões.
  • Cards.
  • Alertas.
  • Formulários.
  • Containers.
  • Tipografia.

Quando utilizar Mixins?

Prefira Mixins quando:

  • Os estilos precisam ser personalizados.
  • São necessários parâmetros.
  • É preciso utilizar lógica condicional.
  • Há necessidade de laços (@for, @each, @while).

Boas práticas

  • Prefira utilizar %placeholders em vez de classes comuns para herança.
  • Utilize @extend apenas quando os estilos forem realmente compartilhados.
  • Evite cadeias muito longas de herança, pois podem gerar seletores complexos.
  • Utilize Mixins quando houver necessidade de personalização.
  • Organize os placeholders em arquivos específicos, como _placeholders.scss.

Vantagens

  • Reduz repetição de código.
  • Gera CSS mais enxuto.
  • Facilita manutenção.
  • Padroniza componentes.
  • Excelente para estilos comuns.
  • Muito útil em Design Systems.

Desvantagens

  • Pode gerar seletores CSS complexos quando usado em excesso.
  • Não aceita parâmetros.
  • Não é adequado para estilos que precisam variar.
  • Em alguns casos, Mixins oferecem maior flexibilidade.

Organização recomendada

scss/
│
├── abstracts/
│   ├── _variables.scss
│   ├── _functions.scss
│   ├── _mixins.scss
│   ├── _placeholders.scss
│
├── components/
│
├── layout/
│
└── style.scss

Os placeholders ficam concentrados em _placeholders.scss.

Exemplo completo

_placeholders.scss

%botao{

    padding:12px;
    border:none;
    border-radius:6px;
    color:white;
    cursor:pointer;

}

style.scss

@use "placeholders";

.btn-primary{

    @extend %botao;

    background:#0d6efd;

}

.btn-success{

    @extend %botao;

    background:#198754;

}

.btn-danger{

    @extend %botao;

    background:#dc3545;

}

CSS gerado

.btn-primary,
.btn-success,
.btn-danger{

    padding:12px;
    border:none;
    border-radius:6px;
    color:white;
    cursor:pointer;

}

.btn-primary{

    background:#0d6efd;

}

.btn-success{

    background:#198754;

}

.btn-danger{

    background:#dc3545;

}

Casos de uso

A herança é amplamente utilizada para:

  • Botões.
  • Cards.
  • Alertas.
  • Formulários.
  • Componentes reutilizáveis.
  • Tipografia.
  • Layouts padronizados.
  • Design Systems.

Resumo

A Herança no SASS é um recurso implementado pela diretiva @extend, que permite compartilhar estilos entre diferentes seletores sem duplicar propriedades no CSS compilado. A forma mais recomendada de utilizá-la é por meio dos Placeholders (%), que são seletores especiais criados exclusivamente para reutilização e que não aparecem no CSS final. A herança é ideal para componentes que possuem uma base de estilos idêntica, como botões, cards e alertas, resultando em um código mais organizado, reutilizável e com menor tamanho. Quando há necessidade de parâmetros, lógica condicional ou personalização dos estilos, os Mixins são a alternativa mais adequada.
