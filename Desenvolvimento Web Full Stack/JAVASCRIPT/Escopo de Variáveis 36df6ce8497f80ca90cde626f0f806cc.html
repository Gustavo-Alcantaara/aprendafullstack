Escopo de Variáveis

Em JavaScript, escopo de variáveis define onde uma variável pode ser acessada dentro do código. Dependendo de onde ela foi criada, ela pode existir apenas em uma parte do programa ou em todo ele.

O que é escopo?

Escopo é a “área de visibilidade” da variável.

Escopo Global

Variáveis criadas fora de funções ou blocos podem ser acessadas em qualquer lugar do código.

let nome="Gustavo";

function mostrarNome() {
console.log(nome);
}

mostrarNome();

Aqui nome é global.

Escopo Local

Variáveis criadas dentro de funções só existem dentro delas.

function teste() {
let mensagem="Olá";
console.log(mensagem);
}

teste();

Fora da função:

console.log(mensagem);

Isso gera erro.

Escopo de Bloco

Variáveis criadas com let e const respeitam blocos {}:

if (true) {
let idade=21;
}

console.log(idade);

Resultado:

erro.

var ignora escopo de bloco

if (true) {
var nome="Gustavo";
}

console.log(nome);

Resultado:

Gustavo

Por isso var é menos recomendado hoje.

Escopo de Função

var funciona baseado em função:

function teste() {
var cidade="Fortaleza";
}

console.log(cidade);

Isso gera erro porque cidade só existe dentro da função.

Shadowing

Uma variável local pode “esconder” uma global:

let nome="Gustavo";

function teste() {
let nome="Carlos";

console.log(nome);
}

teste();

Resultado:

Carlos

A variável interna teve prioridade.

Escopo Léxico

Funções internas conseguem acessar variáveis das funções externas.

function externa() {
let mensagem="Olá";

function interna() {
console.log(mensagem);
  }

interna();
}

externa();

Closures

Quando uma função “lembra” das variáveis do escopo onde foi criada.

function contador() {
let numero = 0;

return function() {
numero++;
return numero;
  };
}

const incrementar = contador();

console.log(incrementar());
console.log(incrementar());

Resultado:

1
2

A função interna continua tendo acesso à variável numero.

Escopo em loops

Com let, cada repetição possui um novo escopo:

for (let i = 0; i < 3; i++) {
console.log(i);
}

Hoisting e escopo

Variáveis declaradas com:

  • var → sofrem hoisting e começam como undefined
  • let e const → também sofrem hoisting, mas ficam em uma área chamada:

Temporal  Dead  Zone  (TDZ)Temporal\;Dead\;Zone\;(TDZ)TemporalDeadZone(TDZ)

Até serem inicializadas.

Boas práticas

  • Prefira let e const
  • Evite variáveis globais excessivas
  • Crie variáveis no menor escopo possível
  • Use const quando o valor não mudar

Resumindo

Escopo controla:

  • onde variáveis existem
  • quem pode acessá-las
  • quanto tempo elas permanecem na memória

Entender escopo é essencial para evitar bugs e escrever aplicações organizadas em tecnologias como React e Node.js.
