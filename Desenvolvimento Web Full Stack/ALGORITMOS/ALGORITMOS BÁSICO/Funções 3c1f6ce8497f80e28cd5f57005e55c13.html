Funções

As funções são estruturas fundamentais da lógica de programação utilizadas para organizar, reutilizar e executar um conjunto de instruções com o objetivo de produzir um resultado.

Uma função pode receber dados, realizar algum processamento e retornar um valor para o local onde foi chamada.

Por exemplo, podemos criar uma função para somar dois números:

função somar(a, b)
    retorne a + b
fimfunção

Depois podemos utilizá-la:

resultado <- somar(10, 20)

O resultado será:

30

A principal diferença em relação a um procedimento é que, na abordagem tradicional da lógica de programação, a função normalmente retorna um valor, enquanto o procedimento é utilizado principalmente para executar uma ação.

1. O que é uma função?

Uma função é um bloco de código identificado por um nome, criado para realizar uma tarefa específica e, normalmente, produzir um resultado.

Podemos representar uma função desta maneira:

Entrada → Processamento → Saída

Por exemplo:

10 + 20 → cálculo → 30

A função poderia ser:

função somar(a, b)
    retorne a + b
fimfunção

Quando fazemos:

somar(10, 20)

a função recebe 10 e 20, realiza o cálculo e retorna 30.

2. Por que utilizar funções?

Imagine que um programa precisa calcular uma média várias vezes.

Sem uma função, poderíamos escrever:

media1 <- (nota1 + nota2) / 2
media2 <- (nota3 + nota4) / 2
media3 <- (nota5 + nota6) / 2

Com uma função:

função calcularMedia(nota1, nota2)
    retorne (nota1 + nota2) / 2
fimfunção

Podemos fazer:

media1 <- calcularMedia(8, 7)
media2 <- calcularMedia(9, 6)
media3 <- calcularMedia(10, 8)

Isso reduz a repetição e deixa o algoritmo mais organizado.

3. Estrutura básica de uma função

Uma função pode ser representada de forma geral como:

função nomeDaFuncao(parâmetros)
    instruções
    retorne resultado
fimfunção

Por exemplo:

função dobro(numero)
    retorne numero * 2
fimfunção

Chamando:

resultado <- dobro(5)

Temos:

resultado = 10

4. Partes de uma função

Uma função normalmente possui alguns elementos importantes:

função somar(a, b)
    retorne a + b
fimfunção

Nome

somar

Identifica a função.

Parâmetros

a, b

São os dados que a função recebe.

Processamento

a + b

É a operação realizada.

Retorno

retorne

Indica o valor que será devolvido.

5. Declaração de uma função

A declaração é o momento em que criamos a função.

Exemplo:

função quadrado(numero)
    retorne numero * numero
fimfunção

Nesse momento estamos definindo:

"Existe uma função chamada quadrado que recebe um número e retorna esse número multiplicado por ele mesmo."

6. Chamada de uma função

Depois de declarar a função, podemos chamá-la.

resultado <- quadrado(5)

A função recebe:

5

Executa:

5 * 5

E retorna:

25

Portanto:

resultado = 25

7. Parâmetros

Os parâmetros são valores que uma função recebe para realizar seu processamento.

Exemplo:

função multiplicar(a, b)
    retorne a * b
fimfunção

Temos dois parâmetros:

a
b

Podemos chamar:

multiplicar(5, 4)

Nesse caso:

a = 5
b = 4

A função calcula:

5 * 4

E retorna:

20

8. Argumentos

É importante diferenciar parâmetro de argumento.

Na declaração:

função somar(a, b)

a e b são parâmetros.

Na chamada:

somar(10, 20)

10 e 20 são argumentos.

Podemos resumir:

Parâmetro: variável definida na função.
Argumento: valor enviado para a função.

9. Função sem parâmetros

Nem toda função precisa receber informações.

Exemplo:

função obterNumero()
    retorne 10
fimfunção

Podemos chamar:

numero <- obterNumero()

Resultado:

10

Outro exemplo:

função obterNome()
    retorne "Gusta"
fimfunção

Chamada:

nome <- obterNome()

Resultado:

Gusta

10. Função com um parâmetro

Exemplo:

função dobro(numero)
    retorne numero * 2
fimfunção

Chamadas:

dobro(5)
dobro(10)
dobro(20)

Resultados:

10
20
40

A mesma função pode ser reutilizada com diferentes valores.

11. Função com vários parâmetros

Uma função pode receber vários parâmetros.

função calcularMedia(nota1, nota2, nota3)
    media <- (nota1 + nota2 + nota3) / 3
    retorne media
fimfunção

Chamada:

media <- calcularMedia(8, 7, 9)

Cálculo:

(8 + 7 + 9) / 3

Resultado:

8

12. O comando RETORNE

O comando RETORNE é utilizado para devolver um valor ao local onde a função foi chamada.

Exemplo:

função somar(a, b)
    retorne a + b
fimfunção

Quando fazemos:

resultado <- somar(5, 3)

a função retorna:

8

Então:

resultado = 8

13. Retorno como expressão

O valor retornado não precisa necessariamente estar armazenado em uma variável.

Podemos utilizar diretamente:

escreva(somar(10, 20))

A função retorna:

30

E o programa exibe:

30

Também podemos utilizar o resultado em outra operação:

resultado <- somar(10, 20) * 2

Primeiro:

somar(10, 20) = 30

Depois:

30 * 2 = 60

Portanto:

resultado = 60

14. Tipos de retorno

Uma função pode retornar diferentes tipos de dados.

Inteiro

função dobro(numero): inteiro
    retorne numero * 2
fimfunção

Real

função calcularMedia(a, b): real
    retorne (a + b) / 2
fimfunção

Texto

função obterNome(): caractere
    retorne "Gusta"
fimfunção

Booleano

função maiorDeIdade(idade): logico
    retorne idade >= 18
fimfunção

O tipo exato e a forma de declaração dependem da linguagem ou do pseudocódigo utilizado.

15. Funções booleanas

Uma função pode retornar VERDADEIRO ou FALSO.

Por exemplo:

função ehPar(numero): logico

    se numero % 2 == 0 então
        retorne verdadeiro
    senao
        retorne falso
    fimse

fimfunção

Podemos utilizar:

se ehPar(10) então
    escreva("O número é par.")
fimse

Como 10 é par, a função retorna:

VERDADEIRO

16. Funções e estruturas condicionais

Uma função pode conter estruturas condicionais.

Exemplo:

função maiorDeIdade(idade): logico

    se idade >= 18 então
        retorne verdadeiro
    senao
        retorne falso
    fimse

fimfunção

Podemos simplificar dependendo da linguagem:

função maiorDeIdade(idade): logico
    retorne idade >= 18
fimfunção

O resultado será:

maiorDeIdade(20) → verdadeiro
maiorDeIdade(15) → falso

17. Funções e estruturas de repetição

As funções também podem utilizar loops.

Exemplo: calcular a soma de 1 até n.

função somaAte(n)

    soma <- 0

    para i de 1 até n faça
        soma <- soma + i
    fimpara

    retorne soma

fimfunção

Chamando:

resultado <- somaAte(5)

Temos:

1 + 2 + 3 + 4 + 5

Resultado:

15

18. Funções e procedimentos

Funções e procedimentos são conceitos muito próximos.

Procedimento

Normalmente executa uma ação:

procedimento mostrarMensagem()
    escreva("Olá!")
fimprocedimento

Função

Normalmente produz e retorna um valor:

função somar(a, b)
    retorne a + b
fimfunção

Uma forma simples de memorizar é:

Procedimento → faz alguma coisa.
Função → calcula/produz alguma coisa e devolve um resultado.

Em linguagens modernas, entretanto, essa distinção pode não ser tão rígida, pois muitas linguagens utilizam o conceito geral de função para ambos os casos.

19. Exemplo comparativo

Imagine que precisamos calcular o dobro de um número.

Com procedimento:

procedimento mostrarDobro(numero)

    dobro <- numero * 2
    escreva(dobro)

fimprocedimento

Ele mostra o resultado.

Com função:

função calcularDobro(numero)

    retorne numero * 2

fimfunção

Podemos armazenar o resultado:

resultado <- calcularDobro(10)

E depois utilizá-lo:

escreva(resultado)

Isso proporciona maior flexibilidade.

20. Variáveis locais

Uma função pode criar variáveis utilizadas apenas durante sua execução.

Exemplo:

função calcularMedia(a, b, c)

    soma <- a + b + c
    media <- soma / 3

    retorne media

fimfunção

As variáveis:

soma
media

são utilizadas internamente pela função.

Dependendo da linguagem, elas possuem escopo local, ou seja, não podem ser acessadas diretamente de qualquer parte do programa.

21. Escopo

O escopo determina onde uma variável pode ser acessada.

Por exemplo:

função calcular()

    valor <- 100

    retorne valor

fimfunção

A variável valor pertence ao contexto da função.

Fora dela, normalmente não podemos fazer:

escreva(valor)

porque valor é uma variável local.

Podemos, entretanto, obter seu conteúdo através do retorno:

resultado <- calcular()

Agora:

resultado = 100

22. Funções reutilizáveis

Uma das principais vantagens das funções é a reutilização.

Podemos criar:

função calcularDesconto(preco, percentual)
    desconto <- preco * percentual / 100
    retorne preco - desconto
fimfunção

Depois podemos utilizá-la várias vezes:

preco1 <- calcularDesconto(100, 10)
preco2 <- calcularDesconto(500, 20)
preco3 <- calcularDesconto(1000, 15)

A mesma lógica é reaproveitada para diferentes valores.

23. Funções para validação

Funções são muito úteis para validar informações.

Por exemplo:

função idadeValida(idade): logico

    retorne idade >= 0 E idade <= 120

fimfunção

Podemos utilizar:

se idadeValida(idade) então
    escreva("Idade válida.")
senao
    escreva("Idade inválida.")
fimse

Isso deixa o programa principal mais limpo.

24. Funções para cálculos

Funções são especialmente úteis para operações matemáticas.

Soma

função somar(a, b)
    retorne a + b
fimfunção

Subtração

função subtrair(a, b)
    retorne a - b
fimfunção

Multiplicação

função multiplicar(a, b)
    retorne a * b
fimfunção

Divisão

função dividir(a, b)
    retorne a / b
fimfunção

Assim podemos criar uma pequena biblioteca de operações.

25. Exemplo: calculadora

Podemos criar:

função somar(a, b)
    retorne a + b
fimfunção

função subtrair(a, b)
    retorne a - b
fimfunção

função multiplicar(a, b)
    retorne a * b
fimfunção

função dividir(a, b)
    retorne a / b
fimfunção

Depois:

resultado <- somar(10, 5)

ou:

resultado <- multiplicar(10, 5)

Cada função possui uma responsabilidade específica.

26. Funções compostas

Uma função pode utilizar outra função.

Por exemplo:

função quadrado(numero)
    retorne numero * numero
fimfunção

Podemos criar:

função somaDosQuadrados(a, b)

    retorne quadrado(a) + quadrado(b)

fimfunção

Chamando:

resultado <- somaDosQuadrados(3, 4)

Temos:

quadrado(3) = 9
quadrado(4) = 16

Então:

9 + 16 = 25

Resultado:

25

Esse tipo de composição permite construir algoritmos complexos a partir de funções menores.

27. Funções recursivas

Uma função é chamada de recursiva quando ela chama a si mesma.

Um exemplo clássico é o cálculo do fatorial.

função fatorial(n)

    se n == 0 então
        retorne 1
    senao
        retorne n * fatorial(n - 1)
    fimse

fimfunção

Ao calcular:

fatorial(5)

temos:

5 × fatorial(4)

que resulta em:

5 × 4 × 3 × 2 × 1

Resultado:

120

A recursividade é um conceito importante em algoritmos, mas deve ser utilizada com cuidado para evitar chamadas infinitas.

28. Condição de parada na recursividade

Uma função recursiva precisa possuir uma condição de parada.

No exemplo:

se n == 0 então
    retorne 1

Essa é a condição que interrompe a recursividade.

Sem ela, poderíamos ter:

fatorial(5)
→ fatorial(4)
→ fatorial(3)
→ fatorial(2)
→ fatorial(1)
→ fatorial(0)

e então parar.

Sem uma condição adequada, a função continuaria chamando a si mesma indefinidamente.

29. Funções e abstração

As funções também são uma forma de abstração.

Imagine que o programa precisa verificar se um usuário possui idade suficiente:

se maiorDeIdade(idade) então
    ...
fimse

O programa principal não precisa conhecer todos os detalhes internos.

Ele simplesmente utiliza:

maiorDeIdade(idade)

Os detalhes ficam dentro da função.

Isso permite que o algoritmo seja escrito de maneira mais próxima daquilo que queremos expressar.

30. Funções e modularização

Funções ajudam a dividir um sistema em módulos.

Por exemplo:

Sistema
│
├── autenticarUsuario()
├── validarEmail()
├── cadastrarUsuario()
├── calcularIdade()
├── calcularPagamento()
├── gerarRelatorio()
└── enviarMensagem()

Cada função possui uma responsabilidade.

Essa organização facilita:

  • Desenvolvimento;
  • Testes;
  • Manutenção;
  • Reutilização;
  • Correção de erros.

31. Boas práticas ao criar funções

1. Use nomes claros

Evite:

funcao f1()

Prefira:

funcao calcularMedia()

2. Dê uma responsabilidade específica

Evite uma função que faça tudo:

processarSistema()

Prefira separar:

validarUsuario()
calcularPagamento()
gerarRelatorio()

3. Evite funções enormes

Se uma função possui muitas responsabilidades, pode ser interessante dividi-la.

4. Use parâmetros adequadamente

Uma função deve receber somente os dados necessários para executar sua tarefa.

5. Evite dependências desnecessárias

Quanto mais independente for uma função, mais fácil será reutilizá-la e testá-la.

32. Exemplo completo

Vamos criar um algoritmo para calcular a situação de um aluno.

função calcularMedia(nota1, nota2, nota3)

    media <- (nota1 + nota2 + nota3) / 3

    retorne media

fimfunção

Agora podemos criar uma segunda função:

função verificarSituacao(media)

    se media >= 7 então
        retorne "Aprovado"
    senao se media >= 5 então
        retorne "Recuperação"
    senao
        retorne "Reprovado"
    fimse

fimfunção

No programa principal:

nota1 <- 8
nota2 <- 7
nota3 <- 9

media <- calcularMedia(nota1, nota2, nota3)

situacao <- verificarSituacao(media)

escreva("Média: ", media)
escreva("Situação: ", situacao)

Resultado:

Média: 8
Situação: Aprovado

Observe como o problema foi dividido:

calcularMedia()
        ↓
verificarSituacao()
        ↓
resultado final

Isso é uma aplicação prática de modularização.

33. Vantagens das funções

As principais vantagens são:

  • Reutilização de código;
  • Redução de repetição;
  • Organização do algoritmo;
  • Modularização;
  • Facilidade de manutenção;
  • Facilidade de testes;
  • Abstração de detalhes;
  • Maior legibilidade;
  • Separação de responsabilidades;
  • Possibilidade de criar bibliotecas de funcionalidades reutilizáveis.

34. Erros comuns

Esquecer o retorno

Por exemplo:

função somar(a, b)
    a + b
fimfunção

Dependendo do pseudocódigo, isso não significa necessariamente que o resultado será retornado.

O correto é utilizar explicitamente:

retorne a + b

Retornar o valor errado

Exemplo:

função dobro(numero)
    retorne numero + numero
fimfunção

Nesse caso, funciona matematicamente, mas se a intenção era calcular o quadrado, estaria errado.

A função precisa representar corretamente sua responsabilidade.

Criar funções com responsabilidades demais

Uma função como:

processarTudo()

pode esconder várias responsabilidades.

É melhor separar:

validarDados()
calcularValor()
salvarDados()
gerarRelatorio()

35. Funções em diferentes linguagens

O conceito de função aparece em praticamente todas as linguagens de programação.

PHP

function somar($a, $b) {
    return $a + $b;
}

JavaScript

function somar(a, b) {
    return a + b;
}

Python

def somar(a, b):
    return a + b

C

int somar(int a, int b) {
    return a + b;
}

Apesar da sintaxe mudar, a ideia permanece:

Entrada → Processamento → Retorno

36. Funções como base da programação

As funções são extremamente importantes porque permitem construir programas complexos a partir de pequenas unidades de código.

Por exemplo:

Aplicação
│
├── autenticar()
│   ├── validarUsuario()
│   └── validarSenha()
│
├── vendas()
│   ├── calcularSubtotal()
│   ├── calcularDesconto()
│   └── calcularTotal()
│
└── relatorios()
    ├── gerarDados()
    └── formatarRelatorio()

Cada função resolve uma parte específica do problema.

Isso facilita muito a construção de aplicações grandes.

38. Resumo final

As funções são estruturas fundamentais da programação utilizadas para encapsular uma determinada tarefa e, normalmente, retornar um resultado.

Uma função básica pode ser:

função somar(a, b)
    retorne a + b
fimfunção

E pode ser utilizada:

resultado <- somar(10, 20)

O resultado será:

30

As funções podem:

  • Receber parâmetros;
  • Realizar cálculos;
  • Utilizar condições;
  • Utilizar estruturas de repetição;
  • Chamar outras funções;
  • Retornar diferentes tipos de dados;
  • Ser utilizadas de forma recursiva;
  • Ser reutilizadas várias vezes.

A ideia central é:

          FUNÇÃO
             ↓
      ┌──────────────┐
Entrada → Processamento → Saída
      └──────────────┘
             ↓
         Resultado

Por isso, dominar funções é essencial para avançar em lógica de programação, algoritmos e desenvolvimento de software, pois elas formam uma das principais ferramentas para transformar problemas grandes em pequenas partes organizadas, reutilizáveis e fáceis de compreender.
