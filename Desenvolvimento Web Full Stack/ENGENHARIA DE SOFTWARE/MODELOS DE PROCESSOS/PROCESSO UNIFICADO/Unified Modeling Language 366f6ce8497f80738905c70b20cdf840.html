Unified Modeling Language

Unified Modeling Language (UML)

A UML (Unified Modeling Language) é uma linguagem padronizada usada para modelar sistemas de software.

Ela permite representar visualmente:

  • estrutura do sistema
  • comportamento
  • interação entre componentes
  • arquitetura
  • regras de negócio

A UML não é uma linguagem de programação.

Ela é uma linguagem de modelagem visual.

Objetivo da UML

A UML serve para:

  • visualizar sistemas
  • documentar projetos
  • especificar requisitos
  • facilitar comunicação entre equipes
  • auxiliar no planejamento
  • reduzir complexidade

Origem da UML

A UML surgiu nos anos 1990 pela união de métodos de modelagem criados por:

  • Grady Booch
  • James Rumbaugh
  • Ivar Jacobson

Eles ficaram conhecidos como:

“Os Três Amigos da UML”.

A padronização foi feita pela:

  • Object Management Group

Principais características

1. Linguagem visual

Usa diagramas gráficos.

2. Independente de linguagem

Pode ser usada com:

  • Java
  • Python
  • C#
  • PHP
  • JavaScript
  • etc.

3. Orientada a objetos

A UML foi criada principalmente para sistemas OO.

4. Padronizada

Possui símbolos e regras universais.

Importância da UML

A UML ajuda:

  • analistas
  • desenvolvedores
  • arquitetos
  • clientes
  • gerentes

Todos conseguem entender melhor o sistema.

Estrutura da UML

A UML é baseada em diagramas.

Eles são divididos em:

1. Diagramas Estruturais

Mostram a estrutura do sistema.

2. Diagramas Comportamentais

Mostram o comportamento e interações.

Principais Diagramas UML

1. Diagrama de Casos de Uso

É um dos mais importantes.

Mostra:

  • funcionalidades do sistema
  • interação dos usuários

Elementos principais

Ator

Representa quem interage com o sistema.

Pode ser:

  • usuário
  • sistema externo
  • administrador

Representado por:

Boneco palito

Caso de uso

Representa uma funcionalidade.

Exemplos:

  • Fazer login
  • Emitir relatório
  • Realizar pagamento

Representado por:

Elipse

Exemplo

Cliente -----> (Realizar Compra)

Objetivo

  • entender requisitos
  • identificar funcionalidades
  • comunicação com cliente

Vantagens

  • simples
  • fácil entendimento
  • visão geral do sistema

2. Diagrama de Classes

É o principal diagrama estrutural.

Representa:

  • classes
  • atributos
  • métodos
  • relacionamentos

Estrutura da Classe

-------------------
| Cliente         |
-------------------
| nome            |
| cpf             |
-------------------
| comprar()       |
| pagar()         |
-------------------

Relacionamentos

Associação

Relacionamento comum.

Cliente ---- Pedido

Herança (Generalização)

Pessoa
  ↑
Cliente

Cliente herda características de Pessoa.

Agregação

Relacionamento “tem um”.

Exemplo:

  • Time tem jogadores.

Composição

Relacionamento forte.

Exemplo:

  • Pedido possui itens.

Se o pedido for destruído:

  • os itens também são.

Dependência

Uma classe usa outra temporariamente.

Multiplicidade

Define quantidades.

Exemplo:

Cliente 1 ---- * Pedido

Um cliente pode ter vários pedidos.

3. Diagrama de Sequência

Mostra a troca de mensagens entre objetos ao longo do tempo.

Objetivo

Representar:

  • ordem das interações
  • comunicação entre objetos

Elementos

Linha de vida

Representa objeto ativo.

Mensagem

Comunicação entre objetos.

Exemplo

Cliente → Sistema : login()
Sistema → Banco : validar()
Banco → Sistema : OK

Importância

Muito usado para:

  • modelar regras de negócio
  • entender fluxo interno

4. Diagrama de Atividades

Representa fluxo de processos.

Parecido com fluxograma.

Usos

  • processos de negócio
  • algoritmos
  • regras operacionais

Elementos

ElementoFunção
Inícioponto inicial
Atividadeação
Decisãocondição
Fimencerramento

Exemplo

Início
   ↓
Validar Login
   ↓
Senha correta?
 ↙       ↘
Sim       Não
 ↓         ↓
Entrar   Erro

5. Diagrama de Estados

Mostra os estados de um objeto.

Exemplo

Pedido:

Novo → Pago → Enviado → Entregue

Utilidade

Muito usado em:

  • sistemas embarcados
  • jogos
  • controle de processos

6. Diagrama de Componentes

Mostra módulos do sistema.

Exemplo:

  • API
  • Frontend
  • Banco de dados

Objetivo

Representar arquitetura lógica.

7. Diagrama de Implantação

Mostra infraestrutura física.

Representa:

  • servidores
  • dispositivos
  • rede
  • banco de dados

Exemplo

Cliente → Servidor Web → Banco de Dados

Benefícios da UML

Comunicação

Facilita entendimento da equipe.

Redução de erros

Ajuda a identificar problemas antes da implementação.

Documentação

Cria documentação padronizada.

Manutenção

Facilita evolução do software.

Desvantagens

Pode gerar excesso de documentação

Especialmente em projetos pequenos.

Complexidade

Diagramas grandes podem ficar difíceis.

Tempo de modelagem

Pode aumentar custo inicial.

UML e Engenharia de Software

A UML é muito usada em:

  • análise de requisitos
  • projeto de software
  • arquitetura
  • documentação
  • manutenção

UML e Métodos Ágeis

Em metodologias ágeis:

  • usa-se UML de forma mais leve
  • apenas diagramas necessários

Isso é chamado de:

“Modelagem suficiente”.

Ferramentas UML
