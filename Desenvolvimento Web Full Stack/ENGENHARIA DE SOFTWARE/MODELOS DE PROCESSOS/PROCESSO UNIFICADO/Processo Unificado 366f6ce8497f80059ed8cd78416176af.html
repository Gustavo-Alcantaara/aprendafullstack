Processo Unificado

Processo Unificado (Unified Process — UP)

O Processo Unificado (UP — Unified Process) é um modelo de desenvolvimento de software orientado a objetos baseado em:

  • iteração
  • incrementalismo
  • arquitetura
  • gerenciamento de riscos

Ele foi criado para organizar o desenvolvimento de sistemas complexos de forma controlada e flexível.

O Processo Unificado é fortemente associado à:

  • UML (Unified Modeling Language)

Origem

O Processo Unificado foi desenvolvido por:

  • Grady Booch
  • James Rumbaugh
  • Ivar Jacobson

Os mesmos criadores da UML.

Objetivo do Processo Unificado

O objetivo é:

  • produzir software de qualidade
  • reduzir riscos
  • melhorar organização
  • facilitar manutenção
  • permitir evolução contínua

Características Principais

O Processo Unificado possui quatro características fundamentais:

1. Iterativo

O sistema é desenvolvido em ciclos chamados:

iterações

Cada iteração:

  • analisa
  • projeta
  • implementa
  • testa

parte do sistema.

Exemplo

Iteração 1

  • Login

Iteração 2

  • Cadastro

Iteração 3

  • Relatórios

Benefícios da Iteração

  • feedback rápido
  • redução de riscos
  • correção contínua
  • melhoria gradual

2. Incremental

Cada iteração gera um incremento funcional do sistema.

Ou seja:

  • o software cresce aos poucos.

Exemplo

Versão inicial:

  • autenticação

Depois:

  • compras

Depois:

  • pagamentos

3. Centrado na Arquitetura

A arquitetura do sistema é extremamente importante.

O Processo Unificado define:

  • componentes
  • organização
  • comunicação
  • tecnologias
  • estrutura geral

logo no início.

Objetivos da arquitetura

  • estabilidade
  • escalabilidade
  • reutilização
  • manutenção facilitada

4. Guiado por Casos de Uso

Os requisitos são organizados usando:

  • casos de uso da UML

Os casos de uso ajudam a definir:

  • funcionalidades
  • comportamento do sistema
  • prioridades

Estrutura do Processo Unificado

O Processo Unificado é dividido em:

1. Fases

Grandes etapas do projeto.

2. Disciplinas

Atividades realizadas durante o projeto.

Fases do Processo Unificado

São 4 fases principais:

  1. Concepção
  1. Elaboração
  1. Construção
  1. Transição

1. Fase de Concepção

Objetivo:

  • entender o projeto

Atividades

  • levantamento inicial de requisitos
  • identificação de riscos
  • estudo de viabilidade
  • definição do escopo
  • estimativas iniciais

Resultado

Produz:

  • visão geral do sistema
  • planejamento inicial
  • casos de uso principais

Pergunta principal da fase

“Vale a pena desenvolver esse sistema?”

2. Fase de Elaboração

Objetivo:

  • detalhar requisitos
  • definir arquitetura

É uma das fases mais importantes.

Atividades

  • refinamento dos requisitos
  • modelagem UML
  • definição arquitetural
  • análise de riscos
  • prototipação

Resultado

  • arquitetura estável
  • planejamento detalhado
  • riscos reduzidos

Pergunta principal

“Como o sistema será construído?”

3. Fase de Construção

Objetivo:

  • desenvolver o sistema

Atividades

  • codificação
  • testes
  • integração
  • implementação das funcionalidades

Características

Maior parte do desenvolvimento ocorre aqui.

Resultado

Sistema funcional.

Pergunta principal

“O sistema funciona corretamente?”

4. Fase de Transição

Objetivo:

  • entregar o sistema ao usuário

Atividades

  • implantação
  • treinamento
  • correções finais
  • homologação
  • suporte inicial

Resultado

Sistema em produção.

Pergunta principal

“O sistema está pronto para uso?”

Fluxo das Fases

Concepção
     ↓
Elaboração
     ↓
Construção
     ↓
Transição

Mas:

  • dentro de cada fase existem várias iterações.

As disciplinas aparecem em todas as fases, mas com intensidades diferentes.

Vantagens do Processo Unificado

1. Redução de riscos

Problemas são identificados cedo.

2. Flexibilidade

Mudanças podem ser incorporadas.

3. Desenvolvimento incremental

Entregas parciais.

4. Foco em qualidade

Testes acontecem continuamente.

5. Forte arquitetura

Melhor manutenção e escalabilidade.

Desvantagens

1. Complexidade

Pode ser difícil para equipes pequenas.

2. Excesso de documentação

Se aplicado rigidamente.

3. Alto custo inicial

Arquitetura e planejamento exigem tempo.

RUP (Rational Unified Process)

O RUP é a implementação mais famosa do Processo Unificado.

Foi desenvolvido pela:

  • Rational Software

Depois adquirida pela:

  • IBM

Características do RUP

  • baseado no Processo Unificado
  • altamente documentado
  • uso intenso de UML
  • forte gerenciamento

Quando usar o Processo Unificado

Ideal para:

  • sistemas grandes
  • projetos corporativos
  • software complexo
  • equipes médias/grandes
  • projetos com muitos requisitos

Resumo Geral

O Processo Unificado é:

  • iterativo
  • incremental
  • orientado a arquitetura
  • guiado por casos de uso

Fases:

  1. Concepção
  1. Elaboração
  1. Construção
  1. Transição

Benefícios:

  • redução de riscos
  • melhor organização
  • qualidade
  • flexibilidade

Conceito-chave

O Processo Unificado busca desenvolver software de maneira controlada, iterativa e orientada à arquitetura, permitindo evolução contínua do sistema com redução de riscos.
