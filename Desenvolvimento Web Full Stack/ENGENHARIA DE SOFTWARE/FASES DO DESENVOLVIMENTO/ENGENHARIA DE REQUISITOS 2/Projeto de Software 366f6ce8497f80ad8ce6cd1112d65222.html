Projeto de Software

O Projeto de Software é a etapa da engenharia de software responsável por definir como o sistema será construído.

Enquanto a engenharia de requisitos define:

“o que o sistema deve fazer”

o projeto de software define:

“como o sistema fará isso”.

Essa fase transforma requisitos em uma estrutura técnica organizada para desenvolvimento.

Objetivos do Projeto de Software

  • definir arquitetura do sistema
  • organizar componentes
  • facilitar manutenção
  • melhorar escalabilidade
  • aumentar reutilização
  • reduzir complexidade
  • melhorar desempenho e segurança

O que é feito no Projeto de Software?

São definidos:

  • arquitetura
  • módulos
  • banco de dados
  • interfaces
  • componentes
  • padrões de projeto
  • comunicação entre partes do sistema

Etapas do Projeto de Software

1. Projeto Arquitetural

Define a estrutura geral do sistema.

Exemplo:

  • frontend
  • backend
  • banco de dados
  • APIs
  • microsserviços

Arquiteturas comuns

  • Monolítica
  • Cliente-servidor
  • Microsserviços
  • MVC
  • SOA

2. Projeto de Dados

Define como os dados serão armazenados e organizados.

Inclui:

  • modelagem de banco
  • tabelas
  • relacionamentos
  • chaves primárias
  • normalização

Ferramentas:

  • MER
  • DER

3. Projeto de Interface

Define interação do usuário com o sistema.

Inclui:

  • telas
  • menus
  • navegação
  • usabilidade
  • experiência do usuário

Ferramentas comuns:

  • Figma
  • Adobe XD

4. Projeto de Componentes

Define módulos e responsabilidades do sistema.

Exemplo:

  • módulo de autenticação
  • módulo de pagamentos
  • módulo de relatórios

5. Projeto de Implantação

Define onde e como o sistema será executado.

Inclui:

  • servidores
  • cloud
  • containers
  • infraestrutura

Tecnologias:

  • Docker
  • Kubernetes
  • AWS

Arquitetura de Software

A Arquitetura de Software define a organização estrutural do sistema.

Ela estabelece:

  • componentes
  • comunicação
  • responsabilidades
  • tecnologias

Conceitos importantes

Modularização

Dividir sistema em partes menores independentes.

Vantagens:

  • manutenção mais fácil
  • reutilização
  • menor complexidade

Coesão

Mede o quanto um módulo possui responsabilidades relacionadas.

Alta coesão é desejável.

Acoplamento

Mede dependência entre módulos.

Baixo acoplamento é desejável.

Padrões de Projeto (Design Patterns)

Soluções reutilizáveis para problemas comuns.

Conceito associado à Design Patterns: Elements of Reusable Object-Oriented Software.

Exemplos

Singleton

Permite apenas uma instância da classe.

Factory

Criação flexível de objetos.

Observer

Comunicação entre objetos através de notificações.

MVC

Separação entre:

  • Model
  • View
  • Controller

Projeto Orientado a Objetos

Baseado em:

  • classes
  • objetos
  • herança
  • encapsulamento
  • polimorfismo

Princípios SOLID

Conjunto de boas práticas de design orientado a objetos.

S — Single Responsibility

Uma classe deve ter apenas uma responsabilidade.

O — Open/Closed

Aberto para extensão e fechado para modificação.

L — Liskov Substitution

Subclasses devem substituir classes base sem problemas.

I — Interface Segregation

Interfaces específicas são melhores que genéricas.

D — Dependency Inversion

Depender de abstrações, não implementações.
