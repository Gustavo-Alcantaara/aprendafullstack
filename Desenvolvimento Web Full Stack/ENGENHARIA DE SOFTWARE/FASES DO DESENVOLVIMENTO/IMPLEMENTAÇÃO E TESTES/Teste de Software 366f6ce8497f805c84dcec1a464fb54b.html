Teste de Software

O Teste de Software é o processo de verificar e validar se um sistema funciona corretamente, atende aos requisitos e está livre de falhas importantes.

O principal objetivo dos testes é:

  • encontrar erros
  • garantir qualidade
  • aumentar confiabilidade
  • validar funcionalidades
  • reduzir riscos

Objetivos do Teste de Software

  • identificar bugs
  • validar requisitos
  • garantir funcionamento correto
  • melhorar qualidade
  • reduzir falhas em produção
  • aumentar segurança e estabilidade

O que é um Bug?

Um bug é um defeito ou comportamento incorreto do sistema.

Exemplos:

  • login não funciona
  • cálculo errado
  • tela travando
  • sistema lento
  • falha de segurança

Importância dos Testes

Sem testes, o software pode apresentar:

  • falhas críticas
  • perda de dados
  • prejuízos financeiros
  • problemas de segurança
  • má experiência do usuário

Verificação e Validação

Verificação

Analisa:

“o software foi construído corretamente?”

Foco:

  • arquitetura
  • código
  • documentação

Validação

Analisa:

“o software correto foi construído?”

Foco:

  • necessidades do usuário
  • requisitos do sistema

Níveis de Teste

1. Teste Unitário

Testa pequenas partes isoladas do sistema.

Exemplo:

  • função de cálculo
  • método de autenticação

Objetivo:

verificar funcionamento interno do código.

Exemplo

function soma(a,b){
returna + b;
}

Teste:

soma(2,3) === 5

Ferramentas

  • Jest
  • JUnit
  • PyTest

2. Teste de Integração

Verifica comunicação entre módulos.

Exemplo:

  • frontend ↔ backend
  • API ↔ banco de dados

Objetivo:

identificar falhas na integração.

3. Teste de Sistema

Testa o sistema completo.

Verifica:

  • funcionalidades
  • regras de negócio
  • fluxos principais

4. Teste de Aceitação

Valida se o sistema atende expectativas do cliente.

Normalmente realizado:

  • pelo cliente
  • usuários finais
  • equipe de negócio

Tipos de Teste

Teste Funcional

Valida funcionalidades do sistema.

Exemplo:

  • login
  • cadastro
  • pagamentos

Teste Não Funcional

Avalia características de qualidade.

Inclui:

  • desempenho
  • segurança
  • usabilidade
  • escalabilidade

Testes Não Funcionais Mais Comuns

Teste de Performance

Analisa velocidade e desempenho.

Exemplo:

  • tempo de resposta
  • uso de memória

Teste de Carga

Verifica comportamento sob muitos usuários.

Teste de Estresse

Avalia limites do sistema.

Teste de Segurança

Procura vulnerabilidades.

Exemplos:

  • SQL Injection
  • XSS
  • autenticação fraca

Teste de Usabilidade

Avalia experiência do usuário.

Técnicas de Teste

Caixa Preta (Black Box)

Testa entradas e saídas sem conhecer código interno.

Foco:

  • comportamento do sistema

Caixa Branca (White Box)

Testa lógica interna do código.

Foco:

  • estruturas internas
  • caminhos de execução

Caixa Cinza (Gray Box)

Mistura caixa preta e branca.

Testes Automatizados

Executados automaticamente por ferramentas.

Vantagens:

  • rapidez
  • repetição
  • redução de erros humanos

Testes Manuais

Executados por pessoas.

Muito usados em:

  • usabilidade
  • validação visual
  • experiência do usuário

Regressão

Teste realizado após alterações no sistema.

Objetivo:

garantir que mudanças não quebraram funcionalidades existentes.

TDD (Test-Driven Development)

Metodologia baseada em:

  1. criar teste
  1. implementar código
  1. refatorar

Muito usada em desenvolvimento ágil.

Cobertura de Testes

Mede quanto do código está sendo testado.

Exemplo:

  • 80% de cobertura

Maior cobertura:

  • geralmente aumenta confiabilidade

CI/CD e Testes

Na DevOps os testes são automatizados no pipeline.

Ferramentas:

  • GitHub Actions
  • Jenkins

Processo de Teste

1. Planejamento

Definir:

  • estratégia
  • escopo
  • ferramentas

2. Projeto de Casos de Teste

Criar cenários de validação.

Exemplo:

  • login válido
  • senha incorreta
  • e-mail inexistente

3. Execução dos Testes

Rodar testes e registrar resultados.

4. Correção de Bugs

Equipe corrige problemas encontrados.

5. Reteste

Verificar se falhas foram resolvidas.

Caso de Teste

Documento que descreve:

  • objetivo
  • entrada
  • execução
  • resultado esperado

Exemplo

CampoValor
ObjetivoValidar login
Entradausuário e senha válidos
Resultado esperadoacesso permitido

Relação com Qualidade de Software

Os testes são uma das principais práticas da Qualidade de Software.

Eles ajudam a garantir:

  • confiabilidade
  • estabilidade
  • segurança
  • desempenho

Resumo geral

Teste de software é o processo de verificar se um sistema funciona corretamente e atende aos requisitos definidos.

Ele envolve:

  • testes funcionais
  • testes não funcionais
  • automação
  • validação
  • detecção de falhas

Seu objetivo é aumentar qualidade, segurança e confiabilidade do software antes da entrega ao usuário.
