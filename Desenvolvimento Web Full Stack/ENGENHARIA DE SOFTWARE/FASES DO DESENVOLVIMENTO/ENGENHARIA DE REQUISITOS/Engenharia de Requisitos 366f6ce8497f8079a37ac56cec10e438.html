Engenharia de Requisitos

A Engenharia de Requisitos é a área da engenharia de software responsável por identificar, documentar, analisar, validar e gerenciar as necessidades e expectativas dos usuários e clientes de um sistema.

Ela define o que o software deve fazer e quais restrições ele deve seguir.

É considerada uma das etapas mais importantes do desenvolvimento, porque erros nos requisitos podem gerar:

  • retrabalho
  • aumento de custos
  • atrasos
  • falhas no sistema
  • insatisfação do cliente

Objetivos da Engenharia de Requisitos

  • Entender o problema do cliente
  • Definir funcionalidades do sistema
  • Documentar necessidades claramente
  • Evitar ambiguidades
  • Facilitar desenvolvimento e testes
  • Garantir alinhamento entre equipe e cliente

O que é um requisito?

Um requisito é uma necessidade, condição ou funcionalidade que o sistema deve possuir.

Exemplo:

“O usuário deve conseguir fazer login usando e-mail e senha.”

Tipos de Requisitos

1. Requisitos Funcionais

Descrevem o que o sistema faz.

Exemplos:

  • cadastrar usuários
  • emitir relatórios
  • realizar pagamentos
  • autenticar login

Características

  • representam funcionalidades
  • descrevem ações do sistema
  • geralmente usam verbos

2. Requisitos Não Funcionais

Descrevem como o sistema deve funcionar.

Relacionados a:

  • desempenho
  • segurança
  • usabilidade
  • confiabilidade
  • escalabilidade

Exemplos:

  • sistema deve responder em até 2 segundos
  • aplicação deve suportar 10 mil usuários simultâneos
  • dados devem ser criptografados

3. Requisitos de Negócio

Representam objetivos da empresa.

Exemplo:

  • aumentar vendas em 20%
  • reduzir tempo de atendimento

4. Requisitos do Usuário

Descrevem necessidades sob a visão do usuário.

Exemplo:

“O cliente deve acompanhar pedidos em tempo real.”

5. Requisitos de Sistema

Detalham tecnicamente como o sistema deve operar.

Exemplo:

  • banco PostgreSQL
  • autenticação JWT
  • API REST

Processo da Engenharia de Requisitos

1. Elicitação de Requisitos

Coleta das informações e necessidades.

Técnicas:

  • entrevistas
  • questionários
  • reuniões
  • observação
  • brainstorming
  • prototipação

Objetivo:

entender o problema e o contexto do negócio.

2. Análise de Requisitos

Avaliação dos requisitos coletados.

Atividades:

  • identificar conflitos
  • remover ambiguidades
  • verificar viabilidade
  • priorizar funcionalidades

3. Especificação de Requisitos

Documentação formal dos requisitos.

Normalmente feita em:

  • documentos
  • diagramas
  • casos de uso
  • histórias de usuário

Um documento comum é o:

SRS (Software Requirements Specification)

4. Validação de Requisitos

Verificar se os requisitos:

  • estão corretos
  • fazem sentido
  • atendem ao cliente
  • são testáveis

Problemas comuns:

  • requisitos vagos
  • inconsistências
  • informações faltando

5. Gerenciamento de Requisitos

Controle das mudanças nos requisitos ao longo do projeto.

Inclui:

  • versionamento
  • rastreabilidade
  • controle de alterações
  • priorização

Características de um bom requisito

Um requisito deve ser:

CaracterísticaDescrição
ClaroFácil de entender
CompletoSem informações faltando
ConsistenteSem contradições
TestávelPossível de validar
ViávelPossível de implementar
RastreávelPode ser acompanhado
PrioritárioPossui importância definida

Técnicas utilizadas

Casos de Uso

Descrevem interações entre usuário e sistema.

Exemplo:

  • Fazer login
  • Comprar produto

Muito usados com UML.

Histórias de Usuário

Muito usadas em metodologias ágeis.

Estrutura:

“Como [tipo de usuário], quero [objetivo] para [benefício].”

Exemplo:

“Como cliente, quero recuperar minha senha para acessar minha conta novamente.”

Prototipação

Criação de telas ou modelos visuais antes do desenvolvimento.

Ajuda:

  • validar ideias
  • reduzir erros
  • melhorar comunicação

UML na Engenharia de Requisitos

A UML ajuda na modelagem do sistema usando diagramas.

Principais diagramas:

  • Caso de Uso
  • Classes
  • Atividades
  • Sequência

Rastreabilidade

Capacidade de acompanhar:

  • origem do requisito
  • implementação
  • testes relacionados
  • mudanças realizadas

Ajuda no controle do projeto.

Problemas comuns na Engenharia de Requisitos

  • requisitos incompletos
  • má comunicação com cliente
  • mudanças frequentes
  • ambiguidades
  • falta de documentação
  • requisitos conflitantes

Importância da Engenharia de Requisitos

Uma boa engenharia de requisitos:

  • reduz custos
  • evita retrabalho
  • melhora qualidade
  • aumenta satisfação do cliente
  • facilita manutenção
  • melhora planejamento do projeto

Exemplo prático

Sistema de Delivery

Requisito funcional

  • cliente deve fazer pedidos online

Requisito não funcional

  • pedidos devem ser processados em até 3 segundos

História de usuário

“Como cliente, quero rastrear meu pedido em tempo real.”

Caso de uso

  • realizar login
  • adicionar produto ao carrinho
  • finalizar compra

Relação com metodologias ágeis

Em metodologias como:

  • Scrum
  • Kanban

Os requisitos geralmente são organizados em:

  • backlog
  • histórias de usuário
  • épicos
  • tarefas

Ferramentas comuns

  • Jira
  • Trello
  • Notion
  • Figma
  • Draw.io

Resumo geral

A engenharia de requisitos é responsável por definir e controlar tudo que o sistema deve fazer e como ele deve funcionar.

Ela envolve:

  1. coleta de requisitos
  1. análise
  1. documentação
  1. validação
  1. gerenciamento

Seu objetivo principal é garantir que o software atenda corretamente às necessidades do usuário e do negócio.
