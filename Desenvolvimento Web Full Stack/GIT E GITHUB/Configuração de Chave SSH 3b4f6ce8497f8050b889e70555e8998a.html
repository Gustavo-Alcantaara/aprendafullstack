Configuração de Chave SSH no Git

Introdução

Ao utilizar o Git com plataformas como GitHub, GitLab ou Bitbucket, é necessário autenticar-se para enviar (git push) ou receber (git pull) alterações de um repositório remoto.

Existem duas formas principais de autenticação:

  • HTTPS
  • SSH (Secure Shell)

A autenticação por SSH é a mais recomendada para desenvolvedores, pois oferece maior segurança e praticidade. Depois de configurada, não é necessário informar usuário e senha a cada operação.

O que é SSH?

SSH (Secure Shell) é um protocolo de comunicação seguro utilizado para estabelecer conexões criptografadas entre dois computadores.

No contexto do Git, o SSH permite que o computador do desenvolvedor se comunique de forma segura com o servidor do repositório remoto.

Fluxo:

Seu Computador
      │
      │  Conexão criptografada (SSH)
      ▼
GitHub / GitLab / Bitbucket

Por que utilizar SSH?

Ao usar HTTPS, normalmente é necessário autenticar-se utilizando um token de acesso (Personal Access Token) ou outro método suportado pela plataforma.

Com SSH:

  • A autenticação é automática após a configuração.
  • A comunicação é criptografada.
  • Não é necessário informar credenciais a cada operação.
  • É possível utilizar a mesma chave em diversos projetos.

Como Funciona a Autenticação por Chave SSH?

O SSH utiliza um sistema de criptografia baseado em um par de chaves:

Chave Privada (Private Key)

  • Fica armazenada apenas no computador do usuário.
  • Nunca deve ser compartilhada.
  • É utilizada para provar sua identidade.

Exemplo:

id_ed25519

Chave Pública (Public Key)

  • Pode ser compartilhada.
  • É enviada para o GitHub (ou outro serviço).
  • Permite que o servidor reconheça seu computador.

Exemplo:

id_ed25519.pub

Chave Privada
      │
      ▼
Seu Computador
      │
Comunicação SSH
      │
      ▼
GitHub
      ▲
Chave Pública cadastrada

Algoritmos de Chaves

Os algoritmos mais comuns são:

AlgoritmoSituação
Ed25519Recomendado atualmente
RSACompatível com sistemas antigos
ECDSAMenos utilizado
DSAObsoleto e não recomendado

Hoje, a recomendação é utilizar Ed25519, por oferecer maior segurança e desempenho.

Verificando se Já Existe uma Chave SSH

Antes de criar uma nova chave, verifique se já existe uma.

No Linux, macOS ou Git Bash no Windows:

ls ~/.ssh

Exemplo de saída:

id_ed25519
id_ed25519.pub
known_hosts

Se os arquivos da chave já existirem, normalmente não é necessário gerar uma nova.

Gerando uma Nova Chave SSH

O comando recomendado é:

ssh-keygen -t ed25519 -C "seu-email@exemplo.com"

Explicação

  • ssh-keygen → cria uma nova chave.
  • t ed25519 → define o algoritmo.
  • C → adiciona um comentário (geralmente o e-mail).

Exemplo:

ssh-keygen -t ed25519 -C "gustavo@email.com"

Escolhendo o Local da Chave

Durante a criação será exibida a mensagem:

Enter file in which to save the key

Pressione Enter para utilizar o local padrão:

~/.ssh/id_ed25519

No Windows (Git Bash):

C:\Users\SeuUsuario\.ssh\

Definindo uma Senha (Passphrase)

Depois será solicitado:

Enter passphrase

Você pode:

  • Definir uma senha para aumentar a segurança.
  • Pressionar Enter para deixar a chave sem senha.

A senha protege a chave privada caso alguém tenha acesso ao seu computador.

Arquivos Gerados

Após a criação:

~/.ssh/

id_ed25519

id_ed25519.pub

Função de cada um:

id_ed25519

→ Chave privada

id_ed25519.pub

→ Chave pública

Iniciando o SSH Agent

O SSH Agent mantém a chave privada carregada em memória, evitando a necessidade de digitá-la repetidamente.

Linux e macOS:

eval "$(ssh-agent -s)"

Git Bash (Windows):

eval "$(ssh-agent -s)"

Saída:

Agent pid 12345

Adicionando a Chave ao SSH Agent

ssh-add ~/.ssh/id_ed25519

Resultado:

Identity added

Agora a chave está pronta para ser utilizada.

Copiando a Chave Pública

Visualize o conteúdo:

cat ~/.ssh/id_ed25519.pub

Exemplo:

ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAA...

Copie todo o conteúdo da chave pública.

Adicionando a Chave no GitHub

  1. Faça login no GitHub.
  1. Acesse Settings.
  1. Clique em SSH and GPG keys.
  1. Clique em New SSH key.
  1. Informe um título (por exemplo, "Notebook Pessoal").
  1. Cole a chave pública no campo correspondente.
  1. Salve.

A partir desse momento, o GitHub reconhecerá seu computador.

Testando a Conexão

Execute:

ssh -T git@github.com

Na primeira conexão aparecerá:

Are you sure you want to continue connecting?

Digite:

yes

Resultado esperado:

Hi usuario! You've successfully authenticated...

Isso confirma que a autenticação SSH está funcionando.

Utilizando SSH ao Clonar um Repositório

Ao invés da URL HTTPS:

https://github.com/usuario/projeto.git

Utilize a URL SSH:

git@github.com:usuario/projeto.git

Clonando:

git clone git@github.com:usuario/projeto.git

Agora todas as operações utilizarão SSH.

Alterando um Repositório Existente para SSH

Verifique a URL atual:

git remote -v

Exemplo:

origin

https://github.com/usuario/projeto.git

Altere para SSH:

git remote set-url origin git@github.com:usuario/projeto.git

Verifique novamente:

git remote -v

Resultado:

origin

git@github.com:usuario/projeto.git

Vantagens da Autenticação SSH

  • Comunicação criptografada.
  • Maior segurança.
  • Não exige autenticação manual em cada push ou pull.
  • Fácil de utilizar em vários projetos.
  • Compatível com GitHub, GitLab, Bitbucket e outros serviços.

Boas Práticas

  • Utilize Ed25519 sempre que possível.
  • Nunca compartilhe sua chave privada (id_ed25519).
  • Faça backup da chave privada em um local seguro, se necessário.
  • Proteja a chave com uma passphrase quando possível.
  • Cadastre apenas a chave pública (.pub) nos serviços remotos.
  • Remova do serviço remoto chaves de computadores que não utiliza mais.

Erros Comuns

  • Enviar a chave privada por engano em vez da chave pública.
  • Clonar um repositório usando HTTPS e esperar que a autenticação SSH funcione automaticamente.
  • Esquecer de iniciar o SSH Agent ou adicionar a chave com ssh-add.
  • Copiar apenas parte da chave pública ao cadastrá-la.
  • Alterar ou excluir arquivos da pasta .ssh sem saber sua finalidade.

Resumo

A configuração de uma chave SSH permite autenticar o computador de forma segura junto a serviços como GitHub, GitLab e Bitbucket. O processo consiste em gerar um par de chaves (privada e pública), manter a chave privada protegida no computador, adicionar a chave pública à plataforma de hospedagem e utilizar URLs SSH para clonar e sincronizar repositórios. Depois de configurado, o SSH proporciona uma autenticação prática, segura e amplamente utilizada em ambientes profissionais de desenvolvimento.
