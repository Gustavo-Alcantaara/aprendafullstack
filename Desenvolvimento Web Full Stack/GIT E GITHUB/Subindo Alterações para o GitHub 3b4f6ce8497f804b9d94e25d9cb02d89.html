Subindo Alterações para o GitHub

Introdução

Depois de criar ou modificar arquivos em um projeto Git, é necessário enviar essas alterações para o repositório remoto hospedado no GitHub. Esse processo é conhecido como subir alterações (push).

O envio das alterações permite:

  • Fazer backup do projeto na nuvem.
  • Compartilhar o código com outros desenvolvedores.
  • Manter o repositório remoto atualizado.
  • Colaborar em equipes de desenvolvimento.
  • Integrar o projeto com ferramentas de integração contínua (CI/CD).

O principal comando utilizado é o git push, mas antes dele é necessário realizar outras etapas para registrar as alterações no repositório local.

Fluxo Completo para Enviar Alterações

O processo completo segue esta sequência:

       ▼

Cada etapa possui uma função específica.

Passo 1 – Modificar os Arquivos

Imagine o seguinte projeto:

MeuProjeto/
│
├── index.html
├── style.css
└── script.js

Você altera o arquivo:

index.html

Essas alterações ainda existem apenas no computador local.

Passo 2 – Verificar o Estado do Projeto

Antes de enviar qualquer alteração, execute:

git status

Exemplo de saída:

On branch main

Changes not staged for commit:

modified: index.html

O comando mostra:

  • Arquivos modificados.
  • Arquivos novos.
  • Arquivos removidos.
  • Arquivos preparados para commit.

Passo 3 – Adicionar os Arquivos

As alterações precisam ser colocadas na Staging Area.

Adicionar um arquivo:

git add index.html

Adicionar todos os arquivos:

git add .

Agora o Git está preparado para criar um novo commit.

Passo 4 – Criar um Commit

Depois do git add, registre as alterações no histórico:

git commit -m "Atualiza página inicial"

Exemplo de saída:

[main 3f2ab91]

1 file changed

Neste momento:

  • As alterações estão salvas no repositório local.
  • Ainda não foram enviadas ao GitHub.

Passo 5 – Enviar para o GitHub

Agora execute:

git push

Fluxo:

Repositório Local
        │
   git push
        │
        ▼
GitHub

Após alguns segundos, os commits estarão disponíveis no repositório remoto.

Como Funciona o git push

O comando:

git push

Envia:

  • Commits.
  • Novas branches (quando configuradas).
  • Tags (quando solicitado).

Não envia apenas os arquivos modificados, mas todo o histórico de commits que ainda não existe no servidor.

Primeiro Envio de um Repositório

Na primeira vez que um repositório é enviado ao GitHub, normalmente utiliza-se:

git push -u origin main

Explicação

ParteFunção
git pushEnvia alterações
-uDefine a branch remota padrão (upstream)
originNome do repositório remoto
mainBranch principal

Depois desse primeiro envio, basta utilizar:

git push

O que é origin?

Quando um repositório remoto é conectado:

git remote add origin https://github.com/usuario/projeto.git

O Git cria um apelido chamado:

origin

Ele representa o endereço do repositório remoto.

Verifique:

git remote -v

Exemplo:

origin

https://github.com/usuario/projeto.git

O que é main?

main é a branch principal do projeto.

O comando:

git push origin main

Significa:

"Envie os commits da branch main para o repositório remoto chamado origin."

Exemplo Completo

Imagine este fluxo:

Modificar arquivo:

style.css

Verificar:

git status

Adicionar:

git add .

Commit:

git commit -m "Melhora layout da página"

Enviar:

git push

Agora o GitHub terá exatamente essa nova versão do projeto.

Enviando uma Nova Branch

Suponha que exista:

feature-login

Envie-a:

git push -u origin feature-login

Agora essa branch também existirá no GitHub.

Atualizando uma Branch Existente

Depois do primeiro envio:

git add .

git commit -m "Corrige formulário"

git push

Como a branch já está associada ao remoto, não é necessário informar origin e main novamente.

Verificando o Resultado no GitHub

Após o git push, acesse o repositório no GitHub.

Você verá:

  • Novo commit.
  • Arquivos atualizados.
  • Histórico atualizado.
  • Branch sincronizada.

Quando o Push Pode Falhar?

Existem algumas situações comuns.

Repositório Remoto Mais Atualizado

Mensagem:

rejected

non-fast-forward

Significa que outra pessoa enviou alterações antes de você.

Solução:

git pull

Resolver possíveis conflitos.

Depois:

git push

Permissão Negada

Mensagem:

Permission denied

Possíveis causas:

  • Chave SSH não configurada.
  • Token inválido.
  • Usuário sem permissão.

Branch Inexistente

Mensagem:

src refspec main does not match any

Possíveis causas:

  • Nenhum commit foi criado.
  • Nome da branch está incorreto.

Verifique:

git branch

Falha de Autenticação

Caso utilize HTTPS:

  • Verifique suas credenciais ou o token de acesso.
  • Confirme se possui permissão para enviar alterações ao repositório.

Em projetos colaborativos, é recomendável executar git pull antes do git push para reduzir a chance de conflitos.

Exemplo Completo

# Verificar alterações
git status

# Adicionar arquivos
git add .

# Criar commit
git commit -m "Implementa autenticação"

# Atualizar o repositório local
git pull

# Enviar alterações
git push

Boas Práticas

  • Execute git status antes de criar um commit.
  • Faça commits pequenos e com mensagens descritivas.
  • Utilize git pull antes de git push em projetos colaborativos.
  • Verifique se está na branch correta antes de enviar alterações.
  • Envie alterações com frequência para manter o repositório remoto sincronizado.
  • Revise o código antes de criar o commit e realizar o push.

Erros Comuns

  • Esquecer de executar git add antes do git commit.
  • Tentar fazer git push sem ter criado um commit.
  • Enviar alterações diretamente para a branch main quando o fluxo da equipe exige o uso de branches e Pull Requests.
  • Ignorar mensagens de erro relacionadas a conflitos ou falta de permissões.
  • Utilizar git push --force sem compreender seus impactos, podendo sobrescrever alterações de outros desenvolvedores.

Resumo

Subir alterações para o GitHub consiste em enviar os commits do repositório local para um repositório remoto utilizando o comando git push. Antes do envio, é necessário verificar o estado do projeto (git status), adicionar as alterações à Staging Area (git add) e registrá-las em um commit (git commit). Em ambientes colaborativos, é recomendável atualizar o repositório local com git pull antes de realizar o git push, garantindo que o histórico permaneça sincronizado e reduzindo a possibilidade de conflitos. Esse fluxo é essencial para manter projetos organizados, seguros e acessíveis a toda a equipe.
