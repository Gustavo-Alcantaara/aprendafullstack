Criando Repositório GIT

Criação de um Repositório Git

Introdução

Um repositório Git é o local onde o Git armazena todo o histórico de um projeto. É nele que ficam registrados os arquivos, os commits, as branches, as tags e todas as informações necessárias para controlar as diferentes versões do código.

Todo projeto que utiliza Git precisa estar dentro de um repositório. A criação de um repositório é, geralmente, o primeiro passo para começar a utilizar o controle de versão.

Existem duas formas principais de iniciar um projeto com Git:

  • Criando um repositório local com git init.
  • Clonando um repositório existente com git clone.

O que é um Repositório Git?

Um repositório é uma pasta comum que passou a ser monitorada pelo Git.

Após sua criação, o Git acompanha todas as alterações realizadas nos arquivos desse projeto.

Exemplo:

MeuProjeto/
│
├── index.html
├── style.css
├── script.js
├── README.md
└── .git/

A pasta .git contém todas as informações necessárias para o funcionamento do Git.

Ela armazena:

  • Histórico de commits.
  • Branches.
  • Tags.
  • Configurações.
  • Informações dos autores.
  • Referências do projeto.
  • Objetos internos do Git.

Importante: Nunca exclua a pasta .git se quiser manter o histórico do projeto.

Tipos de Repositórios

Repositório Local

É criado diretamente no computador do desenvolvedor.

Exemplo:

Computador

└── MeuProjeto
      │
      ├── index.html
      ├── style.css
      └── .git

Todo o histórico fica armazenado localmente.

Repositório Remoto

É hospedado em um servidor, permitindo o compartilhamento do projeto com outras pessoas.

Exemplos de plataformas:

  • GitHub
  • GitLab
  • Bitbucket

Fluxo:

Computador
     │
     ▼
Repositório Local
     │
 git push
     │
     ▼
Repositório Remoto

Criando um Repositório Local

Passo 1 – Criar a Pasta do Projeto

Primeiro, crie uma pasta para o projeto.

Exemplo:

MeuProjeto

Ou pelo terminal:

mkdir MeuProjeto

Passo 2 – Entrar na Pasta

cd MeuProjeto

Agora o terminal estará dentro do projeto.

Passo 3 – Inicializar o Git

Execute:

git init

Resultado:

Initialized empty Git repository in C:/MeuProjeto/.git/

O Git cria automaticamente a pasta:

.git

Nesse momento, o diretório passa a ser um repositório Git.

O que Acontece ao Executar git init?

Ao executar git init, o Git:

  • Cria a pasta .git.
  • Inicializa o banco de dados do repositório.
  • Cria a branch principal (geralmente main).
  • Prepara o projeto para registrar alterações.

Antes:

MeuProjeto/

index.html

style.css

Depois:

MeuProjeto/

index.html

style.css

.git/

Os arquivos permanecem os mesmos; apenas o controle de versão é adicionado.

Verificando o Repositório

Após inicializar o Git:

git status

Saída:

On branch main

No commits yet

nothing to commit

Isso indica que:

  • O repositório foi criado.
  • Ainda não existem commits.
  • Ainda não há alterações registradas.

Criando o Primeiro Arquivo

Exemplo:

README.md

Ou pelo terminal:

echo "# Meu Projeto" > README.md

Agora execute:

git status

Saída:

Untracked files:

README.md

O arquivo existe, mas ainda não está sendo monitorado pelo Git.

Adicionando Arquivos ao Controle de Versão

Para que o Git passe a monitorar o arquivo:

git add README.md

Ou:

git add .

Resultado:

Changes to be committed:

new file: README.md

O arquivo agora está na Staging Area, pronto para ser incluído em um commit.

Criando o Primeiro Commit

Após adicionar os arquivos:

git commit -m "Primeiro commit"

Exemplo de saída:

[main (root-commit) 2a7c4b1]

1 file changed

Agora o projeto possui seu primeiro registro no histórico.

Verificando o Histórico

Execute:

git log

Exemplo:

commit 2a7c4b1

Author: João Silva

Date:

Primeiro commit

Também é possível utilizar a forma resumida:

git log --oneline

Resultado:

2a7c4b1 Primeiro commit

Estrutura de um Repositório Após o Primeiro Commit

MeuProjeto/
│
├── README.md
├── index.html
├── style.css
└── .git

Internamente, o Git já possui:

.git/

objects/

refs/

HEAD

config

logs/

hooks/

Esses arquivos são gerenciados automaticamente e não devem ser alterados manualmente.

Clonando um Repositório Existente

Nem sempre será necessário criar um repositório do zero.

Quando um projeto já existe em um servidor remoto, utiliza-se:

git clone URL_DO_REPOSITORIO

Exemplo:

git clone https://github.com/usuario/projeto.git

O Git irá:

  • Baixar todos os arquivos.
  • Baixar todo o histórico de commits.
  • Configurar o repositório remoto.
  • Criar automaticamente a pasta .git.

Conectando um Repositório Local ao GitHub

Após criar o repositório local, é possível vinculá-lo a um repositório remoto.

Adicionar o repositório remoto:

git remote add origin https://github.com/usuario/projeto.git

Verificar:

git remote -v

Exemplo:

origin

https://github.com/usuario/projeto.git

Agora o repositório local está conectado ao remoto.

Enviando o Primeiro Commit

Depois da conexão:

git push -u origin main

Explicação:

  • push → envia os commits.
  • origin → nome do repositório remoto.
  • main → branch principal.
  • u → define a branch remota padrão para futuros envios.

Após esse primeiro envio, os próximos podem ser feitos apenas com:

git push

Exemplo Prático Completo

# Criar pasta
mkdir MeuProjeto

# Entrar na pasta
cd MeuProjeto

# Inicializar o Git
git init

# Criar um arquivo README
echo "# Meu Projeto" > README.md

# Verificar o status
git status

# Adicionar o arquivo
git add README.md

# Criar o primeiro commit
git commit -m "Primeiro commit"

# Adicionar o repositório remoto
git remote add origin https://github.com/usuario/meuprojeto.git

# Enviar para o GitHub
git push -u origin main

Vantagens de Criar um Repositório Git

  • Controle completo do histórico de alterações.
  • Possibilidade de recuperar versões anteriores.
  • Trabalho colaborativo com múltiplos desenvolvedores.
  • Criação de branches para desenvolvimento paralelo.
  • Integração com plataformas de hospedagem de código.
  • Segurança dos dados por meio do histórico distribuído.

Boas Práticas

  • Inicialize o Git logo no início do projeto.
  • Crie um arquivo README.md para documentar o projeto.
  • Faça um primeiro commit logo após a estrutura inicial estar pronta.
  • Utilize uma mensagem clara para o primeiro commit, como "Primeiro commit" ou "Estrutura inicial do projeto".
  • Adicione um arquivo .gitignore para evitar que arquivos temporários, de compilação ou dados sensíveis sejam versionados.
  • Configure corretamente user.name e user.email antes de realizar commits.

Erros Comuns

  • Esquecer de executar git init antes de usar comandos do Git.
  • Tentar criar commits sem adicionar os arquivos com git add.
  • Excluir acidentalmente a pasta .git, perdendo todo o histórico de versões.
  • Não criar um arquivo .gitignore, fazendo com que arquivos desnecessários sejam enviados ao repositório.
  • Não conectar o repositório local ao remoto antes de utilizar git push.

Resumo

A criação de um repositório Git é o primeiro passo para utilizar o controle de versão em um projeto. Isso pode ser feito inicializando uma pasta com git init ou clonando um repositório existente com git clone. Após a criação, o fluxo básico consiste em adicionar arquivos (git add), registrar alterações (git commit) e, quando necessário, conectar o repositório a um servidor remoto para compartilhar o projeto (git remote e git push). Com um repositório Git corretamente configurado, torna-se possível acompanhar toda a evolução do projeto de forma organizada, segura e colaborativa.
