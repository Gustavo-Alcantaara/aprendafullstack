Branch

Branch no Git

Introdução

Uma Branch (ramo) é um dos recursos mais importantes do Git. Ela permite criar uma linha de desenvolvimento independente, onde é possível adicionar novas funcionalidades, corrigir erros ou realizar experimentos sem alterar a versão principal do projeto.

Graças às branches, vários desenvolvedores podem trabalhar simultaneamente no mesmo projeto, cada um em sua própria linha de desenvolvimento, sem interferir no trabalho dos demais.

As alterações feitas em uma branch só passam a fazer parte da versão principal quando são integradas por meio de um merge (ou outro método de integração, como rebase).

O que é uma Branch?

Imagine que o desenvolvimento de um projeto é como o tronco de uma árvore.

O tronco representa a versão principal do projeto (main).

Quando surge uma nova funcionalidade, em vez de modificar diretamente o tronco, cria-se um galho (branch) para desenvolver essa funcionalidade.

                 main
                   │
                   │
        ┌──────────┴──────────┐
        │                     │
 feature-login        feature-cadastro

Cada branch evolui de forma independente até que esteja pronta para ser incorporada à branch principal.

Por que usar Branches?

Sem branches, qualquer alteração seria feita diretamente na versão principal do projeto.

Isso pode causar problemas como:

  • Bugs afetando usuários.
  • Funcionalidades inacabadas.
  • Conflitos entre desenvolvedores.
  • Dificuldade para testar mudanças.

Com branches, o código principal permanece estável enquanto novas alterações são desenvolvidas separadamente.

Como uma Branch Funciona

Quando uma branch é criada, ela começa exatamente no estado do commit atual.

Exemplo:

Commit A
   │
Commit B
   │
Commit C
   │
  main

Criando uma branch chamada feature-login:

Commit A
   │
Commit B
   │
Commit C
   ├──────── feature-login
   │
  main

A partir desse ponto, cada branch pode seguir seu próprio caminho.

Após novos commits:

                Commit D
               /
Commit A
   │
Commit B
   │
Commit C
   │
   └──────── Commit E
            │
     feature-login

main

Agora existem duas linhas de desenvolvimento.

A Branch Principal

Atualmente, a branch principal normalmente chama-se:

main

Em versões antigas do Git era comum utilizar:

master

Hoje, a maioria dos projetos utiliza main como padrão.

A branch principal costuma conter a versão mais estável do projeto.

Criando uma Branch

Para criar uma nova branch:

git branch nome-da-branch

Exemplo:

git branch feature-login

Esse comando apenas cria a branch, mas você continua na branch atual.

Listando Branches

Para visualizar todas as branches locais:

git branch

Exemplo:

* main
  feature-login
  feature-pagamento

O asterisco (*) indica a branch atualmente em uso.

Mudando de Branch

Para alternar para outra branch:

git checkout nome-da-branch

Exemplo:

git checkout feature-login

Agora todos os commits serão feitos nessa branch.

Forma Moderna

Nas versões mais recentes do Git, recomenda-se utilizar:

git switch nome-da-branch

Exemplo:

git switch feature-login

O comando git switch foi criado especificamente para facilitar a troca de branches, tornando o uso mais claro do que git checkout, que possui diversas outras funções.

Criando e Mudando para a Branch ao Mesmo Tempo

Forma tradicional:

git checkout -b feature-login

Forma moderna:

git switch -c feature-login

Esses comandos:

  1. Criam a branch.
  1. Já mudam para ela.

Fazendo Commits em uma Branch

Depois de mudar para a branch:

feature-login

Os commits pertencem apenas a ela.

main

Commit A
Commit B
Commit C

feature-login

Commit A
Commit B
Commit C
Commit D
Commit E

A branch main permanece inalterada.

Mesclando Branches (Merge)

Quando o desenvolvimento termina, as alterações podem ser incorporadas à branch principal.

Primeiro:

git switch main

Depois:

git merge feature-login

Resultado:

Antes

main

A → B → C

feature-login

A → B → C → D → E


Depois

main

A → B → C → D → E

Agora a branch principal possui todas as alterações.

Excluindo uma Branch

Após integrar a branch ao projeto, ela pode ser removida.

git branch -d feature-login

Se a branch ainda não tiver sido integrada e você quiser removê-la mesmo assim:

git branch -D feature-login

O -D força a exclusão.

Renomeando uma Branch

Para renomear a branch atual:

git branch -m novo-nome

Exemplo:

git branch -m feature-autenticacao

Visualizando o Histórico das Branches

Um comando muito útil é:

git log --oneline --graph --all

Exemplo de saída:

* 95fd210 Corrige login
* 7ae31c2 Tela de login
|\
| * b87dd91 Cadastro
| * 84a912e Banco
|
* 24d2ff1 Projeto inicial

Esse formato mostra a divisão e a união das branches.

Branches Remotas

Além das branches locais, existem branches armazenadas no repositório remoto (como o GitHub).

Para visualizar todas:

git branch -a

Exemplo:

* main
  feature-login
  remotes/origin/main
  remotes/origin/develop

Enviando uma Branch para o Repositório Remoto

Depois de criar uma branch local:

git push origin feature-login

Agora essa branch também existirá no repositório remoto.

Baixando Branches Remotas

Atualizar as referências do servidor:

git fetch

Listar todas:

git branch -a

Criar uma branch local baseada em uma remota:

git switch feature-login

Se a branch existir apenas no remoto, o Git normalmente a configurará automaticamente como branch de acompanhamento (tracking).

Fluxo de Trabalho com Branches

Um fluxo simples pode ser representado assim:

main
 │
 ├── Criar branch
 │
 ├── Desenvolver funcionalidade
 │
 ├── Fazer commits
 │
 ├── Testar
 │
 ├── Merge
 │
 └── Excluir branch

Esse processo evita que código incompleto chegue à versão principal.

Estratégias de Uso de Branches

Branch por Funcionalidade

Cada nova funcionalidade possui sua própria branch.

main

├── feature-login

├── feature-cadastro

├── feature-relatorios

É uma das estratégias mais utilizadas.

Branch para Correção de Bugs

bugfix-login

bugfix-menu

bugfix-relatorio

Cada correção é isolada.

Branch para Experimentos

Pode ser criada para testar ideias sem comprometer o projeto principal.

experiment-api

experiment-layout

Se o resultado não for satisfatório, basta excluir a branch.

Convenções de Nomes

Embora o Git não imponha regras, algumas convenções facilitam a organização:

PrefixoFinalidadeExemplo
feature/Nova funcionalidadefeature/login
bugfix/Correção de errobugfix/menu
hotfix/Correção urgente em produçãohotfix/login
release/Preparação de uma versãorelease/1.0.0
docs/Alterações na documentaçãodocs/readme
refactor/Refatoração de códigorefactor/auth

Esses padrões tornam o histórico mais organizado e fácil de compreender.

Vantagens das Branches

  • Permitem desenvolver funcionalidades sem afetar a versão principal.
  • Facilitam o trabalho simultâneo de vários desenvolvedores.
  • Tornam os testes mais seguros.
  • Reduzem o risco de introduzir erros na branch principal.
  • Organizam melhor o fluxo de desenvolvimento.
  • Facilitam a revisão de código antes da integração.

Boas Práticas

  • Crie uma branch para cada funcionalidade ou correção.
  • Use nomes claros e descritivos para as branches.
  • Faça commits pequenos e frequentes.
  • Mantenha sua branch sincronizada com a main para reduzir conflitos.
  • Exclua branches que já foram integradas e não serão mais utilizadas.
  • Evite desenvolver diretamente na main em projetos colaborativos.

Erros Comuns

  • Trabalhar diretamente na branch main.
  • Criar uma única branch para várias funcionalidades diferentes.
  • Esquecer de atualizar a branch antes de fazer o merge.
  • Manter branches antigas sem uso, dificultando a organização do projeto.
  • Utilizar nomes genéricos como teste ou nova, que não indicam o objetivo da branch.

Resumo

As branches são um dos principais recursos do Git e permitem criar linhas independentes de desenvolvimento para implementar funcionalidades, corrigir erros ou realizar experimentos sem comprometer a versão principal do projeto. Elas tornam o desenvolvimento colaborativo mais seguro, organizado e eficiente. Com comandos como git branch, git switch, git checkout e git merge, é possível criar, alternar, integrar e remover branches de forma simples, mantendo um fluxo de trabalho profissional e escalável.
