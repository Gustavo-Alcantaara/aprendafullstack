Comandos Básicos do Git

Introdução

Os comandos básicos do Git são responsáveis pelas operações mais comuns realizadas durante o desenvolvimento de um projeto, como:

  • Criar um repositório.
  • Verificar o estado dos arquivos.
  • Adicionar arquivos ao controle de versão.
  • Criar commits.
  • Visualizar o histórico.
  • Trabalhar com repositórios remotos.
  • Gerenciar branches.

Esses comandos fazem parte do fluxo de trabalho diário de qualquer desenvolvedor que utiliza Git.

Fluxo Básico de Trabalho

Antes de conhecer os comandos, é importante entender o fluxo padrão do Git:

Criar ou editar arquivos
          │
          ▼

          │

          │
          ▼
      git add
          │
          ▼
   Staging Area
          │
    git commit
          │
          ▼
 Repositório Local
          │
     git push
          │
          ▼
 Repositório Remoto

1. git --version

Mostra a versão instalada do Git.

Sintaxe

git --version

Exemplo

git --version

Saída:

git version 2.51.0

Quando usar?

  • Verificar se o Git está instalado.
  • Confirmar a versão utilizada.

2. git config

Configura informações do Git.

Configurar nome

git config --global user.name "João Silva"

Configurar e-mail

git config --global user.email "joao@email.com"

Mostrar configurações

git config --list

Opções importantes

OpçãoFunção
--globalConfiguração para todos os projetos
--localConfiguração apenas do repositório atual
--listLista todas as configurações

3. git init

Inicializa um repositório Git.

Sintaxe

git init

Exemplo

mkdir MeuProjeto

cd MeuProjeto

git init

Resultado:

Initialized empty Git repository...

A pasta .git será criada.

4. git clone

Copia um repositório remoto para o computador.

Sintaxe

git clone URL

Exemplo

git clone https://github.com/usuario/projeto.git

Resultado:

Projeto/

index.html

style.css

script.js

.git

Todo o histórico também é copiado.

5. git status

Um dos comandos mais utilizados.

Mostra:

  • arquivos modificados;
  • arquivos novos;
  • arquivos preparados para commit;
  • branch atual;
  • informações sobre sincronização com o repositório remoto.

Sintaxe

git status

Exemplo

On branch main

Changes not staged for commit:

modified: index.html

Untracked files:

script.js

Estados exibidos

  • Modified
  • Untracked
  • Staged
  • Nothing to commit

6. git add

Adiciona arquivos à Staging Area, preparando-os para o próximo commit.

Adicionar um arquivo

git add index.html

Adicionar vários arquivos

git add index.html style.css

Adicionar todos os arquivos

git add .

O ponto (.) significa "todos os arquivos da pasta atual e subpastas".

7. git commit

Salva permanentemente as alterações adicionadas à Staging Area.

Sintaxe

git commit -m "Mensagem"

Exemplo

git commit -m "Adiciona tela de login"

O que acontece?

O Git cria:

  • um novo commit;
  • um hash único;
  • registra data e hora;
  • registra o autor;
  • salva uma fotografia (snapshot) do projeto.

8. git log

Mostra o histórico de commits.

Sintaxe

git log

Exemplo:

commit a8d93ef

Author: João

Date:

Adiciona login

Forma resumida

git log --oneline

Resultado:

8d3ef21 Adiciona Login

24d3ab4 Corrige CSS

75ac991 Projeto inicial

Histórico gráfico

git log --oneline --graph --all

Exemplo:

* Login

* Cadastro

|\

| * API

|

* Projeto Inicial

Muito útil para visualizar branches.

9. git diff

Mostra exatamente o que foi alterado.

Sintaxe

git diff

Exemplo:

- echo "Olá";

+ echo "Bem-vindo";

Comparando arquivos preparados

git diff --staged

Mostra apenas o que está na Staging Area.

10. git branch

Gerencia branches.

Listar

git branch

Resultado:

* main

feature-login

feature-api

Criar

git branch feature-login

Excluir

git branch -d feature-login

Excluir forçando

git branch -D feature-login

11. git switch

Troca de branch.

Sintaxe

git switch nome-da-branch

Exemplo:

git switch feature-login

Criar e mudar

git switch -c feature-login

12. git checkout

Ainda é bastante utilizado.

Pode:

  • trocar de branch;
  • restaurar arquivos;
  • acessar commits antigos.

Trocar de branch

git checkout feature-login

Criar branch

git checkout -b feature-login

Embora ainda funcione, para trocar e criar branches recomenda-se o uso de git switch.

13. git merge

Une duas branches.

Exemplo

git switch main

git merge feature-login

Resultado:

main

↓

Merge

↓

feature-login incorporada

14. git remote

Gerencia repositórios remotos.

Listar

git remote -v

Exemplo:

origin

https://github.com/usuario/projeto.git

Adicionar

git remote add origin https://github.com/usuario/projeto.git

15. git push

Envia commits locais para o repositório remoto.

Sintaxe

git push origin main

Fluxo:

Computador

↓

GitHub

16. git pull

Baixa alterações do servidor e já as integra ao repositório local.

git pull

Fluxo:

GitHub

↓

Computador

17. git fetch

Baixa informações do servidor sem alterar os arquivos locais.

git fetch

É útil para verificar mudanças antes de integrá-las.

18. git restore

Restaura alterações em arquivos.

Descartar alterações

git restore index.html

O arquivo volta ao estado do último commit.

19. git rm

Remove arquivos do projeto e do controle de versão.

git rm arquivo.txt

Depois será necessário criar um commit para confirmar a remoção.

20. git mv

Move ou renomeia arquivos mantendo o histórico.

git mv antigo.txt novo.txt

21. git tag

Cria marcações para versões importantes do projeto.

Criar

git tag v1.0

Muito utilizada para identificar versões lançadas.

22. git show

Mostra detalhes de um commit.

git show

Ou:

git show a8d93ef

Exibe:

  • autor;
  • data;
  • mensagem;
  • alterações realizadas.

23. git stash

Guarda temporariamente alterações ainda não concluídas.

Salvar

git stash

Recuperar

git stash pop

É útil quando você precisa trocar de branch sem fazer um commit incompleto.

Fluxo Completo de Exemplo

Imagine que você criou um novo projeto:

# Criar pasta do projeto
mkdir MeuProjeto

# Entrar na pasta
cd MeuProjeto

# Inicializar o Git
git init

# Criar um arquivo
echo "# Meu Projeto" > README.md

# Verificar o status
git status

# Adicionar o arquivo à Staging Area
git add README.md

# Criar o primeiro commit
git commit -m "Primeiro commit"

# Criar uma nova branch
git switch -c feature-login

# Fazer alterações e salvar
git add .
git commit -m "Adiciona tela de login"

# Voltar para a branch principal
git switch main

# Integrar as alterações
git merge feature-login

# Enviar para o repositório remoto
git push origin main

Boas Práticas

  • Execute git status com frequência para acompanhar o estado do repositório.
  • Faça commits pequenos, com mensagens claras e objetivas.
  • Utilize git switch para gerenciar branches nas versões mais recentes do Git.
  • Revise as alterações com git diff antes de criar um commit.
  • Faça git pull antes de iniciar o trabalho em um repositório compartilhado para evitar conflitos.
  • Use git stash quando precisar interromper temporariamente uma tarefa.

Erros Comuns

  • Esquecer de executar git add antes do git commit.
  • Criar commits com mensagens genéricas, como "teste" ou "alterações".
  • Trabalhar diretamente na branch main em projetos colaborativos.
  • Usar git push --force sem compreender suas consequências, podendo sobrescrever o trabalho de outros desenvolvedores.
  • Não verificar o estado do repositório com git status antes de executar comandos importantes.

Resumo

Os comandos básicos do Git formam a base do controle de versão e são utilizados diariamente por desenvolvedores. Comandos como git init, git status, git add, git commit, git log, git branch, git switch, git merge, git push e git pull permitem criar repositórios, registrar alterações, gerenciar branches e sincronizar projetos com repositórios remotos. Dominar esses comandos é essencial para utilizar o Git de forma eficiente e segura em projetos individuais ou colaborativos.
