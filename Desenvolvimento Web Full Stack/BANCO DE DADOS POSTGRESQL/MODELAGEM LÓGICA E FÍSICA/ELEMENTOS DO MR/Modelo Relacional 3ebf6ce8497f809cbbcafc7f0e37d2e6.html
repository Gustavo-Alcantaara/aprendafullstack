Modelo Relacional

Modelo Relacional e Componentes Básicos de uma Tabela

O modelo relacional é um dos modelos mais utilizados para organizar dados em bancos de dados. Ele representa as informações por meio de tabelas, formadas por linhas e colunas, e utiliza relacionamentos para conectar diferentes tabelas.

SGBDs como MySQL, PostgreSQL, SQL Server e Oracle utilizam esse modelo.

1. O que é o modelo relacional?

No modelo relacional, os dados são organizados em relações, que na prática são representadas por tabelas.

Por exemplo, podemos ter uma tabela CLIENTE:

id_clientenomeemailcidade
1Joãojoao@email.comFortaleza
2Mariamaria@email.comNatal
3Pedropedro@email.comRecife

Essa tabela representa informações sobre clientes.

O modelo relacional permite:

  • organizar os dados;
  • evitar duplicações desnecessárias;
  • estabelecer relacionamentos entre informações;
  • consultar os dados através de SQL;
  • garantir regras de integridade.

2. Componentes básicos de uma tabela

Uma tabela possui principalmente:

Tabela
│
├── Colunas
│   ├── Nome
│   ├── Tipo de dado
│   └── Restrições
│
└── Linhas
    └── Registros

Vamos analisar cada componente.

3. Tabela

A tabela representa um conjunto de dados sobre determinado assunto ou entidade.

Exemplos:

CLIENTE
PRODUTO
PEDIDO
FUNCIONARIO
CURSO
ALUNO

Por exemplo:

CLIENTE
---------------------------------
id_cliente | nome | email

Uma tabela normalmente representa uma entidade ou conceito do sistema.

4. Colunas

As colunas representam os atributos dos dados armazenados.

Por exemplo:

CLIENTE
--------------------------------
id_cliente
nome
email
data_nascimento

Cada coluna possui um significado específico.

Podemos relacionar isso com o que vimos anteriormente:

Entidade: CLIENTE

Atributos:
- id_cliente
- nome
- email
- data_nascimento

Quando passamos para o modelo relacional, esses atributos normalmente se tornam colunas.

5. Tipo de dado

Cada coluna possui um tipo de dado, que determina que tipo de informação ela pode armazenar.

Por exemplo:

CREATE TABLE cliente (
    id_cliente INT,
    nome VARCHAR(100),
    email VARCHAR(150),
    data_nascimento DATE
);

Aqui:

ColunaTipo
id_clienteINT
nomeVARCHAR
emailVARCHAR
data_nascimentoDATE

Alguns tipos comuns:

INT       → números inteiros
DECIMAL   → números decimais
VARCHAR   → textos
DATE      → datas
DATETIME  → data e hora
BOOLEAN   → verdadeiro/falso

6. Linhas ou registros

As linhas representam os registros armazenados na tabela.

Por exemplo:

id_clientenomeemail
1Joãojoao@email.com
2Mariamaria@email.com
3Pedropedro@email.com

Temos 3 registros.

Cada registro representa uma ocorrência da entidade CLIENTE.

CLIENTE
   ↓
João
Maria
Pedro

Uma forma simples de lembrar:

Coluna = característica

Linha = ocorrência/registro

7. Célula

A interseção entre uma linha e uma coluna forma uma célula.

Por exemplo:

id_clientenomecidade
1JoãoFortaleza

A célula:

João

é o valor armazenado na coluna nome do registro cujo id_cliente é 1.

8. Chave primária (Primary Key)

A chave primária (PK) identifica unicamente cada registro da tabela.

Exemplo:

id_clientenome
1João
2Maria
3Pedro

Nesse caso:

id_cliente → PRIMARY KEY

Não podemos ter:

id_cliente
1
1
2

porque dois clientes diferentes não poderiam possuir o mesmo identificador.

Em SQL:

CREATE TABLE cliente (
    id_cliente INT PRIMARY KEY,
    nome VARCHAR(100)
);

A chave primária normalmente:

  • identifica cada registro;
  • não pode ser duplicada;
  • não deve ser NULL.

9. Chave estrangeira (Foreign Key)

A chave estrangeira (FK) é utilizada para criar um relacionamento entre tabelas.

Por exemplo:

CLIENTE

id_clientenome
1João
2Maria

PEDIDO

id_pedidoid_clientevalor
1011250
1021100
1032300

Aqui:

CLIENTE
id_cliente (PK)
      ↑
      │
      │ FK
      │
PEDIDO
id_cliente (FK)

O id_cliente da tabela PEDIDO indica qual cliente realizou aquele pedido.

Em SQL:

CREATE TABLE pedido (
    id_pedido INT PRIMARY KEY,
    id_cliente INT,
    valor DECIMAL(10,2),

    FOREIGN KEY (id_cliente)
        REFERENCES cliente(id_cliente)
);

10. Restrições (Constraints)

As tabelas também podem possuir restrições, que ajudam a garantir a integridade dos dados.

Algumas das principais são:

PRIMARY KEY

Identifica unicamente o registro.

id_cliente INT PRIMARY KEY

FOREIGN KEY

Estabelece relacionamento entre tabelas.

FOREIGN KEY (id_cliente)
REFERENCES cliente(id_cliente)

NOT NULL

Determina que o campo deve possuir um valor.

nome VARCHAR(100) NOT NULL

UNIQUE

Impede valores duplicados.

email VARCHAR(150) UNIQUE

DEFAULT

Define um valor padrão.

status VARCHAR(20) DEFAULT 'ativo'

11. Exemplo completo

Podemos juntar tudo:

CREATE TABLE cliente (
    id_cliente INT PRIMARY KEY,
    nome VARCHAR(100) NOT NULL,
    email VARCHAR(150) UNIQUE,
    cidade VARCHAR(100),
    status VARCHAR(20) DEFAULT 'ativo'
);

Essa tabela possui:

CLIENTE
│
├── id_cliente
│   └── PRIMARY KEY
│
├── nome
│   └── NOT NULL
│
├── email
│   └── UNIQUE
│
├── cidade
│
└── status
    └── DEFAULT 'ativo'

Resumindo

O modelo relacional organiza os dados principalmente através de tabelas.

Uma tabela possui:

                    TABELA
                       │
        ┌──────────────┴──────────────┐
        ↓                             ↓
     COLUNAS                        LINHAS
   (atributos)                   (registros)
        │                             │
        ↓                             ↓
  nome, email, etc.             João, Maria...

E seus componentes mais importantes são:

  • Tabela → conjunto de dados sobre um assunto;
  • Coluna → atributo/característica;
  • Linha → registro/ocorrência;
  • Célula → valor de uma coluna em determinado registro;
  • Tipo de dado → define o tipo de valor armazenado;
  • Chave primária (PK) → identifica o registro;
  • Chave estrangeira (FK) → relaciona tabelas;
  • Constraints → regras que garantem a integridade dos dados.
