Esquema Diagramático

Esquema Diagramático de Banco de Dados Relacional

O esquema diagramático de um banco de dados relacional é uma representação visual da estrutura do banco, mostrando principalmente as tabelas, suas colunas, chaves e relacionamentos.

Ele ajuda a entender como os dados estão organizados antes de implementar ou analisar o banco.

1. O que é um esquema de banco de dados?

O esquema descreve a estrutura do banco de dados.

Por exemplo, podemos ter:

CLIENTE
- id_cliente
- nome
- email

PEDIDO
- id_pedido
- id_cliente
- data_pedido
- valor

O esquema mostra:

  • quais tabelas existem;
  • quais colunas cada tabela possui;
  • quais são as chaves primárias;
  • quais são as chaves estrangeiras;
  • como as tabelas estão relacionadas.

2. Representação diagramática

Podemos representar o exemplo anterior visualmente:

┌─────────────────────────┐
│        CLIENTE          │
├─────────────────────────┤
│ PK id_cliente           │
│    nome                 │
│    email                │
└────────────┬────────────┘
             │
             │ 1:N
             │
             ▼
┌─────────────────────────┐
│         PEDIDO          │
├─────────────────────────┤
│ PK id_pedido            │
│ FK id_cliente           │
│    data_pedido          │
│    valor                │
└─────────────────────────┘

Podemos interpretar assim:

Um cliente pode realizar vários pedidos, e cada pedido pertence a um cliente.

3. Componentes do esquema diagramático

Os principais componentes são:

Tabela

Representa uma relação do banco.

┌───────────────┐
│    CLIENTE    │
└───────────────┘

Coluna

Representa um atributo da tabela.

id_cliente
nome
email

PK

Indica a chave primária.

PK id_cliente

FK

Indica uma chave estrangeira.

FK id_cliente

Relacionamento

Mostra a ligação entre tabelas.

CLIENTE 1 ───── N PEDIDO

4. Exemplo mais completo

Imagine um sistema de vendas.

Temos:

CLIENTE
- id_cliente
- nome
- email

PEDIDO
- id_pedido
- id_cliente
- data_pedido

PRODUTO
- id_produto
- nome
- preco

ITEM_PEDIDO
- id_pedido
- id_produto
- quantidade
- preco_unitario

O esquema poderia ser:

┌──────────────────┐
│     CLIENTE      │
├──────────────────┤
│ PK id_cliente    │
│    nome          │
│    email         │
└────────┬─────────┘
         │
         │ 1:N
         ▼
┌──────────────────┐
│      PEDIDO      │
├──────────────────┤
│ PK id_pedido     │
│ FK id_cliente    │
│    data_pedido   │
└────────┬─────────┘
         │
         │ 1:N
         ▼
┌──────────────────────┐
│     ITEM_PEDIDO      │
├──────────────────────┤
│ PK/FK id_pedido      │
│ PK/FK id_produto     │
│     quantidade       │
│     preco_unitario   │
└──────────┬───────────┘
           │
           │ N:1
           ▼
┌──────────────────┐
│     PRODUTO      │
├──────────────────┤
│ PK id_produto    │
│    nome          │
│    preco         │
└──────────────────┘

Esse esquema permite visualizar toda a estrutura do sistema.

5. Cardinalidade

O esquema também pode mostrar a cardinalidade dos relacionamentos.

Os casos mais comuns são:

1:1 — Um para um

PESSOA 1 ───── 1 PASSAPORTE

Uma pessoa possui um passaporte e um passaporte pertence a uma pessoa.

1:N — Um para muitos

CLIENTE 1 ───── N PEDIDO

Um cliente pode possuir vários pedidos.

N:N — Muitos para muitos

ALUNO N ───── N CURSO

Um aluno pode fazer vários cursos e um curso pode ter vários alunos.

No banco relacional, normalmente criamos uma tabela intermediária:

ALUNO 1 ─── N MATRICULA N ─── 1 CURSO

6. Identificação das chaves

Um dos objetivos do esquema diagramático é deixar claro como as tabelas se relacionam.

Por exemplo:

┌─────────────────────┐
│       CLIENTE       │
├─────────────────────┤
│ PK id_cliente       │
│    nome             │
└──────────┬──────────┘
           │
           │
           │
┌──────────▼──────────┐
│        PEDIDO       │
├─────────────────────┤
│ PK id_pedido        │
│ FK id_cliente       │
│    valor            │
└─────────────────────┘

Observe:

CLIENTE.id_cliente
       ↑
       │
       │ referência
       │
PEDIDO.id_cliente

A PK da primeira tabela é referenciada pela FK da segunda.

7. Esquema diagramático × DER

É importante não confundir os dois.

DER

O Diagrama Entidade-Relacionamento representa principalmente o modelo conceitual.

Exemplo:

CLIENTE ───── FAZ ───── PEDIDO

Ele está preocupado com:

  • entidades;
  • atributos;
  • relacionamentos;
  • cardinalidades;
  • regras de negócio.

Esquema relacional

Está mais próximo da implementação do banco:

CLIENTE
PK id_cliente
nome
email

PEDIDO
PK id_pedido
FK id_cliente
data
valor

Ou seja:

DER → representa o modelo conceitual.

Esquema relacional → representa a estrutura das tabelas e seus relacionamentos.

8. Esquema diagramático e implementação

Depois de definir o esquema, podemos transformá-lo em SQL.

Por exemplo:

CLIENTE
    │
    │ 1:N
    ▼
PEDIDO

Pode virar:

CREATE TABLE cliente (
    id_cliente INT PRIMARY KEY,
    nome VARCHAR(100),
    email VARCHAR(150)
);

CREATE TABLE pedido (
    id_pedido INT PRIMARY KEY,
    id_cliente INT NOT NULL,
    data_pedido DATE,
    valor DECIMAL(10,2),

    FOREIGN KEY (id_cliente)
        REFERENCES cliente(id_cliente)
);

Portanto, o esquema funciona como uma visão estrutural do banco antes ou durante sua implementação.

9. Por que utilizar um esquema diagramático?

Ele facilita:

Visualização

Permite enxergar a estrutura do banco de forma rápida.

Planejamento

Ajuda a projetar o banco antes de criar as tabelas.

Identificação de problemas

Pode revelar:

  • relacionamentos incorretos;
  • tabelas desnecessárias;
  • ausência de chaves;
  • duplicação de informações;
  • cardinalidades inadequadas.

Comunicação

Facilita explicar a estrutura do banco para outros desenvolvedores, analistas e administradores.

Manutenção

Quando o sistema cresce, o diagrama ajuda a entender como as tabelas estão conectadas.

10. Exemplo para memorizar

Um esquema simples pode ser visualizado assim:

                 BANCO DE DADOS
                       │
          ┌────────────┼────────────┐
          ▼            ▼            ▼
       CLIENTE       PEDIDO      PRODUTO
          │            │            │
          │            │            │
        PK id        PK id        PK id
          │            │            │
          └──────┐     │     ┌──────┘
                 ▼     ▼     ▼
                  RELACIONAMENTOS

O objetivo é mostrar quem se relaciona com quem e através de quais chaves.

Resumo

O esquema diagramático de um banco de dados relacional é uma representação visual da estrutura do banco.

Ele apresenta principalmente:

  • Tabelas → entidades/relações armazenadas;
  • Colunas → atributos;
  • PK → identificadores únicos;
  • FK → referências entre tabelas;
  • Relacionamentos → conexões entre tabelas;
  • Cardinalidade → quantidade de registros relacionados.

A ideia principal é:

O esquema diagramático funciona como um mapa do banco de dados, permitindo visualizar suas tabelas, campos, chaves e relacionamentos.
