Atributo Opcional

Um atributo opcional é um atributo que pode não possuir um valor para determinada ocorrência de uma entidade.

Ou seja, o sistema não exige que esse atributo seja preenchido.

No banco de dados relacional, isso normalmente significa que a coluna pode receber o valor NULL.

1. Exemplo simples

Imagine a entidade CLIENTE:

CLIENTE
├── id_cliente
├── nome
├── email
└── telefone

Podemos definir que:

  • id_cliente → obrigatório
  • nome → obrigatório
  • email → obrigatório
  • telefone → opcional

Isso significa que um cliente pode ser cadastrado sem informar telefone.

CLIENTE
id | nome   | email          | telefone
---|--------|----------------|----------
1  | João   | joao@email.com | 8899999-1111
2  | Maria  | maria@email.com| NULL

No caso de Maria, o telefone não foi informado.

2. Atributo obrigatório × opcional

A diferença principal é:

Obrigatório

Precisa possuir um valor.

nome
email

No SQL, normalmente usamos NOT NULL:

nome VARCHAR(100) NOT NULL,
email VARCHAR(150) NOT NULL

Opcional

Pode não possuir um valor.

telefone

Nesse caso, não colocamos NOT NULL:

telefone VARCHAR(20)

Assim:

INSERT INTO cliente (id_cliente, nome, email)
VALUES (1, 'Maria', 'maria@email.com');

O telefone ficará como NULL.

3. O que significa NULL?

NULL significa que não existe um valor armazenado naquele campo.

É importante não confundir NULL com:

''

ou:

'Não informado'

Por exemplo:

telefone = NULL

significa que não existe valor registrado.

Enquanto:

telefone = ''

é uma string vazia.

E:

telefone = 'Não informado'

é um texto armazenado como valor.

Em geral, quando o atributo é realmente opcional e não há informação disponível, NULL é a representação apropriada.

4. Exemplo prático

Imagine um sistema de funcionários:

FUNCIONÁRIO
├── id_funcionario
├── nome
├── CPF
├── telefone
├── email
└── ramal

Podemos ter:

AtributoObrigatório?
id_funcionarioSim
nomeSim
CPFSim
telefoneNão
emailSim
ramalNão

O funcionário pode não possuir um ramal, por exemplo.

Então:

id | nome  | email          | ramal
---|-------|----------------|------
1  | João  | joao@email.com | 203
2  | Maria | maria@email.com| NULL

5. Como representar no modelo?

A forma de representar um atributo opcional depende da notação utilizada no DER.

O mais importante conceitualmente é indicar que a participação daquele atributo não é obrigatória.

No modelo lógico, isso fica mais evidente através da restrição da coluna:

CREATE TABLE funcionario (
    id_funcionario INT PRIMARY KEY,
    nome VARCHAR(100) NOT NULL,
    cpf VARCHAR(14) NOT NULL,
    email VARCHAR(150) NOT NULL,
    telefone VARCHAR(20),
    ramal VARCHAR(10)
);

Observe:

NOT NULL → obrigatório
sem NOT NULL → pode ser NULL

6. Quando um atributo deve ser opcional?

Um atributo deve ser opcional quando faz sentido para a regra de negócio que determinada ocorrência não tenha aquela informação.

Exemplo:

CLIENTE
├── nome
├── email
├── telefone
└── data_nascimento

Se o sistema permite cadastrar um cliente sem saber sua data de nascimento:

data_nascimento → opcional

Por outro lado, se a regra do sistema determina que todo cliente precisa informar a data:

data_nascimento → obrigatório

Portanto, ser opcional ou obrigatório não é uma decisão puramente técnica. É uma decisão baseada nos requisitos e nas regras de negócio.

7. Cuidado com o uso excessivo de NULL

Embora atributos opcionais sejam perfeitamente normais, muitos campos opcionais podem indicar um problema de modelagem.

Imagine:

PESSOA
├── nome
├── CPF
├── CNPJ
├── matrícula_aluno
├── matrícula_funcionário
├── CRM
├── registro_profissional
└── ...

Muitos desses campos poderiam ficar NULL dependendo do tipo de pessoa.

Nesse caso, talvez seja melhor utilizar especialização/generalização, por exemplo:

                 PESSOA
                /      \
           ALUNO      FUNCIONÁRIO

Assim, cada tipo possui seus atributos específicos.

Resumo

Atributo opcional é aquele que não precisa obrigatoriamente possuir um valor.

Exemplo:

CLIENTE
├── nome       → obrigatório
├── email      → obrigatório
├── telefone   → opcional
└── endereço   → opcional

No banco relacional:

nome VARCHAR(100) NOT NULL,  -- obrigatório
telefone VARCHAR(20)         -- opcional

A ideia principal é:

Atributo obrigatório → precisa ter um valor.

Atributo opcional → pode não ter um valor (NULL).

E a definição de quais atributos são opcionais deve vir principalmente das regras de negócio do sistema.
