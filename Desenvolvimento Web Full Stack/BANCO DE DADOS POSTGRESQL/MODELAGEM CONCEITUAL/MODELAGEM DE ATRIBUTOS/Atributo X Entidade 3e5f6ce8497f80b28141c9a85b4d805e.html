Atributo X Entidade

Atributo × Entidade

No Modelo Entidade-Relacionamento (MER), é fundamental saber diferenciar entidade de atributo, porque os dois representam coisas diferentes dentro da modelagem do banco de dados.

A forma mais simples de entender é:

Entidade é aquilo sobre o qual queremos armazenar informações.

Atributo é uma característica ou informação sobre essa entidade.

1. Entidade

Uma entidade representa um objeto, pessoa, lugar, conceito ou elemento do sistema que possui informações que precisam ser armazenadas.

Por exemplo, em um sistema de uma loja:

CLIENTE
PRODUTO
PEDIDO
FUNCIONÁRIO

São entidades porque o sistema precisa guardar informações sobre cada uma delas.

Por exemplo:

CLIENTE

representa o conceito de cliente no sistema.

2. Atributo

Um atributo representa uma característica de uma entidade.

Por exemplo:

CLIENTE
├── id_cliente
├── nome
├── CPF
├── email
└── telefone

Aqui:

  • CLIENTE → entidade
  • id_cliente → atributo
  • nome → atributo
  • CPF → atributo
  • email → atributo
  • telefone → atributo

Ou seja, os atributos descrevem a entidade.

3. Exemplo prático

Imagine que temos:

CLIENTE

E queremos armazenar:

  • nome;
  • e-mail;
  • telefone.

A modelagem seria:

        CLIENTE
       /   |   \
      /    |    \
   nome  email  telefone

CLIENTE é a entidade.

nome, email e telefone são atributos.

4. Entidade representa vários registros

Uma entidade normalmente representa um tipo de objeto, enquanto seus atributos descrevem cada ocorrência desse objeto.

Por exemplo:

CLIENTE

pode ter várias ocorrências:

1 | João   | joao@email.com
2 | Maria  | maria@email.com
3 | Carlos | carlos@email.com

A entidade é CLIENTE.

Cada linha representa uma ocorrência/instância da entidade.

Os atributos são:

id_cliente
nome
email

E os valores são:

1
João
joao@email.com

Portanto:

ConceitoExemplo
EntidadeCLIENTE
Atributonome
ValorJoão
OcorrênciaCliente de ID 1

5. Como saber se algo é uma entidade ou atributo?

Uma boa pergunta é:

"Preciso armazenar várias informações sobre isso?"

Se sim, provavelmente estamos diante de uma entidade.

Por exemplo:

CLIENTE

Precisamos armazenar:

nome
CPF
email
telefone
endereço

Então CLIENTE é uma entidade.

Já nome normalmente não precisa de vários atributos próprios:

nome

Ele é uma característica do cliente, portanto é um atributo.

6. Um exemplo que pode causar dúvida

Considere:

CLIENTE
└── endereço

À primeira vista, endereço parece apenas um atributo.

Porém, dependendo do sistema, podemos precisar armazenar:

rua
número
bairro
cidade
estado
CEP

Nesse caso, endereço pode ser tratado como um atributo composto:

CLIENTE
   │
   └── ENDEREÇO
       ├── rua
       ├── número
       ├── bairro
       ├── cidade
       ├── estado
       └── CEP

Em outros sistemas, endereço pode justificar uma entidade própria, principalmente quando:

  • um cliente pode ter vários endereços;
  • endereços possuem informações e relacionamentos próprios;
  • outros objetos do sistema também utilizam endereços.

Então a decisão depende das regras de negócio.

7. Outro exemplo: Produto

Imagine uma loja:

PRODUTO
├── id_produto
├── nome
├── descrição
├── preço
└── estoque

Temos:

Entidade:

PRODUTO

Atributos:

id_produto
nome
descrição
preço
estoque

Um registro poderia ser:

id_produto: 10
nome: Teclado Mecânico
preço: 250.00
estoque: 15

Aqui:

  • PRODUTO → entidade
  • nome → atributo
  • preço → atributo
  • 250.00 → valor do atributo
  • Teclado Mecânico → valor do atributo

8. Entidade × Atributo × Relacionamento

É importante não confundir os três conceitos:

              ┌──────────┐
              │ CLIENTE  │
              └────┬─────┘
                   │
              possui atributos
                   │
        ┌──────────┼──────────┐
        ▼          ▼          ▼
       nome       CPF       email


CLIENTE ───── realiza ───── PEDIDO
 ↑                              ↑
entidade                    entidade
             ↑
        relacionamento

Entidade

Representa o objeto ou conceito:

CLIENTE
PEDIDO
PRODUTO

Atributo

Descreve a entidade:

nome
CPF
preço
data

Relacionamento

Representa uma associação:

CLIENTE realiza PEDIDO
PEDIDO contém PRODUTO

Resumindo

Pense da seguinte maneira:

ENTIDADE
    ↓
"Sobre o que estou armazenando informações?"
    ↓
CLIENTE
    ↓
"Quais informações preciso armazenar sobre ele?"
    ↓
nome
CPF
email
telefone

Portanto:

Entidade = aquilo que queremos representar no sistema.

Atributo = informação que descreve essa entidade.

E no modelo relacional isso normalmente se traduz em:

ENTIDADE  →  TABELA
ATRIBUTO  →  COLUNA
OCORRÊNCIA → LINHA/REGISTRO
VALOR     → VALOR DA CÉLULA

Essa correspondência é uma das bases para entender como um DER é transformado em tabelas de um banco de dados relacional.
