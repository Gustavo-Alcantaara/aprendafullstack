Atributo Multivalorado

Atributo Multivalorado

Um atributo multivalorado é um atributo que pode possuir mais de um valor para uma mesma ocorrência de uma entidade.

Ou seja, enquanto um atributo comum normalmente possui um único valor por registro, um atributo multivalorado pode possuir vários valores.

1. Exemplo simples

Imagine a entidade CLIENTE:

CLIENTE
├── id_cliente
├── nome
└── telefone

Se cada cliente puder ter vários telefones, telefone pode ser considerado um atributo multivalorado.

Por exemplo:

Cliente: João

Telefones:
- 8899999-1111
- 8898888-2222
- 8833333-4444

Representando conceitualmente:

CLIENTE
   │
   ├── id_cliente
   ├── nome
   └── telefones
          ├── 8899999-1111
          ├── 8898888-2222
          └── 8833333-4444

2. Atributo comum × multivalorado

Atributo comum

Possui um único valor por ocorrência:

CLIENTE
nome = "João"

Um cliente possui um nome.

Atributo multivalorado

Pode possuir vários valores:

CLIENTE
telefones = {
    "8899999-1111",
    "8898888-2222"
}

Um cliente pode possuir vários telefones.

TipoExemplo
Atributo comumnome = João
Multivaloradotelefones = {1111, 2222}

3. Outros exemplos

Existem várias situações em que um atributo pode ser multivalorado.

E-mails

Uma pessoa pode possuir mais de um e-mail:

email:
- joao@gmail.com
- joao@empresa.com

Telefones

telefone:
- 8899999-1111
- 8898888-2222

Idiomas

Um funcionário pode falar vários idiomas:

idiomas:
- Português
- Inglês
- Espanhol

Especialidades

Um médico pode possuir várias especialidades:

especialidades:
- Cardiologia
- Clínica Geral

4. Como representar no banco relacional?

Aqui existe um ponto importante:

Bancos relacionais normalmente não devem armazenar vários valores separados dentro de uma única coluna.

Por exemplo, evitar:

id_cliente | nome  | telefones
-----------|-------|------------------------------
1          | João  | 8899999-1111, 8898888-2222

Isso dificulta consultas, alterações e validações.

Em vez disso, normalmente criamos uma tabela separada.

CLIENTE

CLIENTE
id_cliente | nome
-----------|------
1          | João
2          | Maria

TELEFONE

TELEFONE
id_telefone | id_cliente | telefone
------------|------------|--------------
1           | 1          | 8899999-1111
2           | 1          | 8898888-2222
3           | 2          | 8897777-3333

Agora cada telefone possui seu próprio registro.

5. Relação entre as tabelas

A estrutura fica:

CLIENTE 1 ───────── N TELEFONE

Ou seja:

Um cliente pode possuir vários telefones.

No banco:

CREATE TABLE cliente (
    id_cliente INT PRIMARY KEY,
    nome VARCHAR(100) NOT NULL
);
CREATE TABLE telefone (
    id_telefone INT PRIMARY KEY,
    id_cliente INT NOT NULL,
    numero VARCHAR(20) NOT NULL,

    FOREIGN KEY (id_cliente)
        REFERENCES cliente(id_cliente)
);

Assim, podemos cadastrar quantos telefones forem necessários para cada cliente.

6. Atributo multivalorado no DER

Na notação tradicional do DER, um atributo multivalorado costuma ser representado por uma elipse dupla.

Conceitualmente:

                 ╔═══════════╗
                 ║ TELEFONE  ║
                 ╚═══════════╝
                       │
                       │
                  ┌────▼────┐
                  │ CLIENTE │
                  └─────────┘

Enquanto um atributo normal é representado por uma única elipse:

          ( nome )
             |
        ┌────▼────┐
        │ CLIENTE │
        └─────────┘

A representação exata pode variar conforme a notação e a ferramenta utilizada, mas o conceito permanece o mesmo.

7. Atributo multivalorado × entidade

Uma dúvida comum é:

"Quando algo possui vários valores, devo usar um atributo multivalorado ou criar uma entidade?"

No modelo conceitual, pode existir um atributo multivalorado. Porém, ao transformar o modelo em um banco relacional, frequentemente criamos uma tabela para representar esses valores.

Por exemplo:

CLIENTE
   │
   └── telefones

pode ser transformado em:

CLIENTE
   │
   │ 1:N
   ▼
TELEFONE

Dependendo do sistema, TELEFONE pode ser tratado como uma entidade própria, especialmente se precisar de outras informações:

TELEFONE
├── id_telefone
├── número
├── tipo
└── principal

Por exemplo:

id | número          | tipo
---|-----------------|----------
1  | 8899999-1111    | Celular
2  | 8833333-2222    | Comercial

8. Quando usar?

Um atributo multivalorado faz sentido quando uma entidade pode possuir vários valores do mesmo tipo de informação.

Exemplo:

ALUNO
└── telefones

Um aluno pode possuir:

  • telefone pessoal;
  • telefone dos pais;
  • telefone de contato de emergência.

Outro exemplo:

PROFESSOR
└── especialidades

Um professor pode possuir várias especialidades.

Na implementação relacional, esses valores normalmente são separados em outra tabela.

9. Cuidado com listas em uma coluna

Evite estruturas como:

id | nome | telefones
---|------|------------------------------
1  | João | 1111, 2222, 3333

Isso pode causar problemas para consultar:

"Quais clientes possuem o telefone 2222?"

Também dificulta:

  • adicionar um telefone;
  • remover apenas um telefone;
  • validar cada telefone;
  • criar índices;
  • relacionar o telefone com outras informações.

Uma estrutura melhor seria:

CLIENTE

id | nome
---|------
1  | João
TELEFONE

id | id_cliente | numero
---|------------|--------
1  | 1          | 1111
2  | 1          | 2222
3  | 1          | 3333

Resumo

Atributo multivalorado é aquele que pode possuir mais de um valor para uma mesma entidade.

Exemplo:

CLIENTE
├── id_cliente
├── nome
└── telefones
       ├── 1111
       ├── 2222
       └── 3333

No modelo relacional, geralmente transformamos isso em uma estrutura 1:N:

CLIENTE 1 ───────── N TELEFONE

Diferença principal

Atributo simples:
nome → "João"

Atributo multivalorado:
telefone → {1111, 2222, 3333}

Em resumo: quando uma entidade pode possuir vários valores de uma determinada informação, temos um atributo multivalorado. Em bancos relacionais, esses valores normalmente são armazenados em uma tabela separada, evitando colocar listas dentro de uma única coluna.
