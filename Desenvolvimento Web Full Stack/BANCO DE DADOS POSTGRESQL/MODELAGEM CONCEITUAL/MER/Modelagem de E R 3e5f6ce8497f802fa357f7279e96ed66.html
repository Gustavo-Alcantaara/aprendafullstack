Modelagem de E.R

Modelagem de Entidades e Relacionamentos

A Modelagem de Entidades e Relacionamentos é uma técnica utilizada para representar, de forma organizada, quais dados um sistema precisa armazenar e como esses dados se relacionam.

Ela é uma etapa fundamental do projeto de um banco de dados e normalmente está associada ao Modelo Entidade-Relacionamento (MER) e ao Diagrama Entidade-Relacionamento (DER).

A ideia principal é transformar os requisitos de um sistema em uma estrutura que possa posteriormente ser implementada em um SGBD, como PostgreSQL ou MySQL.

1. O que é uma entidade?

Uma entidade representa algo sobre o qual o sistema precisa armazenar informações.

Por exemplo, em um sistema de uma loja podemos ter:

CLIENTE
PRODUTO
PEDIDO
FUNCIONÁRIO

Cada uma dessas entidades representa um tipo de objeto ou conceito do sistema.

Por exemplo:

CLIENTE
├── id_cliente
├── nome
├── cpf
├── email
└── telefone

2. O que é um atributo?

Um atributo representa uma característica de uma entidade.

Por exemplo:

CLIENTE
├── id_cliente
├── nome
├── email
└── telefone

Aqui, nome, email e telefone são atributos de CLIENTE.

O id_cliente normalmente funciona como identificador, permitindo distinguir um cliente dos demais.

3. O que é um relacionamento?

Um relacionamento representa uma associação entre duas ou mais entidades.

Por exemplo:

CLIENTE ─── realiza ─── PEDIDO

Isso significa que um cliente realiza pedidos.

Outro exemplo:

PEDIDO ─── contém ─── PRODUTO

4. Cardinalidade

Depois de identificar um relacionamento, precisamos determinar quantas ocorrências de uma entidade podem estar relacionadas com outra.

As principais cardinalidades são:

1:1 — Um para um

Uma ocorrência de uma entidade está relacionada a uma ocorrência da outra.

PESSOA 1 ───── 1 PASSAPORTE

1:N — Um para muitos

Uma ocorrência pode estar relacionada com várias ocorrências.

CLIENTE 1 ───── N PEDIDO

Um cliente pode fazer vários pedidos, mas cada pedido pertence a um cliente.

N:N — Muitos para muitos

Várias ocorrências de uma entidade podem estar relacionadas com várias ocorrências de outra.

PEDIDO N ───── N PRODUTO

Um pedido pode ter vários produtos, e um produto pode aparecer em vários pedidos.

Em um banco relacional, normalmente criamos uma entidade associativa:

PEDIDO 1 ─── N ITEM_PEDIDO N ─── 1 PRODUTO

5. Entidade associativa

A entidade associativa é utilizada principalmente para representar relacionamentos N:N.

Por exemplo:

PEDIDO N ───── N PRODUTO

Transformamos em:

PEDIDO 1 ─── N ITEM_PEDIDO N ─── 1 PRODUTO

ITEM_PEDIDO pode possuir seus próprios atributos:

ITEM_PEDIDO
├── id_pedido
├── id_produto
├── quantidade
└── preco_unitario

Isso permite registrar informações que pertencem à própria associação entre pedido e produto.

6. Processo de modelagem

A modelagem normalmente segue uma sequência de etapas.

1. Levantamento dos requisitos

Entender o que o sistema precisa fazer e quais informações precisam ser armazenadas.

2. Identificação das entidades

Encontrar os principais objetos ou conceitos:

CLIENTE
PEDIDO
PRODUTO

3. Identificação dos atributos

Determinar quais informações serão armazenadas sobre cada entidade.

4. Identificação dos relacionamentos

Descobrir como as entidades estão relacionadas.

5. Definição das cardinalidades

Determinar se os relacionamentos são 1:1, 1:N ou N:N.

6. Identificação de entidades associativas

Resolver relacionamentos N:N quando necessário.

7. Definição das regras de negócio

Garantir que o modelo represente corretamente o funcionamento real do sistema.

8. Construção do DER

Representar graficamente as entidades, atributos e relacionamentos.

9. Validação

Verificar se o modelo atende aos requisitos e não possui inconsistências.

7. Exemplo completo

Imagine uma loja com as seguintes regras:

Um cliente pode realizar vários pedidos. Cada pedido pertence a um cliente. Um pedido pode possuir vários produtos, e um produto pode aparecer em vários pedidos. Para cada produto dentro de um pedido, precisamos saber a quantidade.

Primeiro identificamos as entidades:

CLIENTE
PEDIDO
PRODUTO

Como PEDIDO e PRODUTO possuem relacionamento N:N, criamos:

ITEM_PEDIDO

O modelo fica:

┌──────────────┐
│   CLIENTE    │
├──────────────┤
│ id_cliente   │
│ nome         │
│ email        │
└───────┬──────┘
        │
        │ 1:N
        ▼
┌──────────────┐
│    PEDIDO    │
├──────────────┤
│ id_pedido    │
│ id_cliente   │
│ data         │
└───────┬──────┘
        │
        │ 1:N
        ▼
┌────────────────┐
│  ITEM_PEDIDO   │
├────────────────┤
│ id_pedido      │
│ id_produto     │
│ quantidade     │
└────────┬───────┘
         │
         │ N:1
         ▼
┌──────────────┐
│   PRODUTO    │
├──────────────┤
│ id_produto   │
│ nome         │
│ preco        │
└──────────────┘

Esse modelo já permite representar a estrutura básica da loja.

8. Modelo conceitual, lógico e físico

A modelagem de entidades e relacionamentos está principalmente relacionada ao modelo conceitual, mas faz parte de um processo maior.

Modelo conceitual

Representa os dados de maneira independente do SGBD.

Exemplo:

CLIENTE ─── realiza ─── PEDIDO

Modelo lógico

Transforma o modelo conceitual em estruturas mais próximas das tabelas:

CLIENTE
(id_cliente, nome, email)

PEDIDO
(id_pedido, id_cliente, data)

Modelo físico

Define como essas estruturas serão realmente implementadas no SGBD:

CREATE TABLE cliente (
    id_cliente INT PRIMARY KEY,
    nome VARCHAR(100),
    email VARCHAR(150)
);

Portanto:

Requisitos
    ↓
Modelo Conceitual
    ↓
Modelo Lógico
    ↓
Modelo Físico
    ↓
Banco de Dados

9. Por que a modelagem é importante?

Uma boa modelagem ajuda a:

  • organizar os dados;
  • evitar informações duplicadas;
  • estabelecer relacionamentos corretamente;
  • facilitar consultas;
  • melhorar a integridade dos dados;
  • identificar problemas antes da implementação;
  • facilitar a manutenção do banco;
  • representar corretamente as regras de negócio.

Um banco mal modelado pode gerar problemas como duplicação de dados, inconsistências, dificuldade de manutenção e consultas desnecessariamente complexas.

Resumo

A Modelagem de Entidades e Relacionamentos consiste em identificar e organizar:

ENTIDADES
    ↓
ATRIBUTOS
    ↓
RELACIONAMENTOS
    ↓
CARDINALIDADES
    ↓
REGRAS DE NEGÓCIO

E posteriormente transformar esse modelo em estruturas que possam ser implementadas no banco de dados.

Os principais conceitos que você deve dominar são:

ConceitoFunção
EntidadeRepresenta um objeto ou conceito
AtributoCaracterística da entidade
IdentificadorIdentifica uma ocorrência de forma única
RelacionamentoAssociação entre entidades
CardinalidadeDefine quantas ocorrências podem se relacionar
Entidade associativaRepresenta principalmente relacionamentos N:N
MERModelo conceitual dos dados
DERRepresentação gráfica do modelo

Em resumo: a modelagem de entidades e relacionamentos é o processo de transformar as regras e necessidades de um sistema em uma estrutura clara de dados e seus relacionamentos, servindo como base para a criação do banco de dados.
