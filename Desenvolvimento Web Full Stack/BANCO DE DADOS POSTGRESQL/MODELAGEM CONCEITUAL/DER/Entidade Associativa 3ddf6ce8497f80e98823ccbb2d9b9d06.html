Entidade Associativa

Uma entidade associativa é utilizada no Modelo Entidade-Relacionamento (MER) quando precisamos transformar um relacionamento entre entidades em uma nova entidade.

Ela é especialmente comum em relacionamentos de muitos para muitos (N:N).

1. Por que usar uma entidade associativa?

Imagine um sistema de vendas:

CLIENTE ─── faz ─── PEDIDO

Um cliente pode fazer vários pedidos, e cada pedido pertence a um cliente. Nesse caso, temos:

CLIENTE 1 ─── N PEDIDO

Esse relacionamento pode ser representado diretamente.

Agora imagine:

PEDIDO ─── contém ─── PRODUTO

Um pedido pode conter vários produtos.

E um produto pode aparecer em vários pedidos diferentes.

Portanto:

PEDIDO N ─── N PRODUTO

Temos um relacionamento N:N.

Em um banco de dados relacional, esse relacionamento precisa ser transformado para que possa ser armazenado adequadamente. É aí que entra a entidade associativa.

2. Exemplo: Pedido e Produto

Inicialmente temos:

PEDIDO N ───────── N PRODUTO

O problema é que precisamos armazenar informações sobre a associação.

Por exemplo:

  • qual produto está no pedido?
  • qual a quantidade?
  • qual o preço do produto naquele pedido?

Podemos criar:

PEDIDO
   │
   │
   ▼
ITEM_PEDIDO
   ▲
   │
   │
PRODUTO

ITEM_PEDIDO é a entidade associativa.

3. Atributos da entidade associativa

Ela pode possuir seus próprios atributos.

Por exemplo:

ITEM_PEDIDO
├── id_pedido
├── id_produto
├── quantidade
└── preco_unitario

Assim, conseguimos representar:

PEDIDO
id_pedido: 1001

        ↓

ITEM_PEDIDO
id_pedido: 1001
id_produto: 25
quantidade: 3
preco_unitario: 50,00

        ↓

PRODUTO
id_produto: 25
nome: Teclado

Isso significa:

O pedido 1001 possui 3 unidades do produto Teclado, pelo preço de R$ 50,00 cada.

4. Como fica o relacionamento?

O relacionamento N:N:

PEDIDO N ───── N PRODUTO

é transformado em dois relacionamentos 1:N:

PEDIDO 1 ───── N ITEM_PEDIDO N ───── 1 PRODUTO

Visualmente:

┌──────────┐        ┌─────────────┐        ┌──────────┐
│  PEDIDO  │ 1    N │ ITEM_PEDIDO │ N    1 │ PRODUTO  │
├──────────┤────────├─────────────┤────────├──────────┤
│id_pedido │        │id_pedido    │        │id_produto│
│data      │        │id_produto   │        │nome      │
│cliente   │        │quantidade   │        │preço     │
└──────────┘        │preço_unit.  │        └──────────┘
                    └─────────────┘

5. Entidade associativa no banco de dados

No modelo relacional, a entidade associativa normalmente se transforma em uma tabela intermediária.

Por exemplo:

CREATE TABLE pedido (
    id_pedido INT PRIMARY KEY,
    data_pedido DATE
);
CREATE TABLE produto (
    id_produto INT PRIMARY KEY,
    nome VARCHAR(100),
    preco DECIMAL(10,2)
);

E a entidade associativa:

CREATE TABLE item_pedido (
    id_pedido INT,
    id_produto INT,
    quantidade INT,
    preco_unitario DECIMAL(10,2),

    PRIMARY KEY (id_pedido, id_produto),

    FOREIGN KEY (id_pedido)
        REFERENCES pedido(id_pedido),

    FOREIGN KEY (id_produto)
        REFERENCES produto(id_produto)
);

Nesse exemplo:

  • id_pedido → chave estrangeira para PEDIDO
  • id_produto → chave estrangeira para PRODUTO
  • quantidade → atributo da associação
  • preco_unitario → atributo da associação

A combinação:

(id_pedido, id_produto)

pode funcionar como chave primária composta.

6. Outro exemplo: Aluno e Curso

Imagine uma faculdade onde:

  • um aluno pode fazer vários cursos;
  • um curso pode ter vários alunos.

Temos:

ALUNO N ───── N CURSO

Podemos criar:

ALUNO 1 ───── N MATRÍCULA N ───── 1 CURSO

MATRÍCULA funciona como entidade associativa.

Ela pode possuir:

MATRÍCULA
├── id_aluno
├── id_curso
├── data_matricula
├── situação
└── nota

A vantagem é que conseguimos armazenar informações sobre a relação entre aluno e curso.

7. O que diferencia uma entidade associativa?

O ponto principal é que ela representa uma associação que possui informações próprias.

Por exemplo:

ALUNO ─── CURSO

A relação "aluno está matriculado no curso" pode possuir:

  • data da matrícula;
  • situação;
  • nota;
  • frequência.

Essas informações não pertencem exclusivamente ao ALUNO nem ao CURSO.

Elas pertencem à relação entre os dois.

Por isso criamos:

ALUNO
   │
   ▼
MATRÍCULA
   ▲
   │
CURSO

8. Quando utilizar?

A entidade associativa é principalmente utilizada quando:

  1. Existe um relacionamento N:N;
  1. O relacionamento possui atributos próprios;
  1. Precisamos representar a associação como uma tabela no modelo relacional.

Resumo

A entidade associativa serve para representar uma associação entre entidades, principalmente quando existe um relacionamento muitos para muitos (N:N).

Exemplo clássico:

Antes:

PEDIDO N ───────── N PRODUTO


Depois:

PEDIDO 1 ─── N ITEM_PEDIDO N ─── 1 PRODUTO

A entidade associativa ITEM_PEDIDO permite armazenar informações como:

id_pedido
id_produto
quantidade
preco_unitario

Em resumo:

Entidade associativa é uma entidade criada para representar e armazenar informações de um relacionamento, especialmente um relacionamento N:N.
