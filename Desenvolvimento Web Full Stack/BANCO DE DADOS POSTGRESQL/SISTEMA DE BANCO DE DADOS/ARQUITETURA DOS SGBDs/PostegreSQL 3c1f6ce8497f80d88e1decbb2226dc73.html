PostgreSQL

O PostgreSQL é um dos principais Sistemas Gerenciadores de Banco de Dados Relacionais (SGBDs) de código aberto. Ele utiliza SQL para manipulação dos dados e é conhecido por sua robustez, segurança, confiabilidade, extensibilidade e suporte a recursos avançados.

É muito utilizado em aplicações Web, sistemas empresariais, APIs, aplicações financeiras, sistemas de análise de dados e diversos outros projetos.

1. O que é PostgreSQL?

O PostgreSQL é um SGBD objeto-relacional, ou seja, possui uma forte base no modelo relacional, mas oferece recursos que vão além do modelo relacional tradicional.

Sua estrutura básica é:

Aplicação
    ↓
PostgreSQL
    ↓
Banco de Dados
    ↓
Tabelas
    ↓
Dados

Uma aplicação pode utilizar PostgreSQL através de diferentes linguagens, como:

  • PHP;
  • Python;
  • Java;
  • C#;
  • JavaScript/Node.js;
  • Ruby;
  • Go.

2. Origem do PostgreSQL

O PostgreSQL tem suas raízes no projeto POSTGRES, desenvolvido na Universidade da Califórnia, Berkeley, a partir da década de 1980.

O projeto foi liderado por Michael Stonebraker e tinha como objetivo desenvolver um sistema de banco de dados mais avançado que os sistemas existentes na época.

Posteriormente, o projeto passou por mudanças e recebeu suporte à linguagem SQL, dando origem ao nome PostgreSQL.

Sua evolução fez com que se tornasse um dos SGBDs de código aberto mais importantes da atualidade.

3. Característica de código aberto

Uma das características mais importantes do PostgreSQL é ser open source.

Isso significa que seu código-fonte pode ser estudado, modificado e distribuído de acordo com sua licença.

Isso contribuiu para a criação de uma grande comunidade ao redor do projeto.

Entre as vantagens estão:

  • Liberdade de uso;
  • Comunidade ativa;
  • Grande quantidade de documentação;
  • Desenvolvimento colaborativo;
  • Ausência de dependência obrigatória de uma licença proprietária.

5. SQL no PostgreSQL

O PostgreSQL utiliza SQL para criar e manipular os dados.

Criando uma tabela

CREATE TABLE clientes (
    id SERIAL PRIMARY KEY,
    nome VARCHAR(100) NOT NULL,
    email VARCHAR(150)
);

Inserindo dados

INSERT INTO clientes (nome, email)
VALUES ('João', 'joao@email.com');

Consultando

SELECT *
FROM clientes;

Atualizando

UPDATE clientes
SET email = 'novo@email.com'
WHERE id = 1;

Excluindo

DELETE FROM clientes
WHERE id = 1;

Esses comandos formam parte das operações fundamentais de SQL:

SELECT  → Consultar
INSERT  → Inserir
UPDATE  → Atualizar
DELETE  → Excluir

7. Transações

O PostgreSQL possui suporte completo a transações.

Uma transação permite agrupar várias operações em uma unidade lógica.

Exemplo:

BEGIN;

UPDATE contas
SET saldo = saldo - 500
WHERE id = 1;

UPDATE contas
SET saldo = saldo + 500
WHERE id = 2;

COMMIT;

Se ocorrer algum problema, podemos cancelar a transação:

ROLLBACK;

Isso é muito importante para sistemas que precisam garantir consistência.

8. Integridade dos dados

O PostgreSQL permite definir regras que ajudam a impedir dados inválidos.

Exemplo:

CREATE TABLE usuarios (
    id INTEGER PRIMARY KEY,
    nome VARCHAR(100) NOT NULL,
    email VARCHAR(150) UNIQUE,
    idade INTEGER CHECK (idade >= 18)
);

Nesse exemplo:

  • PRIMARY KEY identifica cada registro;
  • NOT NULL exige um valor;
  • UNIQUE impede duplicidade;
  • CHECK estabelece uma condição.

9. Chaves estrangeiras

O PostgreSQL permite criar relacionamentos entre tabelas.

Exemplo:

CREATE TABLE pedidos (
    id INTEGER PRIMARY KEY,
    cliente_id INTEGER,

    FOREIGN KEY (cliente_id)
    REFERENCES clientes(id)
);

Assim:

Clientes
   │
   │ 1
   │
   └──────────< N
              Pedidos

Um cliente pode possuir vários pedidos.

11. JSON e JSONB

O PostgreSQL possui suporte importante para dados JSON.

Por exemplo:

CREATE TABLE usuarios (
    id SERIAL PRIMARY KEY,
    nome TEXT,
    dados JSONB
);

Podemos armazenar:

{
    "telefone": "99999-1111",
    "cidade": "Fortaleza",
    "interesses": ["programação", "banco de dados"]
}

O JSONB é especialmente interessante porque permite armazenar e consultar estruturas JSON de forma eficiente dentro do PostgreSQL.

Isso possibilita combinar:

Modelo Relacional
       +
     JSON

em uma mesma aplicação.

12. Views

Uma VIEW é uma consulta armazenada que pode ser utilizada como uma tabela virtual.

Exemplo:

CREATE VIEW clientes_ativos AS
SELECT id, nome, email
FROM clientes
WHERE ativo = TRUE;

Depois:

SELECT *
FROM clientes_ativos;

Views podem ajudar a:

  • Simplificar consultas;
  • Controlar acesso;
  • Organizar a lógica de consulta.

13. Triggers

Os triggers permitem executar determinadas ações automaticamente quando eventos acontecem no banco.

Por exemplo:

INSERT
  ↓
Trigger
  ↓
Registrar alteração

Podem ser utilizados para:

  • Auditoria;
  • Registro de alterações;
  • Validações;
  • Automatização de processos.

14. Funções e Procedures

O PostgreSQL permite criar lógica diretamente no banco.

Por exemplo, uma função pode realizar cálculos ou processar informações.

CREATE FUNCTION somar(a INTEGER, b INTEGER)
RETURNS INTEGER
AS $$
BEGIN
    RETURN a + b;
END;
$$ LANGUAGE plpgsql;

Depois:

SELECT somar(10, 20);

Resultado:

30

O PostgreSQL possui sua própria linguagem procedural chamada PL/pgSQL, embora também ofereça suporte a outras linguagens em determinados contextos.

15. Índices

Os índices são utilizados para melhorar o desempenho de determinadas consultas.

Por exemplo:

CREATE INDEX idx_clientes_nome
ON clientes(nome);

Quando uma tabela possui muitos registros, índices adequadamente planejados podem acelerar consultas.

Porém, índices também possuem custo de armazenamento e podem aumentar o trabalho necessário para determinadas operações de escrita.

Por isso, não devemos criar índices indiscriminadamente.

16. Concorrência

O PostgreSQL foi projetado para permitir que vários usuários trabalhem simultaneamente.

Por exemplo:

Usuário A ──┐
Usuário B ──┤
Usuário C ──┼──→ PostgreSQL
Usuário D ──┘

O banco utiliza mecanismos de controle de concorrência para manter a consistência dos dados.

Um conceito importante no PostgreSQL é o MVCC (Multi-Version Concurrency Control), que permite que diferentes transações trabalhem com versões apropriadas dos dados sem depender exclusivamente de bloqueios tradicionais.

17. Segurança

O PostgreSQL possui recursos para controlar o acesso aos dados.

Podemos trabalhar com:

  • Usuários;
  • Roles;
  • Permissões;
  • Autenticação;
  • Controle de acesso;
  • Criptografia em conexões;
  • Auditoria através de recursos e extensões apropriados.

Por exemplo:

CREATE ROLE usuario_app LOGIN PASSWORD 'senha';

E podemos conceder permissões:

GRANT SELECT ON clientes
TO usuario_app;

Em sistemas reais, senhas e credenciais devem ser tratadas com segurança e nunca expostas diretamente no código-fonte.

21. Vantagens do PostgreSQL

Principais vantagens:

1. Código aberto

Pode ser utilizado sem depender de licenças proprietárias tradicionais.

2. Robustez

É adequado para aplicações que precisam de confiabilidade.

3. Recursos avançados

Oferece uma grande variedade de recursos SQL e de banco de dados.

4. Extensibilidade

Pode ser expandido através de extensões.

5. Excelente suporte a transações

Adequado para sistemas que exigem consistência.

6. Grande variedade de tipos de dados

Oferece tipos tradicionais e recursos mais avançados.

Possui uma comunidade grande e bastante ativa.

22. Desvantagens

Apesar de suas vantagens, existem alguns pontos que devem ser considerados:

  • Pode ser mais complexo para iniciantes do que soluções mais simples;
  • Alguns recursos avançados exigem conhecimento especializado;
  • Administração e otimização podem exigir experiência;
  • Migrações de outros SGBDs podem exigir adaptações;
  • Não é necessariamente a melhor escolha para todos os tipos de aplicações.

24. PostgreSQL em uma aplicação PHP

Como você está estudando PHP, é importante entender que o PostgreSQL pode ser utilizado diretamente com PHP.

A arquitetura pode ser:

Usuário
   ↓
HTML/CSS/JavaScript
   ↓
PHP
   ↓
PDO
   ↓
PostgreSQL
   ↓
Banco de Dados

Exemplo utilizando PDO:

<?php

$pdo = new PDO(
    "pgsql:host=localhost;dbname=loja",
    "postgres",
    "senha"
);

$stmt = $pdo->query("SELECT * FROM clientes");

$clientes = $stmt->fetchAll(PDO::FETCH_ASSOC);

print_r($clientes);

O PDO permite que o PHP trabalhe com diferentes bancos de dados através de uma interface relativamente uniforme.

Resumo

O PostgreSQL é um SGBD objeto-relacional, open source e altamente extensível, baseado principalmente no modelo relacional.

Suas principais características são:

  • Utilização de SQL;
  • Transações e propriedades ACID;
  • Controle de concorrência;
  • Chaves e constraints;
  • Views;
  • Triggers;
  • Functions e Procedures;
  • JSON/JSONB;
  • Índices;
  • Segurança;
  • Extensões;
  • Suporte a grandes volumes de dados;
  • Integração com diversas linguagens e aplicações.

Sua estrutura básica é:

Aplicação
    ↓
Driver / PDO
    ↓
PostgreSQL
    ↓
Banco de Dados
    ↓
Tabelas + Índices + Dados

Para quem está estudando Banco de Dados, PostgreSQL é especialmente importante porque permite aprender não apenas SQL e o modelo relacional, mas também diversos recursos avançados encontrados em SGBDs profissionais.
