Criptografia

🔐 Criptografia

A criptografia é uma área da segurança da informação responsável por proteger dados por meio de técnicas matemáticas, permitindo que informações sejam armazenadas ou transmitidas de forma que somente pessoas ou sistemas autorizados consigam utilizá-las corretamente.

Ela é fundamental em praticamente todos os sistemas modernos: sites, aplicativos, bancos, sistemas corporativos, mensageria, armazenamento de arquivos, autenticação e transações financeiras.

1. O que é criptografia?

A ideia básica é transformar uma informação original, chamada de texto claro (plaintext), em uma informação protegida, chamada de texto cifrado (ciphertext).

Texto original
      ↓
   CRIPTOGRAFIA
      ↓
Texto cifrado
      ↓
   DESCRIPTOGRAFIA
      ↓
Texto original

Por exemplo:

Mensagem original:
"Minha senha é 123456"

          ↓ criptografia

Mensagem protegida:
"8fA#92xK!pL..."

O objetivo é que alguém que obtenha o texto cifrado não consiga descobrir facilmente o conteúdo original.

2. Para que serve a criptografia?

A criptografia está principalmente relacionada a quatro objetivos de segurança:

🔒 Confidencialidade

Garante que somente pessoas autorizadas possam acessar determinada informação.

Exemplo:

Você → mensagem criptografada → servidor

Mesmo que alguém consiga interceptar os dados, não deverá conseguir entender seu conteúdo.

🛡️ Integridade

Permite verificar se uma informação foi modificada.

Por exemplo:

Arquivo original
      ↓
     HASH
      ↓
A1B2C3...

Se o arquivo for alterado:

Arquivo alterado
      ↓
     HASH
      ↓
X9Y8Z7...

Os valores serão diferentes.

Hashes são relacionados à criptografia, mas hashing não é criptografia, porque normalmente não existe uma operação de "descriptografar" o hash.

👤 Autenticidade

Permite verificar se uma mensagem, documento ou comunicação realmente veio de determinada entidade.

Um exemplo importante são as assinaturas digitais.

Documento
    ↓
Assinatura digital
    ↓
Verificação
    ↓
"Foi realmente assinado por X?"

✅ Não repúdio

Em determinados sistemas, uma assinatura digital pode fornecer evidências de que determinada entidade assinou uma informação, dificultando que ela posteriormente negue a autoria.

Isso é especialmente importante em:

  • contratos digitais;
  • documentos;
  • sistemas jurídicos;
  • transações;
  • certificados.

3. Conceitos fundamentais

Existem alguns termos que você precisa conhecer.

Plaintext

É o dado original.

"Olá, mundo!"

Ciphertext

É o resultado da criptografia.

"X9a#72Lm..."

Chave

É um valor utilizado pelo algoritmo criptográfico para realizar a operação.

Mensagem + Chave
       ↓
   Algoritmo
       ↓
Mensagem cifrada

Algoritmo criptográfico

É o conjunto de operações matemáticas utilizadas para proteger os dados.

Exemplos:

  • AES;
  • RSA;
  • ECC;
  • ChaCha20.

4. Criptografia simétrica

Na criptografia simétrica, a mesma chave é utilizada para criptografar e descriptografar.

             MESMA CHAVE
                  │
                  ▼
Mensagem ──→ Criptografia ──→ Dados cifrados
                                  │
                                  ▼
                           Descriptografia
                                  │
                                  ▼
                              Mensagem

Por exemplo:

Chave: ABC123

Mensagem
   ↓
AES + chave
   ↓
Dados criptografados
   ↓
AES + mesma chave
   ↓
Mensagem original

Vantagem

É geralmente muito rápida.

Por isso é bastante utilizada para proteger grandes quantidades de dados.

Problema

Existe a questão da distribuição da chave.

Se duas pessoas precisam utilizar a mesma chave:

Alice ─── chave ───→ Bob

Como Alice entrega a chave para Bob de maneira segura?

Esse problema é uma das razões pelas quais a criptografia assimétrica é tão importante.

5. Exemplos de algoritmos simétricos

AES

O AES (Advanced Encryption Standard) é um dos principais algoritmos simétricos utilizados atualmente.

É encontrado em diversos sistemas, protocolos e aplicações.

Possui tamanhos de chave como:

  • 128 bits;
  • 192 bits;
  • 256 bits.

Um exemplo comum é:

AES-256

ChaCha20

O ChaCha20 também é um algoritmo moderno de criptografia simétrica.

É especialmente conhecido por seu bom desempenho em software e é utilizado em diversos protocolos modernos.

Frequentemente aparece associado ao Poly1305, formando:

ChaCha20-Poly1305

Esse tipo de construção fornece tanto criptografia quanto autenticação dos dados.

6. Criptografia assimétrica

A criptografia assimétrica utiliza um par de chaves:

🔑 Chave pública
🔐 Chave privada

A chave pública pode ser compartilhada.

A chave privada deve ser protegida.

        PAR DE CHAVES

   ┌─────────────────┐
   │ Chave Pública   │
   └─────────────────┘

   ┌─────────────────┐
   │ Chave Privada   │
   └─────────────────┘

Uma propriedade importante é que determinadas operações feitas com uma chave podem ser verificadas ou revertidas utilizando a chave correspondente, conforme o algoritmo e o uso.

7. Exemplo conceitual

Imagine que João quer enviar uma informação protegida para Maria.

Maria possui:

Chave pública → pode compartilhar
Chave privada → deve permanecer secreta

João utiliza a chave pública de Maria:

Mensagem
   ↓
Chave pública de Maria
   ↓
Dados protegidos
   ↓
Maria

Maria utiliza sua chave privada para obter o conteúdo.

A ideia importante é:

A chave pública pode ser divulgada; a chave privada precisa permanecer protegida.

8. Exemplos de criptografia assimétrica

Algoritmos e famílias importantes incluem:

RSA

Um dos algoritmos assimétricos mais conhecidos.

Foi muito utilizado em:

  • troca de chaves;
  • certificados;
  • assinaturas digitais;
  • sistemas de segurança.

ECC

Elliptic Curve Cryptography utiliza conceitos matemáticos relacionados a curvas elípticas.

Possui a vantagem de fornecer níveis de segurança comparáveis aos de sistemas tradicionais utilizando chaves menores.

Dentro desse universo existem algoritmos e esquemas como:

  • ECDSA;
  • ECDH;
  • EdDSA.

Na prática, sistemas modernos frequentemente utilizam as duas.

10. Criptografia híbrida

Um sistema pode combinar criptografia assimétrica e simétrica.

Por exemplo:

        Cliente
           │
           │
     Criptografia
      assimétrica
           │
           ▼
     Troca/estabelece
        uma chave
           │
           ▼
    Criptografia
       simétrica
           │
           ▼
       Dados

A criptografia assimétrica ajuda a estabelecer ou proteger uma chave de sessão.

Depois, a criptografia simétrica é utilizada para proteger os dados porque é mais eficiente.

Esse conceito é extremamente importante para entender protocolos como TLS/HTTPS.

11. Criptografia no HTTPS

Quando você acessa:

https://exemplo.com

a comunicação entre navegador e servidor utiliza TLS.

De forma simplificada:

Navegador
    │
    │  negociação segura
    ▼
Servidor
    │
    ▼
Chaves de sessão
    │
    ▼
Comunicação criptografada

O TLS utiliza criptografia assimétrica, certificados e criptografia simétrica em diferentes partes do processo.

Depois que uma sessão segura é estabelecida, os dados normalmente são protegidos utilizando mecanismos simétricos eficientes.

12. Certificados digitais

Os certificados digitais ajudam a estabelecer a identidade de servidores e outras entidades.

Quando você acessa:

https://meubanco.com

o navegador verifica informações do certificado apresentado pelo servidor.

Conceitualmente:

Servidor
   │
   └── Certificado
          │
          ▼
      Navegador
          │
          ▼
"Este certificado corresponde
 a quem estou tentando acessar?"

Certificados são fundamentais para o funcionamento seguro do HTTPS.

13. Hashing

Hashing é frequentemente estudado junto com criptografia, mas existe uma diferença fundamental.

Uma função hash transforma uma entrada em um valor de tamanho determinado.

Entrada
   ↓
Função Hash
   ↓
Hash

Exemplo conceitual:

"Olá"
   ↓
SHA-256
   ↓
valor hexadecimal longo

Uma característica importante é que uma função hash criptográfica é projetada para tornar computacionalmente inviável recuperar a entrada original apenas a partir do hash.

14. Hash ≠ criptografia

Essa diferença é muito importante.

Criptografia

Possui como objetivo permitir:

Mensagem
   ↓
Criptografia
   ↓
Dados cifrados
   ↓
Descriptografia
   ↓
Mensagem

Hash

Normalmente funciona assim:

Mensagem
   ↓
Hash
   ↓
Resumo

Não existe simplesmente:

Hash → Deshash → Mensagem

15. Hash de senhas

Um sistema não deveria armazenar senhas dos usuários em texto puro.

Errado:

usuario: gustavo
senha: 123456

Se o banco de dados for comprometido, as senhas estarão imediatamente expostas.

O correto é utilizar uma função de derivação de senha adequada, como:

  • Argon2;
  • bcrypt;
  • scrypt;
  • PBKDF2.

Conceitualmente:

Senha
  +
Salt
  ↓
KDF
  ↓
Hash derivado
  ↓
Banco de dados

Quando o usuário entra novamente:

Senha informada
      ↓
Mesmo processo
      ↓
Resultado
      ↓
Comparação
      ↓
Acesso permitido/negado

16. O que é Salt?

O salt é um valor adicional utilizado no processo de armazenamento seguro de senhas.

Por exemplo:

Senha:
"minhasenha"

Salt:
"X7a91..."

        ↓

Função de derivação

        ↓

Resultado armazenado

Isso ajuda a evitar que usuários com a mesma senha produzam exatamente o mesmo resultado armazenado e dificulta ataques baseados em tabelas pré-computadas.

Cada senha deve ter um salt apropriado e único.

17. Hashes criptográficos

Algoritmos conhecidos incluem:

  • SHA-256;
  • SHA-384;
  • SHA-512;
  • SHA-3.

Eles podem ser utilizados para:

  • verificar integridade;
  • identificar alterações em arquivos;
  • construir mecanismos criptográficos;
  • gerar identificadores derivados;
  • apoiar assinaturas digitais.

Atenção

SHA-256 não é uma função adequada para armazenar senhas diretamente.

Para senhas, utilize uma função específica de derivação de senha, como Argon2 ou bcrypt.

18. Integridade com hash

Imagine que você disponibilizou um arquivo:

programa.zip

Você calcula:

SHA-256(programa.zip)

Resultado:

ABC123...

Outra pessoa baixa o arquivo e calcula novamente.

SHA-256(programa.zip)

Se obtiver:

ABC123...

o hash é compatível com o valor esperado.

Se obtiver:

XYZ789...

o arquivo não é idêntico ao original.

Hash ajuda a detectar alterações, mas sozinho não prova quem produziu o arquivo.

Para autenticidade, entram mecanismos como assinaturas digitais.

19. Assinatura digital

Uma assinatura digital permite verificar principalmente:

  • integridade;
  • autenticidade;
  • autoria criptográfica.

Conceitualmente:

Documento
    ↓
Hash
    ↓
Assinatura usando chave privada
    ↓
Assinatura digital

Quem recebe pode utilizar a chave pública correspondente para verificar a assinatura.

Documento
    +
Assinatura
    +
Chave pública
    ↓
Verificação
    ↓
✔ assinatura válida

20. Criptografia de dados em repouso

Também podemos proteger informações armazenadas.

Exemplos:

  • banco de dados;
  • HD/SSD;
  • backups;
  • arquivos;
  • dispositivos móveis.

Isso é chamado de proteção de dados em repouso (data at rest).

Exemplo:

Banco de dados
      ↓
Criptografia
      ↓
Dados armazenados protegidos

Mesmo que alguém consiga obter acesso físico ou lógico ao armazenamento, a criptografia pode dificultar o acesso aos dados.

21. Criptografia em trânsito

Protege informações enquanto elas estão sendo transmitidas.

Exemplo:

Seu computador
      │
      │ 🔐 dados protegidos
      ▼
   Internet
      │
      ▼
    Servidor

O HTTPS/TLS é um dos principais exemplos.

22. Criptografia ponta a ponta

Na criptografia ponta a ponta (E2EE), o objetivo é que apenas os participantes finais tenham acesso ao conteúdo em texto claro.

Conceitualmente:

Pessoa A
   │
   │ 🔐
   ▼
Internet
   │
   │ 🔐
   ▼
Pessoa B

Os intermediários não deveriam conseguir acessar o conteúdo em texto claro.

Esse conceito aparece em sistemas de comunicação segura.

23. IV e Nonce

Alguns algoritmos utilizam valores adicionais, como:

  • IV (Initialization Vector);
  • Nonce (Number used once).

Eles ajudam a garantir propriedades importantes durante a utilização de determinados modos criptográficos.

Por exemplo:

Mensagem
   +
Chave
   +
Nonce/IV
   ↓
Dados protegidos

É importante seguir exatamente as regras do algoritmo/protocolo utilizado.

Não se deve inventar como gerar, reutilizar ou manipular esses valores.

24. Criptografia autenticada

Não basta apenas esconder os dados.

Também precisamos detectar alterações.

Por isso existem mecanismos de AEAD (Authenticated Encryption with Associated Data).

Exemplos importantes:

  • AES-GCM;
  • ChaCha20-Poly1305.

Eles oferecem, de forma integrada, proteção do conteúdo e autenticação/integridade dos dados.

25. Gerenciamento de chaves

Um dos maiores problemas da criptografia não é necessariamente o algoritmo.

É o gerenciamento das chaves.

Imagine:

AES-256
   +
chave extremamente forte

Mas a chave está:

senha.txt

ou:

codigo-fonte

ou:

GitHub público

A criptografia pode ser excelente, mas a implementação continua insegura.

Boas práticas

As chaves devem:

  • ser protegidas;
  • possuir acesso restrito;
  • não ficar hardcoded no código;
  • não ser publicadas em repositórios;
  • possuir rotação quando necessário;
  • ser armazenadas em mecanismos apropriados;
  • ter permissões mínimas;
  • ser protegidas durante backups.

Em ambientes profissionais podem ser utilizados:

  • KMS;
  • HSM;
  • secret managers;
  • cofres de segredos.

26. Algoritmos que devem ser evitados

Algoritmos antigos podem não fornecer segurança adequada para sistemas modernos.

Exemplos históricos/problemáticos incluem:

DES
RC4
MD5
SHA-1

Isso não significa que qualquer utilização histórica desses algoritmos seja automaticamente vulnerável em qualquer contexto, mas não devem ser escolhidos para novos projetos quando existem alternativas modernas e apropriadas.

27. Não invente sua própria criptografia

Um erro muito comum de iniciantes é pensar:

"Vou criar meu próprio algoritmo de criptografia."

Por exemplo:

A → X
B → Q
C → Z
D → M
...

Isso pode parecer seguro, mas criptografia moderna depende de:

  • matemática avançada;
  • análise criptográfica;
  • resistência a diferentes tipos de ataques;
  • implementação correta;
  • gerenciamento de chaves;
  • protocolos bem estudados.

Por isso:

Use algoritmos e bibliotecas criptográficas consolidadas em vez de criar sua própria criptografia.

29. Criptografia × Segurança da informação

É importante entender que:

Criptografia não resolve todos os problemas de segurança.

Por exemplo:

Sistema perfeitamente criptografado
           +
Senha "123456"
           =
Sistema ainda inseguro

Ou:

Banco criptografado
      +
Controle de acesso inexistente
      =
Problema de segurança

Ou:

HTTPS
   +
Vulnerabilidade de autorização
   =
Sistema vulnerável

Criptografia é apenas uma camada da segurança.

30. Criptografia e os outros temas de segurança

Você pode conectar esse assunto diretamente aos tópicos que já estudou:

                    SEGURANÇA
                        │
        ┌───────────────┼───────────────┐
        │               │               │
   Autenticação    Autorização     Criptografia
        │               │               │
      Login         Permissões       Proteção
        │               │               │
        └───────────────┼───────────────┘
                        │
                  Aplicação segura

Por exemplo:

  • Falhas criptográficas → criptografia mal utilizada.
  • Falhas de autenticação → problemas com senhas, sessões e credenciais.
  • Falhas de integridade → alterações não detectadas.
  • Controle de acesso → quem pode acessar os dados.
  • Configuração incorreta → TLS, certificados ou chaves mal configurados.
  • Componentes vulneráveis → bibliotecas criptográficas desatualizadas.

⭐ A ideia central

Criptografia não é simplesmente "embaralhar uma mensagem".

É um conjunto de técnicas matemáticas utilizadas para fornecer confidencialidade, integridade, autenticidade e, em determinados contextos, não repúdio, formando uma das bases da segurança cibernética moderna.
