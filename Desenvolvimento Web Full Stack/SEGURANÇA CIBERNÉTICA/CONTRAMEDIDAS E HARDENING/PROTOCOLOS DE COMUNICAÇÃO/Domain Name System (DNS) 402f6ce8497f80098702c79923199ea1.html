Domain Name System (DNS)

O DNS (Domain Name System), ou Sistema de Nomes de Domínio, é um dos principais serviços da Internet. Sua função principal é traduzir nomes de domínio, fáceis de memorizar, em endereços IP que os computadores utilizam para se comunicar.

Por exemplo, quando você acessa:

www.google.com

seu computador precisa descobrir qual endereço IP está associado a esse domínio.

O DNS realiza justamente essa tradução:

www.google.com
       ↓
     DNS
       ↓
142.250.xxx.xxx

Sem DNS, precisaríamos memorizar endereços IP para acessar os serviços da Internet.

1. O que significa DNS?

DNS = Domain Name System

Em português:

Sistema de Nomes de Domínio

Ele funciona como uma espécie de sistema de identificação e localização de serviços na Internet.

Uma analogia simples é pensar no DNS como uma agenda telefônica:

Nome                  Número

João        →         99999-9999
Maria       →         98888-8888
Empresa X   →         97777-7777

Na Internet:

Domínio               IP

google.com    →       endereço IP
github.com    →       endereço IP
example.com   →       endereço IP

A diferença é que o DNS é muito mais complexo e distribuído.

2. Por que o DNS é necessário?

Computadores trabalham com endereços IP.

Por exemplo:

142.250.190.14

É possível acessar um servidor usando diretamente seu IP, mas seria muito difícil memorizar milhares de endereços.

Em vez disso, utilizamos nomes:

google.com
youtube.com
github.com
amazon.com

O DNS faz a associação entre eles.

Usuário
   ↓
www.exemplo.com
   ↓
DNS
   ↓
192.168.1.10
   ↓
Servidor

3. DNS não é apenas "nome → IP"

Essa é uma simplificação útil para começar, mas o DNS consegue armazenar vários tipos de informações.

Por exemplo, ele pode informar:

  • endereço IPv4;
  • endereço IPv6;
  • servidor responsável por e-mail;
  • servidores autoritativos;
  • aliases;
  • informações de verificação;
  • políticas relacionadas ao domínio.

Essas informações são armazenadas em registros DNS.

4. Estrutura de um domínio

Vamos utilizar:

www.exemplo.com.br

Podemos dividi-lo:

www . exemplo . com . br
 │       │       │      │
 │       │       │      └── TLD
 │       │       └───────── domínio de segundo nível
 │       └───────────────── nome do domínio
 └───────────────────────── subdomínio/host

br

É o TLD (Top-Level Domain) relacionado ao Brasil.

Exemplos:

.br
.com
.org
.net
.edu

com

É uma categoria dentro da hierarquia de nomes.

Em:

exemplo.com.br

temos:

br
└── com
    └── exemplo

exemplo

É o domínio registrado dentro daquela hierarquia.

www

É um subdomínio/hostname utilizado frequentemente para serviços web.

Por exemplo:

www.exemplo.com
api.exemplo.com
mail.exemplo.com
blog.exemplo.com

Todos podem apontar para serviços diferentes.

5. Hierarquia do DNS

O DNS possui uma estrutura hierárquica.

Podemos representar assim:

                    .
                    │
              Root DNS
                    │
          ┌─────────┴─────────┐
          │                   │
         .com                .br
          │                   │
       exemplo             exemplo
          │                   │
        www                 www

O ponto . no topo representa a raiz (root) do sistema DNS.

6. Root DNS

No topo da hierarquia estão os servidores raiz do DNS.

Eles não armazenam uma lista completa de todos os domínios da Internet.

Em vez disso, eles ajudam a indicar qual servidor é responsável por determinado TLD.

Por exemplo:

Preciso descobrir:
www.exemplo.com

        ↓

Root
        ↓

"Procure os servidores responsáveis por .com"

7. TLD

Depois da raiz temos os TLDs (Top-Level Domains).

Exemplos:

.com
.org
.net
.br
.uk
.jp

O servidor responsável pelo TLD .com, por exemplo, conhece informações sobre os servidores autoritativos responsáveis pelos domínios .com.

Simplificando:

Root
 ↓
.com
 ↓
exemplo.com

8. Servidor DNS autoritativo

O servidor autoritativo é responsável por fornecer as informações oficiais sobre determinado domínio.

Por exemplo:

exemplo.com
      ↓
Servidor DNS autoritativo
      ↓
Registros DNS

Ele pode informar:

www.exemplo.com → 203.0.113.10

Também pode informar servidores de e-mail, aliases e outras informações.

9. Servidor DNS recursivo

Existe outro tipo importante de servidor: o DNS recursivo.

Normalmente, seu computador não conversa diretamente com todos os servidores DNS da hierarquia.

Ele pergunta a um resolvedor DNS (DNS resolver).

Por exemplo:

Seu computador
      ↓
DNS Resolver
      ↓
Internet

Esse resolvedor procura a resposta necessária.

10. Como funciona uma consulta DNS?

Imagine que você digite:

www.exemplo.com

no navegador.

Uma versão simplificada do processo seria:

Navegador
   ↓
Sistema operacional
   ↓
DNS Resolver
   ↓
Root
   ↓
TLD .com
   ↓
Servidor autoritativo
   ↓
IP
   ↓
Navegador

Por exemplo:

www.exemplo.com
       ↓
203.0.113.10

Depois disso, o navegador pode iniciar a comunicação com o servidor.

11. DNS Recursivo e DNS Iterativo

Essa distinção é importante.

Consulta recursiva

O cliente pede ao resolvedor:

"Descubra o endereço para mim."

O resolvedor fica responsável por encontrar a resposta.

Cliente
   │
   │ "Qual o IP de exemplo.com?"
   ↓
Resolver
   │
   ├── Root
   ├── TLD
   └── Autoritativo
   ↓
Resposta

Consulta iterativa

Um servidor DNS pode responder indicando onde procurar em seguida.

Por exemplo:

Root
 ↓
"Não tenho o IP, mas procure no TLD .com"

TLD
 ↓
"Procure no servidor autoritativo de exemplo.com"

Autoritativo
 ↓
"É 203.0.113.10"

12. Cache DNS

Se o DNS precisasse consultar toda a hierarquia sempre que alguém acessasse um site, seria muito ineficiente.

Por isso existe o cache DNS.

Imagine que você acessou:

google.com

O resolvedor pode armazenar temporariamente:

google.com
     ↓
IP

Quando outro usuário fizer a mesma consulta, a resposta pode estar disponível no cache.

Cliente
   ↓
DNS Resolver
   ↓
Cache
   ↓
Resposta

Isso reduz:

  • latência;
  • quantidade de consultas;
  • carga dos servidores DNS.

13. TTL

As informações armazenadas no cache possuem um tempo de validade chamado TTL (Time To Live).

Por exemplo:

TTL = 3600 segundos

Isso significa que o registro pode ser mantido em cache por aproximadamente:

3600 segundos = 1 hora

Depois disso, o resolvedor pode precisar consultar novamente a fonte autoritativa.

14. Principais tipos de registros DNS

Os registros DNS são fundamentais.

A

Relaciona um domínio a um endereço IPv4.

exemplo.com
      ↓
203.0.113.10

AAAA

Relaciona um domínio a um endereço IPv6.

exemplo.com
      ↓
2001:db8::10

CNAME

Cria um alias, ou apelido, para outro nome de domínio.

Por exemplo:

www.exemplo.com
       ↓
exemplo.com

Um CNAME aponta para outro nome, não diretamente para um endereço IP.

MX

Indica quais servidores são responsáveis pelo recebimento de e-mails de um domínio.

Por exemplo:

exemplo.com
      ↓
Servidor de e-mail

Quando alguém envia:

usuario@exemplo.com

o DNS pode informar qual servidor deve receber a mensagem.

NS

Indica os servidores DNS autoritativos de um domínio.

exemplo.com
      ↓
NS
      ↓
ns1.exemplo-dns.com
ns2.exemplo-dns.com

TXT

Permite armazenar informações textuais associadas ao domínio.

É muito utilizado para:

  • verificação de domínio;
  • SPF;
  • políticas de e-mail;
  • outras informações administrativas.

PTR

É utilizado principalmente para resolução reversa.

Enquanto:

Nome → IP

é uma resolução direta, o PTR permite:

IP → Nome

15. Resolução direta x reversa

Resolução direta

Pergunta:

Qual é o IP de exemplo.com?
exemplo.com
     ↓
    IP

Utiliza principalmente registros como:

A
AAAA

Resolução reversa

Pergunta:

Qual nome está associado a este IP?
IP
 ↓
Nome

Utiliza:

PTR

16. DNS e navegador

Quando você acessa um site:

https://www.exemplo.com

vários processos acontecem.

De forma simplificada:

1. Usuário digita o domínio
          ↓
2. Sistema precisa descobrir o IP
          ↓
3. Consulta DNS
          ↓
4. Recebe o endereço IP
          ↓
5. Conecta ao servidor
          ↓
6. HTTPS/TLS estabelece segurança
          ↓
7. Navegador solicita a página

O DNS é, portanto, uma das primeiras etapas para chegar ao servidor.

17. DNS utiliza UDP ou TCP?

Tradicionalmente, o DNS utiliza principalmente:

UDP porta 53

para consultas comuns.

Porém, DNS também pode utilizar:

TCP porta 53

em determinadas situações.

Além disso, existem protocolos modernos que transportam DNS através de outros mecanismos.

Por exemplo:

DNS over HTTPS — DoH

DNS é transportado através de HTTPS.

DNS
 ↓
HTTPS
 ↓
TCP/TLS
 ↓
IP

DNS over TLS — DoT

DNS é protegido usando TLS.

DNS
 ↓
TLS
 ↓
TCP
 ↓
IP

Esses mecanismos ajudam a proteger a consulta DNS contra determinados tipos de observação ou manipulação no caminho.

18. DNS não é criptografia

É importante não confundir as coisas.

O DNS tradicional não foi projetado para criptografar as consultas.

Por exemplo:

Você pergunta:

"Qual o IP de exemplo.com?"

Dependendo de como a consulta é realizada, essa informação pode ser observável na rede.

DoH e DoT adicionam proteção criptográfica ao transporte da consulta.

19. DNS e segurança

O DNS possui uma importância enorme em Cibersegurança.

Isso ocorre porque praticamente todos os serviços modernos dependem de resolução de nomes.

Alguns problemas relacionados ao DNS incluem:

  • DNS spoofing;
  • DNS cache poisoning;
  • DNS hijacking;
  • ataques DDoS contra infraestrutura DNS;
  • domínios maliciosos;
  • DNS tunneling;
  • configurações incorretas;
  • registros expostos indevidamente.

20. DNS Spoofing

DNS spoofing ocorre quando um atacante consegue fazer uma vítima receber uma resposta DNS falsa.

Por exemplo:

A vítima deseja acessar:

banco.com

Mas recebe:

banco.com
      ↓
IP do atacante

Em vez de:

banco.com
      ↓
IP legítimo

Conceitualmente:

Usuário
   │
   │ "Qual o IP de banco.com?"
   ↓
DNS comprometido
   │
   │ IP falso
   ↓
Site malicioso

Esse tipo de ataque pode ser usado para redirecionamento e phishing.

21. DNS Cache Poisoning

O DNS cache poisoning é uma forma de ataque em que informações DNS falsas acabam sendo armazenadas em um cache.

Imagine:

DNS legítimo:
banco.com → IP legítimo

Mas um cache é contaminado:

Cache:
banco.com → IP malicioso

Durante o período em que essa informação falsa for utilizada, usuários podem ser direcionados ao destino errado.

22. DNS Hijacking

O DNS hijacking ocorre quando as consultas DNS são desviadas ou manipuladas.

Isso pode acontecer, por exemplo, por meio de:

  • comprometimento de configurações;
  • alteração de servidores DNS;
  • comprometimento de roteadores;
  • ataques a contas administrativas;
  • malware.

23. DNS Tunneling

Esse é um conceito particularmente interessante em Cibersegurança.

O DNS tunneling utiliza consultas e respostas DNS para transportar informações de forma indevida.

Conceitualmente:

Máquina comprometida
        ↓
     Consultas DNS
        ↓
Servidor controlado
        ↓
Comunicação escondida

Como o DNS é permitido em muitas redes, ele pode ser abusado para comunicação não autorizada.

Por isso, ferramentas de segurança podem analisar padrões incomuns de consultas DNS.

24. DNSSEC

O DNSSEC (DNS Security Extensions) adiciona mecanismos criptográficos ao DNS para ajudar a verificar a autenticidade e integridade das respostas DNS.

Sem entrar profundamente na implementação:

DNS tradicional

Pergunta
   ↓
Resposta

Com DNSSEC:

Pergunta
   ↓
Resposta + informações criptográficas
   ↓
Validação
   ↓
Resposta considerada autêntica

DNSSEC não significa que o conteúdo do site está criptografado.

Ele ajuda a garantir que a resposta DNS não tenha sido adulterada.

25. DNS e HTTPS são coisas diferentes

É muito importante não confundir:

DNS

Descobre:

www.exemplo.com
        ↓
       IP

HTTPS

Protege a comunicação com o servidor:

Navegador
    ⇅
  HTTPS/TLS
    ⇅
Servidor

Podemos visualizar:

          DNS
           ↓
    Descobrir o IP
           ↓
         HTTPS
           ↓
   Comunicar com segurança

27. DNS e infraestrutura de uma aplicação

Para quem está estudando Full Stack, DNS é extremamente importante.

Imagine que você tenha uma aplicação:

Ghostware

Você poderia ter:

ghostware.com

E diferentes serviços:

ghostware.com
www.ghostware.com
api.ghostware.com
app.ghostware.com
mail.ghostware.com

O DNS pode ajudar a direcionar cada nome para os serviços apropriados.

Por exemplo:

ghostware.com
      ↓
Servidor Web

api.ghostware.com
      ↓
Servidor da API

mail.ghostware.com
      ↓
Servidor de e-mail

Isso é muito comum em arquiteturas modernas.

28. DNS e hospedagem

Quando você compra um domínio e hospeda um site, normalmente precisa configurar registros DNS.

Um cenário comum:

Domínio
   ↓
DNS
   ↓
Servidor / CDN / serviço de hospedagem
   ↓
Aplicação

Por exemplo:

www.empresa.com
       ↓
Registro DNS
       ↓
Servidor da aplicação

É por isso que, quando um site é publicado pela primeira vez, pode ser necessário configurar DNS.

29. DNS não hospeda o site

Outro erro comum:

"O DNS é onde o site fica hospedado."

Não exatamente.

O DNS normalmente informa onde o serviço está.

DNS
 ↓
"Procure o servidor neste endereço."

Já o servidor de hospedagem contém:

HTML
CSS
JavaScript
PHP
Imagens
Banco de dados
APIs
etc.

Podemos pensar:

DOMÍNIO
   ↓
 DNS
   ↓
ENDEREÇO DO SERVIDOR
   ↓
SERVIDOR
   ↓
APLICAÇÃO

Relacionando com os protocolos que você já estudou:

                 APLICAÇÃO
                     │
                  DNS
                     │
              ┌──────┴──────┐
              │             │
             UDP           TCP
              │             │
              └──────┬──────┘
                     │
                    IP
                     │
               Wi-Fi/Ethernet

Uma consulta DNS tradicional pode ser:

Aplicação
   ↓
DNS
   ↓
UDP
   ↓
IP
   ↓
Rede

Enquanto uma aplicação web pode seguir:

Navegador
   ↓
DNS
   ↓
TCP
   ↓

   ↓

Em HTTP/3, por exemplo:

Navegador
   ↓

   ↓

   ↓

   ↓
IP

🧠 Para memorizar

A ideia central do DNS é:

NOME
 ↓
DNS
 ↓
ENDEREÇO IP
 ↓
SERVIDOR

E os conceitos mais importantes são:

DNS → resolução de nomes → registros → servidores DNS → cache → TTL → UDP/TCP → segurança.

Se você entender DNS + IP + TCP + UDP + HTTP/HTTPS, já terá uma base muito boa para compreender como uma aplicação web realmente se comunica pela Internet.
