Protocolo TCP

🌐 Protocolo TCP

O TCP (Transmission Control Protocol) é um dos principais protocolos utilizados nas redes de computadores. Ele trabalha junto com o IP para permitir a comunicação entre dispositivos de forma confiável, ordenada e orientada à conexão.

Enquanto o IP se preocupa principalmente com endereçamento e encaminhamento dos pacotes, o TCP adiciona mecanismos para garantir que os dados sejam entregues de maneira adequada.

Uma forma simples de visualizar:

Aplicação
    ↓
   TCP
    ↓
    IP
    ↓
Ethernet / Wi-Fi
    ↓
   Rede

1. O que significa TCP?

TCP significa:

Transmission Control Protocol — Protocolo de Controle de Transmissão

Ele pertence à camada de transporte.

No modelo OSI, está associado à:

Camada 4 — Transporte

No modelo TCP/IP:

┌──────────────────────────┐
│ Aplicação                │
│ HTTP, HTTPS, DNS, etc.   │
├──────────────────────────┤
│ Transporte               │
│ TCP / UDP                │ ← TCP
├──────────────────────────┤
│ Internet                 │
│ IP                       │
├──────────────────────────┤
│ Acesso à rede            │
│ Ethernet / Wi-Fi         │
└──────────────────────────┘

2. Para que serve o TCP?

O TCP foi projetado para fornecer uma comunicação confiável entre dois pontos.

Ele oferece mecanismos como:

  • estabelecimento de conexão;
  • entrega ordenada;
  • confirmação de recebimento;
  • retransmissão de dados perdidos;
  • controle de fluxo;
  • controle de congestionamento;
  • detecção de determinados erros;
  • encerramento organizado da conexão.

Podemos resumir:

TCP transforma a comunicação IP, que é "best effort", em uma comunicação de transporte mais confiável.

4. TCP é orientado à conexão

Antes de transmitir dados normalmente, o TCP estabelece uma conexão lógica entre os dois lados.

Imagine:

Cliente
   │
   │ "Podemos estabelecer uma conexão?"
   ▼
Servidor
   │
   │ "Sim."
   ▼
Cliente
   │
   │ "Confirmado."
   ▼
Conexão estabelecida

Esse processo é conhecido como:

Three-Way Handshake

ou handshake de três vias.

5. Three-Way Handshake

O estabelecimento de uma conexão TCP normalmente envolve três mensagens principais:

Cliente                         Servidor
   │                               │
   │ -------- SYN --------------> │
   │                               │
   │ <------ SYN + ACK ----------- │
   │                               │
   │ -------- ACK --------------> │
   │                               │
   │       CONEXÃO ESTABELECIDA    │

Vamos entender cada uma.

5.1 SYN

O cliente envia um segmento com a flag:

SYN

Indicando que deseja iniciar uma conexão.

Cliente → Servidor
SYN

5.2 SYN + ACK

O servidor responde:

SYN + ACK

Isso indica, de maneira simplificada:

"Recebi sua solicitação e também estou pronto para estabelecer a conexão."
Servidor → Cliente
SYN + ACK

5.3 ACK

Finalmente, o cliente responde:

ACK

Confirmando o recebimento.

Cliente → Servidor
ACK

Agora a conexão está estabelecida.

6. Por que três etapas?

O processo permite que os dois lados sincronizem informações necessárias para a comunicação, incluindo os números de sequência utilizados pelo TCP.

Simplificando:

1. Cliente → "Quero conectar."
2. Servidor → "Recebi e também quero conectar."
3. Cliente → "Recebi sua confirmação."

Depois disso:

Cliente ←──────────→ Servidor
       conexão TCP

Imagine que você queira enviar:

"Olá, tudo bem?"

8. Números de sequência

Um dos mecanismos fundamentais do TCP são os números de sequência.

Eles permitem que o receptor saiba como os dados se relacionam e mantenha a ordem correta do fluxo.

Imagine que os dados sejam divididos:

A → B → C → D

Os segmentos podem chegar fora de ordem:

B
D
A
C

O TCP utiliza informações de sequência para reorganizar o fluxo.

A → B → C → D

Assim, a aplicação recebe os dados na ordem esperada.

9. ACK — confirmação de recebimento

TCP utiliza ACK (Acknowledgment) para confirmar o recebimento de dados.

Simplificando:

Cliente
   │
   │ Dados
   ▼
Servidor
   │
   │ ACK
   ▼
Cliente

O ACK informa ao remetente que determinados dados foram recebidos.

10. Retransmissão

Imagine que um segmento seja perdido:

Cliente                     Servidor

Segmento 1 ────────────────→ ✓
Segmento 2 ────────X         perdido
Segmento 3 ────────────────→ ✓

O TCP possui mecanismos para detectar que algo não foi recebido corretamente e pode retransmitir os dados.

Conceitualmente:

Segmento perdido
      ↓
Detecção
      ↓
Retransmissão
      ↓
Recebimento

É uma das características que tornam o TCP confiável.

11. TCP não garante que a rede nunca perderá pacotes

Essa distinção é importante.

O TCP não impede fisicamente a perda de pacotes.

A rede ainda pode apresentar:

  • congestionamento;
  • falhas;
  • perda;
  • atrasos;
  • problemas de roteamento.

O que o TCP faz é implementar mecanismos para detectar determinadas situações e reagir a elas, como retransmitindo dados.

12. Controle de fluxo

Imagine que o remetente seja muito rápido:

Remetente
████████████████████
        ↓
    Receptor
       ██

O receptor pode não conseguir processar tudo nessa velocidade.

O TCP possui mecanismos de controle de fluxo para evitar que o remetente envie mais dados do que o receptor consegue lidar naquele momento.

Um conceito fundamental aqui é a:

janela de recepção (receive window)

Simplificando:

Receptor:
"Consigo receber até determinada quantidade de dados agora."

O remetente ajusta seu envio de acordo com essas informações.

13. Controle de congestionamento

Controle de fluxo não é a mesma coisa que controle de congestionamento.

Controle de fluxo

Protege o receptor.

"Não envie mais do que consigo receber."

Controle de congestionamento

Considera a rede.

"Não envie dados em uma velocidade que contribua para congestionar o caminho."

Portanto:

TCP
├── Controle de fluxo
│   └── protege o receptor
│
└── Controle de congestionamento
    └── considera a rede

14. Portas TCP

É aí que entram as portas.

Imagine:

443

Podemos pensar:

IP → qual dispositivo?
Porta → qual serviço/aplicação?

Por isso uma comunicação TCP é normalmente identificada por:

IP de origem
IP de destino
Porta de origem
Porta de destino

17. Socket

No desenvolvimento de redes, você também encontrará o conceito de socket.

Simplificando:

IP + Porta

identifica um endpoint de comunicação.

Por exemplo:

192.168.1.10:5000

significa:

IP   → 192.168.1.10
Porta → 5000

Uma conexão TCP pode ser entendida considerando os endpoints de origem e destino.

18. Flags TCP

O cabeçalho TCP possui várias flags importantes.

As principais que você deve conhecer são:

  • SYN;
  • ACK;
  • FIN;
  • RST;
  • PSH;
  • URG.

As mais importantes para começar são:

SYN

Utilizada para estabelecer uma conexão.

ACK

Indica confirmação.

FIN

Utilizada no encerramento normal da conexão.

RST

Indica uma reinicialização/aborto da conexão.

19. Encerramento da conexão

O TCP também possui um processo para encerrar uma conexão.

Conceitualmente:

Cliente                         Servidor
   │                               │
   │ -------- FIN --------------> │
   │                               │
   │ <-------- ACK -------------- │
   │                               │
   │ <-------- FIN -------------- │
   │                               │
   │ -------- ACK --------------> │
   │                               │
   │       CONEXÃO ENCERRADA       │

É comum falar em four-way termination, porque o encerramento normal pode envolver quatro segmentos.

20. FIN × RST

Essa diferença é importante.

FIN

Representa um encerramento normal.

"Terminei de enviar."

RST

Indica uma interrupção/reset da conexão.

"Essa conexão precisa ser interrompida."

Um RST pode aparecer, por exemplo, quando uma conexão não pode ser estabelecida ou quando ocorre uma situação que exige seu encerramento imediato.

23. Quando usar TCP?

O TCP é adequado quando a confiabilidade dos dados é importante.

Exemplos:

🌐 Web

HTTP/HTTPS
   ↓
TCP

Embora HTTP/3 utilize QUIC sobre UDP, HTTP/1.1 e HTTP/2 tradicionalmente utilizam TCP.

🔐 SSH

SSH
 ↓
TCP

📧 E-mail

Protocolos como SMTP, IMAP e POP3 tradicionalmente utilizam TCP.

🗄️ Banco de dados

Muitos sistemas de banco de dados utilizam TCP para comunicação cliente-servidor.

24. Quando UDP pode ser mais adequado?

Existem situações nas quais esperar retransmissões pode ser menos desejável do que simplesmente continuar recebendo dados.

Exemplos:

  • jogos online;
  • comunicação em tempo real;
  • VoIP;
  • streaming;
  • DNS;
  • protocolos modernos como QUIC.

Por exemplo, em uma chamada de voz:

Pacote atrasado
      ↓
Chega depois
      ↓
Pode ser menos útil

Às vezes é melhor continuar transmitindo os dados mais recentes.

28. SYN Scan

Em segurança de redes, você também pode encontrar o conceito de SYN scan.

Ele utiliza o comportamento do handshake TCP para ajudar a identificar o estado de uma porta.

Conceitualmente:

Scanner
   │
   │ SYN
   ▼
Servidor
   │
   ├── SYN/ACK → porta possivelmente disponível
   │
   └── RST/sem resposta → análise adicional

O Nmap possui técnicas baseadas nesse conceito.

Em ambientes de estudo, isso é útil para entender como ferramentas de segurança conseguem descobrir serviços.

Sempre realize testes de rede somente em sistemas para os quais você possui autorização.

29. SYN Flood

O funcionamento do handshake também ajuda a entender um tipo de ataque de negação de serviço chamado SYN Flood.

Conceitualmente:

Atacante
  │
  ├── SYN ──→
  ├── SYN ──→
  ├── SYN ──→
  ├── SYN ──→
  └── SYN ──→
          Servidor

O servidor pode precisar manter recursos associados às conexões que ainda não foram concluídas.

Uma grande quantidade de solicitações pode contribuir para o esgotamento desses recursos.

Defesas podem envolver:

  • SYN cookies;
  • firewalls;
  • rate limiting;
  • balanceamento;
  • proteção anti-DDoS;
  • monitoramento.

30. TCP e firewall

Firewalls podem analisar informações do TCP.

Por exemplo:

IP origem
IP destino
Porta origem
Porta destino
Protocolo

Isso permite criar regras como:

Internet → Servidor Web → TCP/443 → PERMITIR
Internet → Banco de Dados → TCP/3306 → BLOQUEAR

Assim, o firewall ajuda a limitar a superfície de ataque.

32. Checksum

O TCP utiliza um checksum para ajudar a detectar corrupção dos dados durante o transporte.

Conceitualmente:

Dados
 ↓
Checksum
 ↓
Transmissão
 ↓
Recepção
 ↓
Verificação

Se houver inconsistência, o segmento pode ser considerado inválido.

Isso está relacionado à detecção de erros, não à criptografia.

33. TCP não é criptografia

Outro ponto importante:

TCP não criptografa os dados.

Por exemplo:

HTTP
 ↓
TCP
 ↓
IP

O TCP fornece mecanismos de transporte, mas não torna automaticamente os dados secretos.

Para comunicação web segura:

HTTPS
 ↓
TLS
 ↓
TCP
 ↓
IP

O TLS é responsável pela proteção criptográfica.

34. TCP não é responsável pelo conteúdo da aplicação

O TCP não sabe necessariamente se os dados são:

HTML
JSON
imagem
arquivo
mensagem

Para ele, existe essencialmente um fluxo de bytes que precisa ser transportado.

Quem interpreta o conteúdo é a camada de aplicação.

HTTP → interpreta HTTP
TCP  → transporta o fluxo
IP   → encaminha pacotes

O TCP é o protocolo de transporte responsável por fornecer uma comunicação confiável e ordenada entre aplicações através de uma rede IP.

E as responsabilidades:

E o TCP possui mecanismos fundamentais como:

Three-Way Handshake → Sequenciamento → ACK → Retransmissão → Controle de fluxo → Controle de congestionamento → Encerramento da conexão.

Para Cibersegurança, entender TCP é especialmente importante porque ele está diretamente relacionado a portas, firewalls, Nmap, Wireshark, IDS/IPS, análise de tráfego, SYN Flood e monitoramento de redes.
