Protocolo UDP

O UDP (User Datagram Protocol) é um protocolo da camada de transporte (Camada 4) do modelo TCP/IP. Ele é usado para transportar dados entre aplicações através de uma rede, assim como o TCP.

A principal diferença é que o UDP prioriza velocidade e baixa sobrecarga, enquanto o TCP prioriza confiabilidade e controle da comunicação.

1. O que é UDP?

UDP = User Datagram Protocol, ou Protocolo de Datagrama do Usuário.

Ele permite que uma aplicação envie dados para outra aplicação sem estabelecer previamente uma conexão formal.

Por exemplo:

Aplicação A
     ↓
    UDP
     ↓
    IP
     ↓
   Rede
     ↓
    IP
     ↓
    UDP
     ↓
Aplicação B

O UDP recebe os dados da aplicação, coloca informações de controle em um cabeçalho e entrega o datagrama para o IP transmitir.

2. UDP é um protocolo de transporte

Assim como o TCP, o UDP fica acima do IP:

┌─────────────────────────────┐
│       Aplicação             │
│ HTTP, DNS, jogos, VoIP...   │
├─────────────────────────────┤
│       UDP / TCP             │ ← Camada de Transporte
├─────────────────────────────┤
│            IP               │ ← Camada de Rede
├─────────────────────────────┤
│       Ethernet/Wi-Fi        │
└─────────────────────────────┘

O IP é responsável principalmente por endereçar e encaminhar os pacotes.

O UDP ajuda a identificar qual aplicação deve receber os dados usando portas.

3. Como o UDP funciona?

Diferentemente do TCP, o UDP não precisa estabelecer uma conexão.

Imagine um computador enviando uma mensagem:

Computador A
192.168.1.10
     │
     │ UDP
     ↓
Computador B
192.168.1.20

O computador A simplesmente cria um datagrama UDP e o envia.

Não existe o famoso:

SYN
SYN/ACK
ACK

do TCP.

Portanto, o UDP é considerado connectionless, ou seja, sem conexão.

4. Datagrama UDP

No UDP, os dados são transportados em unidades chamadas datagramas.

Um datagrama possui:

┌──────────────────────────┐
│ Cabeçalho UDP            │
├──────────────────────────┤
│ Dados da aplicação       │
└──────────────────────────┘

O cabeçalho UDP é extremamente simples.

Ele possui apenas 8 bytes.

5. Cabeçalho UDP

O cabeçalho possui quatro campos principais:

┌───────────────────────┬───────────────────────┐
│ Porta de origem       │ Porta de destino      │
├───────────────────────┼───────────────────────┤
│ Comprimento           │ Checksum              │
├───────────────────────┴───────────────────────┤
│ Dados                                           │
└────────────────────────────────────────────────┘

Porta de origem

Identifica a aplicação que está enviando os dados.

Porta de destino

Indica para qual aplicação os dados devem ser entregues.

Comprimento

Indica o tamanho do datagrama UDP.

Checksum

É utilizado para ajudar a detectar corrupção dos dados durante a transmissão.

6. Portas UDP

Assim como no TCP, o UDP utiliza portas.

Por exemplo:

IP: 192.168.1.20
Porta: 53

A porta 53 é tradicionalmente utilizada pelo DNS.

Outro exemplo:

IP: 192.168.1.20
Porta: 5000

Uma aplicação própria poderia estar utilizando essa porta.

Podemos pensar assim:

IP → identifica o computador/interface
Porta → identifica a aplicação/serviço

Por isso, uma comunicação pode ser representada por:

192.168.1.10:50000
        ↓
192.168.1.20:53

7. UDP não garante entrega

Essa é uma das características mais importantes do UDP.

O UDP não garante que o datagrama chegará ao destino.

Por exemplo:

Computador A
     │
     │ Datagrama 1
     ↓
    Rede
     X  ← perdido
     │
Computador B

O UDP não possui, por si só, um mecanismo equivalente ao TCP para retransmitir automaticamente o dado perdido.

8. UDP não garante ordem

Imagine que uma aplicação envie:

A → B
B → B
C → B
D → B

Os dados podem chegar em uma ordem diferente:

A
C
B
D

O UDP não possui um mecanismo interno para reorganizar os datagramas como o TCP faz.

Se a aplicação precisar de ordenação, ela própria pode implementar mecanismos para isso.

9. UDP não possui controle de conexão

No TCP temos:

Cliente                  Servidor

   SYN ────────────────────→
       ←──────────────── SYN/ACK
   ACK ────────────────────→

       CONEXÃO ESTABELECIDA

No UDP não existe esse processo.

A aplicação pode simplesmente enviar:

Cliente                  Servidor

   UDP ────────────────────→
   UDP ────────────────────→
   UDP ────────────────────→

Isso reduz a quantidade de comunicação necessária antes da transmissão.

10. UDP é mais rápido?

É comum dizer que "UDP é mais rápido que TCP", mas é melhor entender o motivo.

O UDP possui menos mecanismos de controle.

Ele não precisa lidar, por padrão, com:

  • estabelecimento de conexão;
  • confirmação de recebimento;
  • retransmissão;
  • ordenação;
  • controle de fluxo da mesma maneira que TCP;
  • controle de congestionamento da mesma maneira que TCP.

Consequentemente, existe menos sobrecarga.

TCP
Dados
 ↓
Controle de conexão
Controle de sequência
ACK
Retransmissão
Controle de fluxo
Controle de congestionamento
 ↓
Transmissão

UDP
Dados
 ↓
Datagrama
 ↓
Transmissão

Isso pode proporcionar menor latência e menor overhead, dependendo da aplicação e da rede.

11. UDP não significa "sem confiabilidade"

Aqui existe uma diferença importante.

O UDP não fornece confiabilidade na camada de transporte, mas uma aplicação pode implementar seus próprios mecanismos.

Por exemplo:

Aplicação
 ├── UDP
 ├── número de sequência
 ├── confirmação
 ├── retransmissão
 └── controle próprio

Ou seja, uma aplicação pode usar UDP e construir mecanismos adicionais sobre ele.

12. Onde o UDP é utilizado?

O UDP é muito utilizado quando velocidade, baixa latência ou simplicidade são importantes.

Alguns exemplos:

DNS

O DNS frequentemente utiliza UDP para consultas.

Cliente
   │
   │ UDP
   ↓
Servidor DNS

Tradicionalmente, consultas DNS comuns utilizam a porta:

UDP 53

Mas DNS também pode utilizar TCP e, atualmente, existem outras formas de transporte, como DNS sobre HTTPS e DNS sobre TLS.

Jogos online

Jogos multiplayer podem utilizar UDP porque perder ocasionalmente uma atualização pode ser menos problemático do que esperar por uma retransmissão.

Imagine um jogo enviando a posição de um jogador:

Posição 1
Posição 2
Posição 3
Posição 4
Posição 5

Se a posição 3 for perdida, talvez seja melhor simplesmente receber a posição 4.

Em um jogo em tempo real:

Posição 1 → chegou
Posição 2 → chegou
Posição 3 → perdida
Posição 4 → chegou
Posição 5 → chegou

A posição atual pode tornar a informação perdida irrelevante.

VoIP

Em chamadas de voz pela internet, a latência é extremamente importante.

Imagine perder alguns milissegundos de áudio.

É possível que seja melhor continuar a conversa do que esperar uma retransmissão.

Áudio
 ↓
UDP
 ↓
Rede
 ↓
UDP
 ↓
Áudio

Isso também pode ser usado em aplicações de vídeo em tempo real.

Streaming e comunicação em tempo real

Aplicações que precisam transmitir informações continuamente podem utilizar UDP ou protocolos construídos sobre UDP.

Um exemplo moderno importante é o QUIC, utilizado pelo HTTP/3.

HTTP/3
   ↓
 QUIC
   ↓
 UDP
   ↓
 IP

O QUIC implementa vários mecanismos modernos que ficam acima do UDP.

14. Exemplo prático

Imagine que você está baixando um arquivo de 100 MB.

Você precisa que todos os dados cheguem corretamente.

Nesse caso, TCP é muito apropriado:

Pacote 1 ✓
Pacote 2 ✓
Pacote 3 ✗
Pacote 4 ✓

TCP:
"Pacote 3 não chegou.
Preciso retransmiti-lo."

Agora imagine um jogo online:

Jogador está em:

X = 100
Y = 200

Depois:

X = 102
Y = 201

Se uma atualização intermediária for perdida, talvez não seja necessário retransmiti-la.

A próxima atualização já pode informar a posição atual.

Por isso, UDP pode ser adequado:

Atualização 1 ✓
Atualização 2 ✓
Atualização 3 ✗
Atualização 4 ✓
Atualização 5 ✓

15. UDP e segurança

O UDP também é importante em Cibersegurança.

Ferramentas de análise de rede podem identificar serviços UDP disponíveis em uma máquina.

Por exemplo:

IP
 ↓
Portas
 ↓
Serviços UDP
 ↓
Análise de segurança

Ferramentas como Nmap e Wireshark podem ser utilizadas em ambientes autorizados para analisar esse tipo de tráfego.

Um administrador pode, por exemplo, descobrir que determinado servidor possui um serviço UDP que não deveria estar exposto.

16. UDP e ataques

O UDP também aparece em alguns tipos de ataques de rede.

Um exemplo é o UDP flood, no qual uma grande quantidade de tráfego UDP pode ser enviada contra um alvo, consumindo recursos ou largura de banda.

Conceitualmente:

Atacantes
   │
   ├──── UDP ────┐
   ├──── UDP ────┤
   ├──── UDP ────┤
   └──── UDP ────┘
                  ↓
              Servidor
                  ↓
          Recursos consumidos

Por isso, firewalls, filtros de tráfego, rate limiting, monitoramento e proteção contra DDoS são importantes.

17. UDP não é criptografado

Outro ponto muito importante:

UDP não fornece criptografia.

Assim como TCP, ele é apenas um protocolo de transporte.

Por exemplo:

Aplicação
   ↓
Criptografia (quando aplicável)
   ↓
UDP
   ↓
IP

Um protocolo construído sobre UDP pode fornecer segurança.

Um exemplo importante é:

HTTP/3
   ↓
QUIC
   ↓
UDP

O QUIC utiliza TLS para fornecer proteção criptográfica.

18. TCP/IP e UDP

Podemos visualizar a relação entre os principais protocolos assim:

                 APLICAÇÕES
                     │
        ┌────────────┴────────────┐
        │                         │
       TCP                       UDP
        │                         │
        └────────────┬────────────┘
                     │
                    IP
                     │
             Ethernet / Wi-Fi

Exemplos:

HTTP ── TCP ── IP
HTTPS ─ TCP ── IP
SSH ─── TCP ── IP

DNS ─── UDP ── IP
QUIC ── UDP ── IP

É importante lembrar que isso é uma simplificação: alguns protocolos e aplicações podem utilizar TCP, UDP ou outros transportes dependendo do caso.

19. TCP x UDP: uma analogia

Imagine duas formas de enviar informações.

TCP — entrega controlada

Você envia:

"Preciso que você receba exatamente todos esses documentos."

O sistema verifica:

Documento 1 ✓
Documento 2 ✓
Documento 3 ✗
→ Reenviar documento 3
Documento 4 ✓

UDP — envio rápido

Você envia:

"Aqui estão as informações mais recentes."

Não existe, no próprio UDP, a mesma preocupação em confirmar cada informação.

Isso é útil quando a informação mais recente é mais importante do que garantir cada pacote individual.

20. Resumindo

O UDP é um protocolo da camada de transporte que foi projetado para ser simples, rápido e com baixa sobrecarga.

Suas principais características são:

  • não orientado à conexão;
  • utiliza portas;
  • transmite datagramas;
  • possui cabeçalho de apenas 8 bytes;
  • não garante entrega;
  • não garante ordenação;
  • não faz retransmissão por padrão;
  • não fornece criptografia;
  • possui menor overhead que o TCP;
  • é muito utilizado em aplicações de tempo real;
  • aparece em DNS, jogos, VoIP, streaming e protocolos modernos como QUIC.

TCP prioriza a entrega confiável dos dados; UDP prioriza uma transmissão simples e rápida, deixando mecanismos adicionais de confiabilidade para a aplicação quando necessário.
